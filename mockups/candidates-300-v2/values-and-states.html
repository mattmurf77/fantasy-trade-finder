Value as pick tiers — and the states nobody drew

“Value must be presented in PICK TIERS, not raw numbers. […] Open problem: that labels a team’s value, not a difference from median. Show what ‘1.2k below median’ looks like as a pick tier, and say plainly what happens when a delta falls below the ladder’s floor.”

Short answer: the app already has a delta→pick converter, its floor is already defined in code, and you should still not use it here. Label each team’s level (which is already on the wire and already shipped on this screen) and let the divider carry the median’s level. Deltas get their magnitude from the sorted order and the existing bar chart — encodings that do not need a name and therefore cannot invent one.
1. What the codebase already has read before designing, not after

The floor is not a design question; it is already answered in code

_pick_gap_equivalent returns pick_equivalent: None when gap < min_val * 0.5 or gap > max_val * 1.25. Evaluated against GENERIC_PICK_SEEDS (pick_values.py:24-38) and elo_to_value (trade_service.py:712-727, base 1000 / k 0.0050 / ref 1500):

So: “what happens when a delta falls below the ladder’s floor” has a concrete answer — the server returns null and the honest render is “about even at WR”, never a fabricated tier. And that non-answer is itself useful information: “about even” is exactly “this team is not a candidate at this position.”
2. Why delta-as-pick-tier still fails the ladder audit, run on the mock league

The rungs are sparse and top-heavy. Between Late 1st (0.705 firsts) and Early 1st (1.419) there is nothing at all — a 0.71-firsts hole, two-thirds of a first round wide. Every delta that lands in it gets named after whichever edge is closer.

What that column reads like down the screen: —, Early 1st, Early 1st, Late 1st, Early 3rd, Early 3rd, │ Early 3rd, Early 3rd, Late 1st, Late 1st, Early 1st, Early 1st. Four different deltas collapse onto “an Early 1st”, the largest gap in the league has no name at all, and the labels mirror around the line so the top of the list and the bottom read identically. A column that says the same thing about the richest team and the poorest team is worse than no column.

And the floor is worse than “below 0.058 firsts there is no name”. Just above it the nearest-rung approximation is wild: a delta of 0.07 firsts is named “a Late 4th” — off by 66%. So the honest floor for display is not the code’s null boundary; it is wherever the naming error stops being defensible, and nothing in the codebase defines that. That is a second invented number, right after the one the three-section variant needed on page 1.

The build finding buried in this

The median’s label cannot be computed on the client. Every team’s raw positions[P].value is already on the wire (api/league.ts:560-566), so the client can compute the median value exactly — but converting it to “≈2 firsts” needs elo_to_value and GENERIC_PICK_SEEDS, which live on the server, and numeric values are no longer an allowed fallback. So Direction 2’s divider label requires a new response field — minimally medians: { QB|RB|WR|TE: { value, value_label } } on /api/league/power-rankings, computed with the same _aggregate_pick_label and gated by the same aggregate_tier_labels experiment as the labels beside it.

That makes this an API-contract change, which the project’s bright line says is not a “quick fix” (root CLAUDE.md → Feature gates). Whichever direction wins: docs/api-reference.md must be updated, and the feature-scope block’s Docs table filled row by row. Direction 1 needs the same field for its “6 sellers · 5 buyers” counts, so this is not a cost that picking Direction 1 avoids.

Degradation is already specified by precedent: value_label is absent for anyone outside the experiment and on old servers, and TeamRow falls back to the numeric (LeagueSummaryScreen.tsx:1889-1891). The divider must degrade the same way — label absent → draw the line with the bare text “League median” and no value. The line is still true; only the number is missing.

What the auto-return needs, that is easy to forget

  • Announce it. Setting selectedId = null silently moves VoiceOver focus with no explanation. The transient strip should carry an AccessibilityInfo.announceForAccessibility equivalent: “Showing TE. Back to all 12 teams.”
  • It is not the same as “back”. #302 V2’s ‹ All teams is a deliberate exit; this is an automatic one. They should land on the same screen but should not be logged as the same event — via: 'filter_change' vs via: 'back', so the analytics can tell an ejection from a choice.
  • Android back. The #299/#302 lab already flagged that there are zero BackHandler registrations in LeagueSummaryScreen.tsx and the drill-in is component state, not a stack push. Auto-return does not fix that; it adds a second way to leave the drill-in while the hardware button still has none.
  • Restore scroll to the line. Returning to the top of a 570pt list hides the answer. The return should scroll so the median divider is near the top of the viewport — the position from which both sides are readable.
  • Multi-select. Adding a second position (WR + TE) is also a filter change, but see the next section: it has no median at all, so it must return to the top and drop the line.
