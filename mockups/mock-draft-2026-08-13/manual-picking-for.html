Manual mode — the “Picking for” clock variant (#305)

Both frames are reconstructions — manual mode does not exist yet, and (house note) the shipped mock has never shown any user-turn state on a live league. The surface is the shipped MockDraftScreen verbatim; the delta is one clock-card variant (LLD §3.4) plus the confirm-bar meta.

The distinction rule, drawn: “your team” vs “picking on behalf of {other team}” must be unmistakable with no new chrome. The shipped card already encodes the user's turn as flare headline text (“You're on the clock”) — the variant keeps that channel: flare headline = your team; chalk headline naming the other team = on their behalf, plus a persistent sub-line (mock-draft.clock.picking-for) and the confirm bar naming whose pick is being committed. Color is never the only encoding — the words differ in both places.

League context: live ffv3 (12 teams, linear, user = mattmurf77 at slot 8). Leaguemate handles are illustrative. All quoted copy is the LLD placeholder — PRD owns final wording.

Rationale & findings

  • Why the existing flare channel, not a new badge: the clock card's flare border + flare headline is the shipped "this concerns YOU" encoding. Reusing it (flare = yours, chalk + name = theirs) keeps one visual system; a new badge or color would need a new rule and violate the no-new-chrome constraint. The redundant text (“You're on the clock” vs “You're picking for {name}”, and “your pick” vs “{name}'s pick”) satisfies the color-is-never-the-only-encoding floor.
  • The picking-for sub-line renders only when is_user && roster_id !== user_owner_id (LLD §1.6) — so it appears on every on-behalf turn and never on the user's own turn, in either mode. It sits at 11px faint above the instruction line, mirroring the CPU-mode persona line's position so the card's height rhythm matches across modes.
  • Finding (report, not improvised around): the ticker's who-column goes blank in manual mode. Shipped code renders mine ? 'You' : p.by === 'cpu' ? 'CPU' : '—'. In manual mode every non-own pick is by: "user" but not mine, so the whole ticker column reads “—” (drawn faithfully in both frames). Legal but uninformative — the natural fix is joining the owner name via the existing order[] name ladder, but PickTicker is not in the LLD §3.4 change list, so this lab draws shipped behavior and flags the gap for the PRD/build rather than inventing the join.
  • My-picks chips still work unchanged: the flare-bordered “Your picks” chips (drawn on the CPU page) key off userOwnerId, which manual mode resolves from the new settings_echo.user_owner_id (LLD §11.1) — the shipped inference would misidentify the team on every on-behalf turn, which is exactly why the echo field exists.
