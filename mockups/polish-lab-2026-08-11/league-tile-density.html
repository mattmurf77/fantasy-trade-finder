League roster tile density — #299

"I want to reduce the height of the player tiles on the league summary. Move the tier value to the right, presenting it to the left of the position. This should cut the tiles to about half of their current height." — feedback #299, screen LeagueRankings, polish, 2026-08-10, v1.12.0

Does it reproduce? Yes — and the spec is achievable with no information loss

The tiles are PlayerCard in its dense branch (mobile/src/components/PlayerCard.tsx), mounted by the League-rankings drill-in roster panel at mobile/src/screens/LeagueSummaryScreen.tsx:1210-1229. The height is a hard constant — cardDense: { height: 60 } (PlayerCard.tsx, dense styles) — plus rosterRow: { marginBottom: space.xs } = 4pt (LeagueSummaryScreen.tsx:2228). Pitch today = 64pt per player.

The 60pt buys two lines. But look at what this caller passes (LeagueSummaryScreen.tsx:1212-1227): dense, player, tier, posRank — and no statsSlot. In PlayerCard's dense branch, line 2 is {tier && <TierChalkBadge/>}{statsSlot}. With no statsSlot, line 2 of every tile on this screen holds exactly one small badge and nothing else — roughly 23pt of the 60 spent on a single chip that has a whole row to itself. That is the density the operator is reacting to, and it is specific to this screen: the Tiers board, the other dense caller, does pass a statsSlot and genuinely needs line 2.

So the operator's instruction is exactly right, and it is free. Moving the tier badge into the existing right cluster — left of posRank, which is the "position" the report refers to (densePosRank, the position-colored mono "WR4") — empties line 2 entirely, and the tile collapses to one line. Nothing is dropped. Name, team, RK and injury micro-tags, tier and positional rank all survive.

The tile is not a tap target here — which is what makes 32pt safe

LeagueSummaryScreen passes no onPress to these cards (:1212-1227), so PlayerCard leaves accessibilityRole undefined and the row is inert. The 44pt minimum touch target does not bind. On the Tiers board — where rows are pressable and draggable — it would, so this change must stay scoped to the League drill-in caller, not applied to the shared dense branch wholesale. The cleanest shape is a new opt-in prop on PlayerCard (e.g. denseSingleLine) that the League screen sets and the Tiers board does not.

Width stress test the real risk in V1 — not height, width

Collapsing to one line moves the tier badge from a row of its own into competition with the name. Content width is 358pt (390 − scroll: { padding: space.lg } = 16 each side, LeagueSummaryScreen.tsx:1956). Budget for V1:

ElementWidth
Rail + left inset (paddingLeft: 13)16pt
Team code ("ARI") + gap28pt
RK tag + gap (when present)28pt
Injury tag + gap (when present)26pt
Tier badge — worst case "4+ 1sts"60pt
posRank "WR61" + gaps + right margin52pt
Remaining for the name — clean row202pt (~26 chars)
Remaining — name + RK + injury both148pt (~19 chars)

Longest names in a dynasty pool run ~19–21 characters ("Marvin Harrison Jr.", "Christian McCaffrey", "Amon-Ra St. Brown"). The clean row is comfortable. The worst case — a long-named rookie carrying an injury tag and a top-tier badge — ellipsizes. denseName already sets flexShrink: 1, so it truncates gracefully rather than pushing the badges off, but it does truncate. Scoped via a new opt-in prop so the Tiers board — where rows are pressable and need the 44pt target and the statsSlot — is unaffected. Doubles roster visible above the fold.

Only worth it if truncation proves annoying in the sim.

Build notes

  • Scope the prop. Add denseSingleLine (or equivalent) to PlayerCard; branch cardDense height 60 → 32 and render tier in denseNums before posRank. Only LeagueSummaryScreen.tsx:1212 passes it.
  • Do not change the Tiers board. It passes statsSlot, its rows are pressable and drag-liftable, and 44pt applies there.
  • Draft-capital rows are a separate style. styles.pickRow (LeagueSummaryScreen.tsx:2232) renders the "Draft capital" group and is not a PlayerCard — it will not shrink with this change and will look tall beside the new tiles. Worth matching in the same pass; not drawn here because #299 names player tiles only.
  • No API or flag surface. Pure presentation; r.tier and playerPosRank are already on the payload. No docs/api-reference.md row moves.
  • Capture first. Request the drill-in state before build so the before/after can be verified against a real frame (see the coverage-gap note above).
