Back to all teams — League drill-in exit (#302)

"The nav to get back to all teams view after drilling down on one specific team is too hard to navigate to." — feedback #302, screen LeagueRankings, polish, 2026-08-10, v1.12.0

There IS a back control. Four reasons it doesn't work.

The affordance exists and is correctly labelled: mobile/src/screens/LeagueSummaryScreen.tsx:902-914 renders a Pressable with testID="league-summary.roster-close", accessibilityLabel="Back to all teams", a chevron-left icon in ice.base, and the text "All teams". It shipped with #243 (it replaced an X). So this is not a missing-control problem — it is a findability problem, and the four causes are separable:

  1. It scrolls away — the dominant cause. The control lives inside the chart card's header (styles.cardHead, :866), which sits at the very top of the ScrollView. The roster panel it introduces (:1133-1280) is 1,600pt+ of player tiles for a 26-man roster (60pt tile + 4pt margin, see the #299 page in this lab). The moment the user does the thing they drilled in to do — scroll the roster — the only exit leaves the screen. There is nothing sticky, nothing pinned.
  2. It's on the wrong side. The control is right-aligned, in the slot where the unfocused state puts the refresh button (:916-926). iOS puts back at top-left, and this app already agrees with iOS everywhere else — subScreenOptions mounts HeaderBack as headerLeft (mobile/src/navigation/TabNav.tsx:131-135). This screen is the exception.
  3. It has the visual weight of a caption. backLinkText is type.label — 11px uppercase Archivo SemiBold, 0.88 letterspacing — the same style the app uses for passive section labels. It sits beside a 16px team-name title that dominates it. It is ice-colored, which is the only thing marking it as interactive.
  4. No system back works, because this isn't navigation. The drill-in is component state — const [selectedId, setSelectedId] = useState<string | null>(null) (:386). So: the stack header has no back button (LeagueRankings is the stack root, and TabNav.tsx:440-446 comments this deliberately — "never a back button to nowhere"); iOS edge-swipe does nothing; and grep confirms no BackHandler is registered anywhere in the file. Every instinct a user has for "go back" fails silently.
A fifth, aggravating factor. #243 hid the "League home" row while focused (:805, isTabRoot && !selected) — sensible on its own terms, but it removes the other visible landmark, so the focused state reads as a screen with no exits at all.
Note for the orchestrator: the pre-briefed lead pointed at subScreenOptions('League home', 'LeagueRankings') at TabNav.tsx:460. That is a different navigation — it is the back control on the pushed LeagueHome screen (the classic league page reached from the "League home" row), and it works fine. It has nothing to do with the team drill-in, which never leaves LeagueRankings. #302 is entirely in-screen.

Recommendation
VariantCostTradeoff
V2 — nav-header back + title swap0pt Recommended. Fixes all four causes at once: permanent (the header is fixed), top-left (matches iOS and this app's own subScreenOptions pattern), full-size header control rather than an 11px caption, and the title swap answers "which team?" at any scroll depth. Implemented with navigation.setOptions in an effect on selectedId; delete the in-card link at :902-914 once it lands.
V1 — sticky in-content bar38pt Also always-visible and also carries the team name, and stays inside the screen's own layout (no navigator coupling). But it spends 38pt of every focused screen, and needs stickyHeaderIndices on a ScrollView whose children are conditional — fiddly. Take this if the operator objects to the header title changing on a tab root.
V3 — floating pill0pt layout Cheapest to build and the most thumb-reachable, but it occludes content, doubles the floating chrome next to FeedbackFAB, and leaves the header still reading "League rankings" while you look at one team's roster.
V4 — make the drill-in a real push— Considered and rejected. Pushing a route would give header back, edge-swipe and Android back for free. But the inline drill-in is deliberate: the 2026-07-26 League Analyzer treatment keeps the grayscale chart visible above the roster (:1129-1132), and #237 binds the panel's filters to the chart's shared state (:386-388). A push breaks both. Not worth it for #302.

Build notes

  • Keep the testID. league-summary.roster-close is referenced by Maestro flows; whichever control survives should carry it, exactly as #243 did when it turned the X into the link.
  • Android hardware back. Whatever ships, register a BackHandler while selectedId is set so the OS back gesture clears focus instead of leaving the tab. There is none today.
  • Tab re-tap. registerScrollToTop('League', …) (:370-377) scrolls to top but leaves the team focused — worth also clearing selectedId so re-tapping the active tab returns to the all-teams view, which is what the gesture implies.
  • Ships well with #299. Halving the tiles shortens the roster the user has to scroll back through, which reduces how often the exit is off-screen at all. The two items attack the same complaint from opposite ends; neither replaces the other.
  • No API or flag surface. Pure navigation/presentation.
