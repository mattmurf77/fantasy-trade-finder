Polish Lab · Trios Three-Up V2 — two-line names, no truncation (#243 follow-up)

Source: trios-three-up.html (this same folder), reviewed by the operator. V3 — three mini-cards side by side, tap animates a "winner" state, no layout shift — was picked as the base to keep iterating. The one open complaint:

"I like V3 best, but don't like the truncation. We should explore some other versions that allow for two lines. I don't want a last name or even a name suffix spilling over into the next line where the word is split into the two lines — so if the word doesn't fit on the line, the whole word should move down."

This file replaces V3's single-line ellipsis truncation ("Marvin Harris…") with two-line name blocks under three hard rules, explored as three variants below:

  • Whole-word wrapping only — never hyphenate, never split a word across lines; if a word doesn't fit on the current line, the entire word moves to line 2 (overflow-wrap:normal; word-break:normal; hyphens:none — the CSS defaults that refuse to break inside a word, deliberately re-asserted here so a future style tweak can't silently reintroduce breaking).
  • Suffixes stay glued to the surname — "Harrison Jr." is joined by a non-breaking space in the markup (Harrison Jr.), so it wraps as one unit and "Jr." can never strand alone on line 2.
  • Two lines reserved in every card, always — the name box is a fixed-height container (30pt for variants A/C, 28pt for variant B) whether the name needs one line or two, so the three cards in a row never differ in height. Short names are top-aligned in that box (chosen over vertical centering) so they sit flush under the badge row exactly like a two-line name's first line does — the badge-to-name gap never jumps around card to card.

All three variants are stress-tested against the same trio: Marvin Harrison Jr. (long name + suffix), Tetairoa McMillan (long first name + long surname, no suffix), and Bo Nix (short — the one-line case the top-align rule has to look right for).

Recommendation

Variant A — full name, 13px, unchanged 115×128pt card. It fixes the operator's exact complaint (no truncation, no split words, "Jr." never strands) without giving back any of V3's savings and without touching the font size, padding, or card height that V1/V2/V3 already established as the baseline — the only change is letting mininame wrap into a reserved 2-line box instead of ellipsizing at 1 line, plus one non-breaking space in the data layer between a surname and its suffix. B is a reasonable fallback if 13px reads as too tight in real device testing (drops to 12px, the last legal step before the 11px floor) but gives back 8pt of the savings and adds a size variant to maintain. C is the one genuine structural alternative — it buys the most one-line headroom for typical rosters — but it trades away the player's first name, which cuts against personalization for a marginal, mostly-unneeded gain now that A already fits everything. Ship A; keep C in back pocket only if a future name (e.g. a hyphenated-surname + suffix combo) is found that still doesn't fit A's 2 lines.
