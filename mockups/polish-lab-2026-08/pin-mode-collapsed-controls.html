Recommendation

Ship V1. It is literally the audit's #1-ranked lever, phrased almost exactly as the audit's own suggested fix ("Pinned: <player> · Edit, tap-to-expand"), it's scoped entirely inside TradesScreen.tsx (swap the <Card> body for a one-liner + local expand/collapse state — no new navigation, no changes to FeaturedTradeWindow.tsx or where outlook/fairness live), and it recovers ~246pt of the audit's cited ~839pt overflow with the lowest implementation risk. V2 recovers ~16pt more by removing the card shell entirely, but it's a materially bigger change (couples FeaturedTradeWindow to pin state, relocates outlook/fairness editing, changes what "Edit" does) for a small additional saving — worth a follow-on once V1 ships and if outlook/fairness editing genuinely belongs at the hub level instead of here. Neither variant alone closes the full 839pt gap; the audit's other single-pin items (verdict-paragraph disclosure ~68pt, AssetIdeasPanel row cap, screen padding/gap trims) still apply on top.
