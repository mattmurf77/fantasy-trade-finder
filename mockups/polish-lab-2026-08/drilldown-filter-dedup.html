Drill-in filter dedup — League tab roster focus (#237 · #243)

#237 (just shipped, 2026-08-02): the League tab's power-rankings chart card and the roster drill-in panel now share ONE filter state (subset + posFilter) — the All/Starters/Bench segmented control and the position pills render in both sections, so changing a filter anywhere updates both instantly and they can never disagree. This is an explicit operator requirement (mobile/src/screens/LeagueSummaryScreen.tsx, the SubsetControl/PosFilterPills comment block) and it must survive whatever ships here.

#243 scroll audit (`docs/feedback/items/243-scroll-audit/league-misc-surfaces.md`, §1b): while a team is focused, the two identical control sets cost 84pt of pure duplication — the same two controls, doing the same thing, both on screen at once — and combined with the still-visible "League home" row (79pt, irrelevant once you're reviewing a roster), the 658pt tab-screen viewport (iPhone 15/16-class, 393×852, minus safe insets + TopBar + tab bar) is exhausted at 692pt before a single roster row renders. Every drilled-in team focus forces a scroll before the user sees any player — the screen's actual payload.

Three frames below, all sharing the identical 658pt viewport budget: Current (faithful recreation, focused state) vs two proposed fixes — V1 (the audit's own suggested fix: collapse the chart card to a slim summary strip while focused, dedup down to one visible control set) and V2 (lighter touch: keep the chart card as-is, pin the drill panel's controls sticky, only hide the home row). Both variants apply only while a team is focused — the nominal/unfocused view is untouched in every variant; see the callout after the frames.

Recommendation

V1 — it's the audit's own top-ranked fix (#243's ranked list, items #3 and #4: "High impact, blocks the primary post-tap payload") and it clears the fold with real margin (137pt to spare) rather than a bare pass. V2 is included as the lower-risk fallback if hiding the chart card's own controls feels like too big a visual change to ship in one pass — it's a one-line-of-logic diff (conditional homeRow + a sticky style on the drill panel's control row) that still gets something above the fold, just not the full recovery.

Build note: both variants reuse the existing SubsetControl/PosFilterPills components as-is — V1 just conditionally skips mounting them in the chart card (selected ? null : <SubsetControl .../>, mirroring how oddsEnabled already gates a section on this same screen) and adds one caption row; V2 only needs position: 'sticky', top: 0 on drillFilter's wrapper (RN's ScrollView supports sticky headers via stickyHeaderIndices, which would need the drill control row promoted to a direct ScrollView child — a slightly bigger lift than the CSS-only web equivalent implies; flag this for the engineering pass). Neither variant touches subset/posFilter state, togglePos, or switchSubset — the #237 shared-state model is untouched.
