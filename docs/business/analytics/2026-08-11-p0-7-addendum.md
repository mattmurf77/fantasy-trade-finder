# Tracking-plan addendum — P0 remediation batch (analytics blindness, P0-7)

**Date:** 2026-08-11 · **Status:** adopted with commit 1 of the P0 remediation branch
**Parent:** [2026-07-17-tracking-plan-v2.md](2026-07-17-tracking-plan-v2.md) §S3
**Build:** [../../plans/audit-p0-remediation/hld.md](../../plans/audit-p0-remediation/hld.md) §1.2 / §4 Wave 0 · [lld-p0-7.md](../../plans/audit-p0-remediation/lld-p0-7.md) §1
**Registries:** `backend/analytics_taxonomy.py` (`ALLOWED_CLIENT_EVENTS`, `SERVER_FIRED_EVENTS`, `CLIENT_EVENT_PROPS`) · `backend/analytics_queries.py` (`NON_INTENT_EVENTS`, `WAT_LIVE`)

The taxonomy is **default-deny**: an unregistered client event is counted and
dropped at ingest **behind a 200**, and an allowlisted event with no
`CLIENT_EVENT_PROPS` entry raises at **import**. Both registries are required,
and the name must not collide with `SERVER_FIRED_EVENTS` (the disjointness
assert refuses to import on a collision, which crashes the app at boot). This
addendum is the tracking-plan precondition those registries' own comments
demand.

**Registration lands BEFORE any emitter.** That ordering is the whole reason
this is its own commit: a name registered ahead of its `track()` call is inert,
while a `track()` call ahead of its name is silent data loss with a
success-shaped response and a plausible-looking empty dashboard.

## Why now

The 2026-08-09 mobile UX audit's P0-7 finding is *analytics blindness*: the
app's most-used surfaces report nothing, and three separate events have been
firing into the default-deny wall — `invite_shared`, `deck_regenerated` and
`celebration_fired` — on top of the earlier NULL-`platform` incident. Every
claim about the invite loop, the Quick Set drop-off curve, the League tab, and
the Send-in-Sleeper leg has rested on zero rows.

## Events registered (16 client + 1 server)

### Navigation and League surfaces (P0-7)

| Event | Props | Fired when |
|---|---|---|
| `tab_selected` | `tab`, `from_tab`, `refocus`, `intercepted` | A bottom-tab press, recorded before `preventDefault()` so intercepted presses are visible. **NON_INTENT.** |
| `league_view` | `surface`, `state`, `platform`, `team_count`, `basis`, `subset`, `starters_available`, `outlook_shown`, `is_tab_root` | The League home / rankings surface has data to show. **NON_INTENT.** |
| `league_basis_changed` | `basis`, `from`, `boards_differ`, `team_focused` | Consensus ↔ personal basis toggle. `boards_differ` is what makes a toggle interpretable. |
| `league_subset_changed` | `subset`, `from`, `source`, `filter_count`, `picks_stripped` | All ↔ starters (or a filtered subset) switch. |
| `league_team_opened` | `via`, `rank`, `basis`, `subset`, `filter_count` | A team drill-in. `rank` is the team's rank, not a list index. |
| `league_home_action_tapped` | `action` | League Home's exit paths — the only question that screen answers. |

`platform` on `league_view` is the **LEAGUE** platform
(`sleeper` \| `espn` \| `mfl` \| `fleaflicker` \| `unknown`), matching
`league_selected`'s precedent. The **device** platform is a `user_events`
**column**, derived server-side at ingest from the batch body / `X-Device`
headers — it is never an event prop. That confusion is the NULL-`platform`
incident, and `test_p0_events_reject_device_platform_prop` now pins the
distinction.

### Send in Sleeper (P0-7 — the north-star send leg)

| Event | Props | Fired when |
|---|---|---|
| `sleeper_send_attempted` (client) | `surface`, `give_n`, `receive_n`, `from_deck`, `has_target` | The send button's `onPress`, before the request. |
| `sleeper_send_failed` (client) | `surface`, `error_code`, `status`, `kind`, `give_n`, `receive_n`, `from_deck` | The `catch`: network, timeout, or a server refusal. |
| `sleeper_send_succeeded` (**server**) | — | `POST /api/trades/propose` success path only. |

- **`surface` ∈ `deck` \| `match` \| `awaiting` \| `calculator`** — the four
  `SendInSleeperButton` mounts (P0-6 `SEND_SURFACES`). It is `awaiting`, not
  `suggested`: the second Matches mount is the *awaiting* send row, which is
  also what `capture/matches@espn.yaml`'s `populated--espn-awaiting` shutter
  photographs.
- `error_code` is a **closed** enum: the 12 server codes of
  `/api/trades/propose` plus `network` \| `timeout` \| `unknown`. 15 values,
  forever. `kind` is `SleeperWriteError.kind`, present only on
  `sleeper_rejected` / `sleeper_write_failed`.
- **The naming decision (HLD S-30).** These are `sleeper_send_*`, not
  `send_in_sleeper_*` as the audit's `06-resolutions.md` proposed, because
  `analytics_queries.WAT_DARK` reserved these exact strings on 2026-07-17 and
  `FUNNEL_STAGES` stage 8 + `FEATURE_VERTICALS["send_in_sleeper"]` already
  reference `sleeper_send_succeeded`. New names would have left all three dark
  one alias away from working.
- **Success is server-fired** because the propose route is the only place the
  send is *known* to have landed in Sleeper. A client-forgeable success would
  sit in WAT and funnel stage 8 next to server-authoritative `trade_ratified`.

### Invite loop (P0-3)

| Event | Props | Fired when |
|---|---|---|
| `invite_shared` | `league_id` | The invite banner's share sheet — **already firing today**. |
| `invite_link_opened` | `league_id`, `has_ref`, `format`, `auth_state` | `LeagueJoinScreen` mount (path form) and the legacy `?league=` capture. |
| `invite_league_pinned` | `league_id`, `source`, `ms_since_open` | The picker's auto-pin effect, immediately before the league is pinned. |
| `invite_pin_failed` | `league_id`, `reason` | The honest "you're not in that league" notice. |

- `has_ref` is a **boolean**, never the inviter's handle. The handle rides on
  `/api/session/init.invited_by` as it does today — an attribution field, not
  an analytics dimension. `league_id` is a platform league id, not a person.
- `format` ∈ `legacy` \| `path` — the one number that answers "did the new URL
  help?".
- **`auth_state` ∈ `signed_out` \| `authed_member` \| `authed_non_member` \|
  `account_only`.** The fourth value is new (lld-p0-3 D-8): HLD S-17 made the
  account-only intersection a first-class case, and without its own value that
  funnel is invisible. **Prop *values* are not constrained by
  `CLIENT_EVENT_PROPS`** — the registry allowlists prop *names* only — so this
  enum lives here and in the client, and D-8 is documentation, not a code
  constraint.
- `source` ∈ `picker_autopin` \| `join_screen`; only `picker_autopin` is
  emitted by this build. `reason` ∈ `not_member` \| `expired` \|
  `session_init_failed`; only `not_member` is emitted by this build.
- **`invite_shared` has been firing into a default-deny wall since it shipped**
  (`InviteLeaguematesBanner`). Every invite-funnel claim predating this commit
  rests on zero rows. Registering it is a bug fix, not an addition — and it is
  still only *half* the volume: the League tab's own Invite module
  (`LeagueScreen.tsx` `inviteLeaguemates`) fires nothing at all. That gap is a
  `NEXT.md` row, not a fix here.

### Experiments and Quick Set (P0-7 §6 F1 / F3 / F4)

| Event | Props | Fired when |
|---|---|---|
| `experiment_exposed` | `experiment`, `variant`, `unit`, `key` | First **consumption** of an experiment-overlaid flag key, once per key per session, deferred (never during render). **NON_INTENT.** |
| `quickset_step_advanced` | `position`, `tier_index`, `tier_count`, `seeded_accepted`, `picked_n`, `via`, `ms` | A Quick Set rung is completed. **INTENT** — it is real ranking intent. |
| `quickset_abandoned` | `position`, `tier_index`, `tiers_done`, `ms`, `reason` | Quick Set is left mid-position. **NON_INTENT.** |

`experiment_exposed` was already in `FUNNEL_CRITICAL` and already mirrored in
the mobile SDK, but was **never in the allowlist** — a live instance of this
file's own trap. `backend/experiments.py` uses assignment as an exposure proxy
and reports the dilution; every A/B read is exposure-diluted until this lands.
`unit` (`account` \| `device`) is registered but **not emitted today**: the
client cannot derive it, because `GET /api/feature-flags` returns the merged
maps without the `unit_type` the server knew. Registering it now means adding
it later is a server change alone, never a taxonomy change.

Quick Set's server event (`quickset_completed`) fires **per completed
position**, so a user who does three rungs of QB and quits is invisible today.
F3 + F4 are the per-step drop-off curve.

### `deck_regenerated` (P0-8/9 D-4, approved fold-in)

| Event | Props | Fired when |
|---|---|---|
| `deck_regenerated` | `position`, `new_trades` | The post-Quick-Set diff banner: the forced job completed and `new_trades` cards were not in the pre-Quick-Set deck. |

**Registration only — the emitter already exists** (`TradesScreen.tsx`) and has
been dropped every time. This is the S5 reveal counter, the number the
trades-first hypothesis turns on; two P0-9 documents assert it is registered
and it is not. Props match the shipped call site exactly. It stays **INTENT**:
it follows a deliberate Quick Set completion, and the user has already fired
server-side intent events in the same moment, so it cannot inflate DAU on its
own.

## The DAU/WAU seam — 2026-08-11

`INTENT_EVENTS = (SERVER_FIRED | ALLOWED_CLIENT) − NON_INTENT_EVENTS`, i.e.
**taxonomy growth is intent-by-default**. Four of the sixteen new names are
therefore added to `NON_INTENT_EVENTS`:

- **NON_INTENT (4):** `tab_selected`, `league_view`, `experiment_exposed`,
  `quickset_abandoned`. Without these four lines, a tab tap and a League mount
  would make DAU/WAU ≈ app-open count from ship day, and every retention and
  churn series would break at that seam permanently and silently.
- **INTENT (12):** the two League change events, the team drill-in, the
  League-home action, both send client events, the four invite events,
  `quickset_step_advanced`, `deck_regenerated`. These are a user acting on the
  product.

**Expect a real, designed step in WAU on and after 2026-08-11** as
league-browsing, invite-sending and send-attempting users start counting.
Read it as this change, not as drift. Series that cross this date should be
split at it.

### WAT (north star)

`WAT_DARK` is now **empty**; the three `sleeper_send_*` names moved into
`WAT_LIVE`. Historical rows carry none of them, so **past WAT is unchanged** —
only the forward series gains the send leg. The unconditional
"send-leg WAT events not in taxonomy yet" caveat in the engagement report was
**deleted**: it became false the moment this commit landed, and the row-level
`caveat: "dark"` from `is_dark(conn, WAT_LIVE, …)` already degrades a
send-row-less window honestly.

## What is deliberately NOT here

- **`find_trades_tapped`'s empty prop allowlist — a live defect, recorded not
  fixed.** `CLIENT_EVENT_PROPS` registers `"find_trades_tapped": frozenset()`,
  so **every** prop on that event is stripped at ingest, including the `source`
  prop the existing `'prefs_changed_strip'` call site sends. The event lands;
  its only dimension does not. The fix is a one-word change, but silently
  widening a **shipped** event's prop surface inside a registration commit is
  the opposite of this commit's discipline, and it belongs to whoever owns that
  funnel metric. → `NEXT.md`.
- **`send_unavailable_shown` / `trade_copied`** (P0-7 D-4 declined). P0-6 makes
  the non-Sleeper mount render a copy affordance instead of a send button; any
  impression event on that render path would conflate copy-affordance
  impressions with send impressions and corrupt the send-funnel denominator.
  Instrumentation is `onPress` / `catch` only.
- **`is_self` on `league_team_opened`** (HLD S-33). The session-user ↔
  `PowerRankedTeam.user_id` identity was never proven, and a guessed prop is
  worse than a missing one. Adding it later is one taxonomy line plus one
  client line — with the identity proven first.
- **F2 `first_session_started`** (HLD S-37). Arm attribution is already
  derivable from `experiments.stamp_for_event`.
- **`sleeper_send_succeeded` does not bump `last_trade_proposed_at`** (HLD
  S-34). It is deliberately absent from `database._EVENT_TO_USER_COL`: that map
  drives notification gating, and changing gating behaviour is out of scope for
  an instrumentation item.
- **No `FUNNEL_CRITICAL` change.** `experiment_exposed` is already there; the
  other fifteen are not pre-auth funnel primitives. Growing `FUNNEL_CRITICAL`
  changes the SDK's overflow drop policy and would desync the SDK's
  hand-mirrored copy.
- Position-filter pills; drill-in close/dwell; the Send confirm-dialog cancel;
  the `validateTradeSend` warning branch; the SleeperConnect round-trip (owned
  by backlog A-19); season-outlook interactions while `outlook.odds` is dark
  (carried as the single `outlook_shown` boolean).

## The `celebration_fired` → `celebration_shown` rename (P0-9 D2)

Recorded here; **no taxonomy edit accompanies it.** `celebration_shown` is
already registered with matching props (`beat_key`, `beat`). The **client**
renames its three `TradesScreen.tsx` call sites (executed later in this batch
by `W2-TS`) and **no alias is added** (HLD S-41) — the taxonomy is the shipped
surface and an alias would enshrine a typo.

## A wider finding, queued beyond this build

Sweeping every `track('<name>'` literal in `mobile/src` against
`ALLOWED_CLIENT_EVENTS` (source: `lld-p0-8-9.md` §4.3): **73 distinct client
event names are emitted; 33 are absent from the taxonomy and are
counted-and-dropped.** This commit fixes two of them (`invite_shared`,
`deck_regenerated`) and `W2-TS` fixes a third by rename
(`celebration_fired`). **30 remain**, including `calc_trade_shared`,
`deck_summary_viewed`, `guide_tour_reenabled`, `help_opened`, the three
`push_primer_*` events, `player_menu_opened`, `trio_session_started` and
`untouchable_toggled`. The full list goes to `NEXT.md` and reinforces `G-031`.
Registering them is a taxonomy triage pass, not a P0 fix, and each needs a
props decision — which is why it is queued rather than swept in here.

## Reading them

- **Does the invite loop convert?** `invite_shared` → `invite_link_opened`
  (split by `format`) → `invite_league_pinned`. `invite_pin_failed{not_member}`
  is the honest denominator of "invited the wrong person / wrong league".
- **Where does Quick Set lose people?** `quickset_step_advanced` by
  `tier_index` against `quickset_abandoned` by `tier_index` — a per-rung
  survival curve the server's per-position `quickset_completed` cannot express.
- **Is the send leg real?** `sleeper_send_attempted` → server
  `sleeper_send_succeeded`, split by `surface`. The gap is
  `sleeper_send_failed` by `error_code` — a failure rate, not a preference.
- **What is the League tab for?** `league_view` → `league_home_action_tapped`
  and `league_team_opened`. If neither follows a view, the tab is a dead end.
- **Did the S5 reveal land?** `deck_regenerated{new_trades}` distribution. A
  mass of zeros means the reveal beat is promising something the deck does not
  deliver.
