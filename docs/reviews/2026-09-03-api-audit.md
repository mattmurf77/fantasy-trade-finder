# API audit — redundancies and unnecessary calls (2026-09-03)

> **Purpose:** static audit of every HTTP call in the app: clients → backend (mobile, web, extension), backend route overlap, and backend → league platforms. Read-only; nothing was changed. Line numbers are against `main` @ `c7e75666`.
>
> Method: four independent read-only passes (one per layer), then every high-severity claim re-verified by hand against the source. Request counts are per-code-path counts, not measured traffic; `api_events` in `user_events` would give real volumes.

## Headline

| Layer | Finding |
|---|---|
| Backend → Sleeper | **~26–29 upstream calls per `session/init`** for a Sleeper league: rosters 3–4×, league meta 3×, drafts 2×, and 18 weeks of transactions every app open, year-round. `session/init` fires on every cold start and every foreground resume older than 60 s. |
| Mobile → backend | Every cold start and every resume rebuilds the whole league session (rosters + users + init + up to 2 link calls) with no liveness check; `sessionPing` exists but has no caller. Rosters/users are fetched for the init body, discarded, then fetched again by Trades, the calculator, DNA and the hub. |
| Web → backend | The 4.8 MB `/api/sleeper/players` body is downloaded in three flows, JSON-parsed by `apiFetch`, and never read. Notification poll every 30 s with no visibility pause. 5 requests per ranking swipe, 3 redundant. League switch fetches everything then reloads and fetches it all again. |
| Backend routes | 4 routes with no caller anywhere (one is a destructive write), 5 tests-only, 7 admin sub-routes never called, 20 flag-dead, 2 line-for-line duplicate POST bodies, and a mobile screen calling a route that does not exist. |
| Extension | Sound. Background 15-min refresh fetches rankings the content script then ignores (stale-badge bug, 4 wasted req/h per open tab). |

Deploy context that matters: `render.yaml:16` runs **one** gunicorn worker, so in-process caches do share across requests; the problem is that `_sleeper_get` (`server.py:564`) has no cache at all, and the one league-meta cache that exists (`26472`) is consulted by 2 of 9 callers.

## Ranked findings (cross-layer)

Severity weighs wasted calls × frequency × upstream cost. Sleeper calls are the scarce resource (rate limits, and they run inside the session-init daemon the user waits on).

### 1. `session/init` daemon: trades sync walks 18 weeks every app open — HIGH
`sleeper_trades_service.py:128-143` loops `WEEKS = range(1, 19)` (`:40`) and fetches `/league/{id}/transactions/{week}` for each, on every `session/init` (`server.py:19591`). Only the live week can change; the insert is idempotent. In the offseason all 18 are wasted. ~17 wasted Sleeper calls per init; a Sleeper outage costs up to 18 × 15 s of daemon time.
**Fix:** fetch only the current week (plus a one-time backfill flag per league), or move the sweep to the daily tick.

### 2. `session/init` daemon: rosters and league meta re-fetched by each consumer — HIGH
The comment at `server.py:19497-19502` says "Fetch ONCE here, hand it to both consumers" — the trade block gets it (`19508`, `19520`), but `_sync_sleeper_owned_picks` (`11672`) re-fetches rosters (`11693`) **and** meta (`11694`), and draft-status refresh (`15872-15884`) fetches meta, drafts and rosters a third time when its TTL has lapsed. The scoring auto-detect at `19427` calls Sleeper unconditionally: `existing_fmt` is read at `19424` and then never checked, despite the comment at `19410-19412` saying the call is skipped once stored. Telemetry link (`suggestion_telemetry.py:377`) is a fourth rosters read when any unlinked trade exists.
**Fix:** thread `_rh_roster_rows` and one `meta` into the owned-picks and draft-status calls; gate auto-detect on `existing_fmt`. Also hoist the three identical `is_linked_platform_league` SELECTs (`19504`, `19549`, `19623`) and the duplicate `get_league_scoring` (`19185`, `19424`).

### 3. Mobile: full re-init on every launch and every resume, never pinging first — HIGH
`useSession.ts:363-383` → `initLeagueSession` (`auth.ts:377`) → GET rosters + GET users (`auth.ts:416-418`) + POST `session/init` (`:239`), plus GET+POST `/api/sleeper/link` when the session is unverified (`sendInSleeper.ts:146`, `:175`). Fired from `App.tsx:117` (boot) and `App.tsx:210` (every foreground, 60 s throttle at `useSession.ts:61`). `sessionPing` (`auth.ts:320`) has zero callers. Each re-init also pays #1 and #2 server-side and kicks a trade pregen (`useSession.ts:376`).
**Fix:** ping first; re-init only on 401. FB-45's deploy-kills-session concern is fully served by that.

### 4. Web: 4.8 MB players body fetched three ways and discarded — HIGH
`app.js:625`, `:771`, `:2387` call `/api/sleeper/players` and check only `pr.ok`. `apiFetch` (`:121-139`) then clones, reads and `JSON.parse`s every response to build a `summary` string that nothing reads. `/api/sleeper/players/warm` (`server.py:18754`) already exists; its comment claiming "Web client keeps /api/sleeper/players because it consumes the body" is wrong.
**Fix:** point web at `/warm`, delete the summary block, then `/api/sleeper/players` can retire (positional-tiers uses `/api/players?view=summary`, not this).

### 5. Mobile: rosters/users fetched for the init body, then re-fetched by screens — HIGH
No `setQueryData` seeds `['league-rosters'|'league-users']` after `auth.ts:416-430`; `TradesScreen:2762/2772`, `InLeagueCalculator:423`, `TradeDnaSheet:353`, `TradeFinderHub:284` fetch both again. With #3 that is 4 proxy calls per launch for data the server just rebuilt into `league_members`.
**Fix:** either seed the query cache from the init path, or let `session/init` accept `{league_id}` and pull rosters server-side (collapses 3 requests to 1 and removes the client-side Sleeper proxy hop entirely).

### 6. Web: 5 requests per ranking swipe — HIGH (onboarding volume)
`submitRanking` → `rank3` (already returns `interaction_count/threshold/threshold_met`, `server.py:7631-7634`) → `updateProgress(data)` (`app.js:1445`) → `_onRankingSwipeComplete` → `fetchRankingProgress(true)` (`:2635`) → `loadTrio` after 350 ms (`:1493`) → `/api/trio` + `/api/progress` (`:1779`) + `updateUnlockBar` → `fetchRankingProgress(true)` again (`:1797`). Three of five are redundant; ~120 wasted per user reaching the unlock threshold.

### 7. Web: notification poll every 30 s, never paused — HIGH
`app.js:4802` `setInterval(fetchNotifications, 30000)`; cleared only in `logout` (`:275`). No `visibilitychange` handler exists in `app.js`. 120 req/h per backgrounded tab.

### 8. Web: league switch does the full boot twice — MEDIUM
`switchToLeague` (`app.js:2372-2461`) fetches players + rosters + users and POSTs `session/init`, then `location.reload()` (`:2461`) and `boot` repeats all of it. Everything after the `return` at `:2462` is dead code.

### 9. Hourly draft-status sweep: no season gate, no active-user filter — MEDIUM
`server.py:21135-21141` sweeps up to 50 leagues × 3 Sleeper calls per tick; `load_league_ids_for_draft_status_refresh` (`database.py:9653`) scans every `leagues` row. A `not_drafted` league is re-probed every 3 h (`15797-15801`) → 24 calls/league/day for the ~9 months no draft can happen. The daily roster sweep (`20763`) fetches the same rosters independently, and `load_history_sweep_leagues` (`database.py:11529`) sweeps every league ever synced.

### 10. Trade job: prefs and picks loaded 2–3× — MEDIUM (CPU, not network)
Request thread reads `load_league_preference` (`12067`) and `_infer_user_outlook` (`12070`) for the cache key; the worker re-reads both (`5936`, `5972`), and `_infer_user_outlook` → `_user_pick_share` → `load_draft_picks` (`5758`) which the worker loads again at `6009`. Per-opponent N+1 `load_league_preference` inside the members loop (`6003`); `load_league_preferences_bulk` (`database.py:9132`) exists and is already used by `trade_breaker.py:375`. Runs on every `session/init` via pregen.

### 11. Mobile: trade pregen fires on every launch regardless of first-session state — MEDIUM
`tradePregen.ts:64-78` is gated on `onboarding.v2` + `onboarding.trades_first` (both true) and per-launch dedupe only — not on first session. It races `TradesScreen`'s own auto-generate (`:2213-2220`). Server dedupes a fresh job, so usually one wasted POST; unproven whether a POST landing mid-`session/init` produces a second job.

### 12. Mobile: Trades landing mounts five ungated calculator queries — MEDIUM
`calc.inline_home` (true) mounts `InLeagueCalculator` on Trades (`TradesScreen:7596`) with `trade/values`, `sleeper/rosters`, `league/picks`, `league/power-rankings`, `coverage` (`InLeagueCalculator.tsx:412-450`), none gated on the canvas being opened. Power-rankings is not cheap.

### 13. Mobile: format-default applier writes on every boot — MEDIUM
`useScoringFormat.ts:89-116`: GET format-stats → POST `scoring/switch` even when it equals the active format → invalidates progress/rankings/streak/trio/tiers-status/trends (`:68-73`), re-firing the RootNav progress query that just resolved. Web's positional-tiers page has the same pattern: POST `scoring/switch` on every page load (`positional-tiers.html:2659`), twice on toggle (`:2866`, `:2884`), then 4 serial `/api/rankings` fetches (`:2678`).

### 14. ESPN link reads the same league 3–6× — MEDIUM (low volume)
`server.py:24372` (oracle), `24436-24452` (every linked league), `24249` (target again), `24800` (anonymous probe), `24810` (verify again if public).

### 15. `/api/league/invite-meta` is a public, unauthenticated, uncached Sleeper proxy — MEDIUM
`server.py:22984-23012`; one upstream call per hit, no rate limit by design. Trivially abusable to burn the Sleeper budget.

### 16. Extension: background refresh result is never applied — LOW
`background.js:82-99` fetches and broadcasts; `content.js:127` returns early when `leagueId === loadedLeagueId`. Same for the popup Refresh button (`popup.js:157`). Badges stay stale until the user navigates away and back. `popup.js:82` and `background.js:41` are two implementations of the same fetch with different staleness rules.

### Smaller items
- Mobile `RecordPicksScreen.tsx:111` polls `draft/board` every 15 s unconditionally (root push, keeps polling under any screen above it); `DraftRoomScreen:221` is the correct pattern.
- Mobile RankMenu prefetches under keys the target screens never read (`TabNav.tsx:879-923` vs `TiersScreen:206`, `ManualRanks:147`, `PickAnchorScreen:97`); a full `/api/rankings` payload per menu tap.
- Mobile `signIn` response already carries `leagues` (`server.py:22409`) but `SignInScreen:490` immediately calls `getLeagues`, a second Sleeper round-trip (`18465`). Check the compact shape suffices.
- Mobile `progress` and `tiers-status` fetched outside TanStack alongside cached copies (`usePresentationDeck.ts:98`, `quicksetProgress.ts:62`); `TeamReviewScreen:1036` has `staleTime: 0` on league-prefs; entitlements refetch on every foreground with no throttle (`useEntitlements.ts:100`); bell open always POSTs read-all even at zero unread (`TopBar:213-227`).
- Web `/api/trades/liked` (full cards) fetched after every swipe/load for a badge count (`app.js:3185`, `:3262`, `:4011`); trades tab fires 5–6 uncached requests per visit (`:2752-2760`); `session/ping` at `:211` is dead weight since `initSession` always follows.
- Web `loadMarketPulse` (`app.js:4929`) is unreachable from normal navigation — the section never loads (a bug, not a redundancy).
- Backend: DP values CSV fetched twice per boot (`server.py:341`, `1662`); Expo push sent one POST per user (`20129-20139`) where Expo accepts 100/batch; `_sleeper_get` permanently downgrades SSL verification for the process after one cert failure (`598-611`).
- Anthropic: one `messages.create` per `/api/trio` when the rotation lands on `tightest`; result not cached; `generate_next_matchup` (`smart_matchup_generator.py:73`) is dead code.

### Duplicate bodies
- `/api/trio/skip` (`21815`) and `/api/tiers/dismiss` (`21856`) are identical except response keys and one decorator (`@_gate_unverified_write` on dismiss only). Alias one path; `/api/skips` is their unused read side.

- `/api/{espn,mfl,fleaflicker}/{leagues,link,import}` share 15-line bodies; the MFL member-persistence block is copy-pasted three times (`27230-27265`, `27370-27410`, `27480-27515`). Mobile already builds `/api/${platform}/…` (`platformLink.ts:111/134/142`).

- `propose`, `propose-mfl`, `propose-espn` share a ~40-line preamble; a single dispatcher was deliberately rejected (`28145-28150`, numeric id collisions) — extract the preamble, keep the routes.

Not redundant — but `member-unlock-states` is a live wasted call on every League screen visit on both clients.

### Bug found in passing

### Un-provisioned cron levers
`/api/cron/{value-snapshot,players-refresh,roster-snapshot,receipts-grade}` are not in `render.yaml` (which schedules only realtime/hourly/daily); each is duplicated by a fallback guard inside a tick (`21113`, `21381`, `21422`, `21425`). Operator tools, not waste — but the docs should say the guard is what fires.

## Suggested order

1. **Server, no client change:** #2 (thread rosters/meta, gate auto-detect), #1 (current-week-only trades sync), #10 (bulk prefs, pass request-time outlook into the job). Cuts ~25 Sleeper calls and several DB reads per login with zero contract change.
2. **Web, small diffs:** #4 (`/warm` + delete the summary block), #7 (pause on `visibilitychange`), #6 (drop the redundant progress calls), #8 (delete the dead post-reload block, skip the pre-reload fetches).
3. **Mobile, one PR:** #3 (ping-then-init) + #5 (seed the roster/users query cache) + #11 (gate pregen on first session or on Trades being the landing tab). This one touches `session/init` frequency, which is the FB-45 contract — walk it through the gates.
4. **Route hygiene:** delete the four no-caller routes and the ten dead wrappers, alias skip/dismiss, fold `/api/progress` and `/api/trades/matches`, fix the `test-users/templates` call. Update `docs/api-reference.md` row-by-row.
5. **Cron:** season-gate the draft-status sweep and filter both sweeps to leagues with a session in the last N days (#9).

Not recommended: merging the three propose routes (decided against, `28145`), or a "bootstrap bundle" replacing flags/entitlements/session/init — that is a design change, not a de-dup; `session/init` does not embed any of those payloads today (`19700-19715`).

- Whether the server-side job dedupe fully absorbs the double `trades/generate` when the second POST lands mid-`session/init`.
- ~~Whether `ANTHROPIC_API_KEY` is set in Render~~ — **resolved 2026-09-03** (Render API, service `srv-d7g37ftckfvc73a32gvg`): the only env vars set are `CRON_SECRET`, `DATABASE_URL`, `EXPERIMENT_SALT_KEY`, `FTF_TESTER_ALLOWLIST`, `PYTHON_VERSION`, `SLEEPER_TOKEN_KEY`. `ANTHROPIC_API_KEY` is **not set in prod**, so the smart-matchup path never calls Claude there — `_algorithmic_trio` is what runs. The Anthropic notes in §Smaller items are dev-only.
- Whether the compact `leagues` in the `/api/extension/auth` response has every field `LeaguePickerScreen` needs.
- Admin routes may be hit by operator curl not visible in the repo.
