# Mobile search continuity — manual TestFlight checklist

2026-09-05. **Not run.** These are the operator's native-runtime checks after a reviewed build is available. No simulator/Maestro substitute was executed. Scope and source proof: [mobile-scope.md](mobile-scope.md), [mobile-code-walk.md](mobile-code-walk.md).

Use an existing authorized league and test account with identifiable roster players and at least two possible partners. Record build, platform, league format and flag posture with any failure. Primary posture is `calc.inline_home=true`, `calc.results_push=true`; do not change production flags just to exercise a legacy branch.

1. **Receive-only, empty and non-empty searches.** On Find a Trade leave SEND empty, select one GET player, and search. Verify the chosen target/team survive the request and Back; a sole target must not silently become a different player. Compare with a completely empty canvas and a SEND-only canvas. With authorized request traces, check that GET-only sends that ID as `pinned_receive_players`, not an empty/unrelated pin list. Do not interpret this patch as approval of an unimplemented multi-selection fallback policy.

2. **Draft and partner on Back.** Build with two SEND assets and one GET asset; choose a partner in the canvas rather than the parent filter. Search, then use navigation Back and the in-page Back/Change action in separate runs. Expect the original builder sides and selected partner. Repeat after changing the partner, and after clearing the partner to Any. Edit the returned draft and search again; the edited draft, not an earlier prefill, must be used. Rapidly double-tap Find: expect one pushed results page, so one Back returns to the builder.

3. **Same request for Find More and Retry.** Run a SEND-anchored fair search and a GET-only model search separately. Use Find more trades. With a controlled request failure in an authorized test environment, use Try again. Verify the request family, selected asset IDs and partner remain the same; fair Retry must not become an unanchored model search. No assertion of additional unique results is intended—the existing endpoint may return the same eligible offers.

4. **Fairness, shape and refresh.** Set the existing fairness control and, where available, a shape chip; search into the pushed deck. Verify the same settings are reflected in applicable requests. Change a preference and use the refresh strip: selected assets and partner remain, while the explicitly changed preference applies. From a GET-only model deck, complete an existing Quick Set/ranking workflow that regenerates on return: the same target and partner must remain. If an existing model-deck suppression note offers Undo, verify its regeneration likewise retains that request. Repeat a cold launch with fairness previously saved, tapping Find promptly; the first request must use the restored choice. No restart/device synchronization beyond the existing local preference is claimed.

5. **Pending / zero / error / stale response.** In an authorized slow-network test, a SEND-anchored request must show loading and disable repeated manual Find, not show a completed-zero claim or stale prior card. A completed zero should say no trade was found and offer Back to calculator; it must not spin indefinitely on a first-run route. An error should show Try again. Change fairness or switch league while a response is delayed: the old response must not refill the new context or unlock a newer pending request.

6. **Explicit changes and league reset.** After searching partner B and returning, edit SEND and then select partner C in the parent team/DNA control. Expect C, the edited SEND and an empty incompatible GET side; selecting/clearing to Any must not resurrect B. Remove/change selected targets or choose Search without/Search all where offered; a subsequent search must not resurrect saved request IDs. Change leagues and verify old canvas assets, temporary partner, pins and shape are gone. Return to the original league and verify durable Untouchable/Target rules, rankings and the existing fairness preference were not deleted by the temporary-state reset.

7. **Other entrances and retained surfaces.** Repeat a League Buy/Sell Offer/Target handoff and a pushed calculator Find to catch forwarding differences. Open More Offers, change its existing filters, and Back: verify the underlying draft/deck remains as before; do not assume a new initial partner/package default. Smoke-test Win Now, queue, like and provider-send controls without authorizing an actual provider send merely for this check. Card tiers/chips/explanations must look unchanged.

8. **Legacy posture only if an authorized test build already exposes it.** With results-push off, repeat GET-only and SEND-anchored searches and Back. The searched sides should restore rather than an empty pin-derived draft. With canvas-results on, a delayed fair request must keep its existing Looking state until completion, then show its existing zero/error/result state. Both manual Find button layouts must share request-preserving behavior.

Log observed failures with the exact steps and request/result distinction. A native failure blocks a claim that the affected scenario passed; do not substitute structural tests for that observation. TradeBrowseAll's already-dispatched-pass Undo remains a separately deferred P1, not an acceptance claim of this patch.
