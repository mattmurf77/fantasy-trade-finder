# Plan: Connected Rankings — provenance, source connectors, and assisted import

> **Final (v4, 2026-08-15).** Dual-agent validated: 4 rounds, both lenses signed off with no blocking objections in Round 4; the nine Round-4 non-blocking suggestions are folded in below. Reconciliation log: [`reconciliation-log-2026-08-15.md`](reconciliation-log-2026-08-15.md).
>
> **Framing.** Replaces the framing "replace paste/CSV with platform auth" with what the research supports: a provenanced board, zero-credential source connectors, an assisted-export path for user-authored rankings, one sanctioned authenticated connector (MFL) under strict conditions, and refresh-as-proposal. Paste is demoted, never removed. **Hard dependency:** this plan conforms to the merged device-side platform-auth decisions in `docs/plans/device-side-platform-auth-prd-2026-08-12.md` and `docs/plans/device-side-platform-auth-hld-decisions-2026-08-13.md`; it does not re-litigate them.

## 0. Premise audit (research finding that reshapes the plan)

The initiative assumes candidate sites hold **the user's own rankings** behind auth. Most do not:

| Platform | User-authored rankings? | Machine access | Verdict |
|---|---|---|---|
| **MyFantasyLeague** | **Yes** — `export?TYPE=myDraftList` is the owner's ordered player list (per-league). **Caveat: `myDraftList` appears nowhere in `docs/` or `backend/` — the claim rests on external research with zero in-repo corroboration; verifying it is WS-H discovery item (0)** | Documented, sanctioned API; formal Developers Program. Transport nuance: `docs/integrations/mfl.md` §2 says there is **no separate MFL API key — the credential *is* the session cookie**, and §Auth notes MFL restricts APIKEY-style auth to exports only. So "APIKEY" is plausibly the same secret in a query string (worse custody: proxy/access-log exposure), not a distinct read-only credential — this contradicts the device-auth PRD's APIKEY framing and **must be reconciled in WS-G (docs/ wins per CLAUDE.md; whichever loses gets edited)** | **The only candidate combining user-authored data + sanctioned API.** Transport for this feature: the **existing encrypted `mfl_credentials` cookie, `Cookie:` header only** — a distinct APIKEY is a Q7 discovery output, not an assumption. Open questions: endpoint verification, pick representation, draft-list density |
| **FantasyPros** | Yes — Cheat Sheet Creator / "My Rankings" behind login, premium-gated, **user-facing CSV export exists** | Official API (`x-api-key`) is consensus/per-expert only — **no endpoint returns a user's own rankings**; keys personal-use licensed | **No sanctioned connect path.** The honest route is assisted export: the user exports their own CSV and hands it to FTF |
| **Dynasty Nerds / DynastyGM** | Yes, inside a $69.99/yr paid product | No public API; app-only bearer-token JSON | **Partnership-or-nothing.** Paid direct competitor; no scraper, no credential collection |
| **KeepTradeCut** | **No** — crowd consensus; a user's votes feed the community number, there is no personal board | No API, no CSV; ToS bars scrapers **and** competitive use | **Non-starter twice over.** NOTE: FTF already scrapes KTC daily (`data_loader.py`, spoofed UA, blend weight default 0.5) — a pre-existing exposure surfaced as an operator decision (Q2); this plan adds no user-facing KTC surface under any option |
| **FantasyCalc** | No — values derived from real league trades; parameterized by league shape | Public unauthenticated JSON (undocumented but open, widely consumed) | **The one user-facing zero-credential external source in v1**; params map onto FTF's `1qb_ppr` / `sf_tep` |
| **DynastyProcess** | No — open consensus data | Open CSVs, already a first-class FTF dependency | **Test-only reference adapter.** Not user-selectable: FTF's default consensus already IS DP blended with KTC, so "seed from DP" would ship a picker option ≈ the user's default board minus the KTC half — unexplainable and it inherits the R1 copy problem |
| **Sleeper** | No rankings surface | n/a | n/a |

**Consequences:**
1. "Import their rankings" is deliverable from exactly one sanctioned API (MFL, with caveats) plus assisted export (FantasyPros et al.). Everything else is consensus — a valuable but **different** feature that must be labeled honestly ("seed from FantasyCalc consensus", never "your FantasyCalc rankings").
2. "Connect" to the remaining sites would mean FTF holding third-party passwords/session cookies and replaying them on a schedule — exactly the custody model the device-auth programme is dismantling (G1 "no server-side JWT at rest", G2 "stop the MFL password transiting FTF", D5). Any new credentialed connector conforms to those decisions or doesn't ship.
3. **Paste is not replaced.** It is the universal path (podcast tiers, spreadsheets, unsupported sites); the incumbent (FantasyPros Draft Wizard) still ships paste despite far more integration leverage. Paste is demoted to "Paste instead"; `ranks.import` stays ON.

## 1. Objective & Definition of Done

**Objective.** Reduce time-to-a-real-board and keep boards fresh: (a) the board knows where each ranking came from and when; (b) zero-credential connectors for sources that sanction machine access; (c) assisted export for sources where users can legitimately extract their own data; (d) one sanctioned authenticated connector (MFL, existing encrypted cookie, header-only) if its gates clear; (e) refresh that is non-destructive by construction.

**Definition of Done** (all must hold on `main`, `ranks.connect` at 100%):

| # | Criterion | Verification |
|---|---|---|
| D1 | Per-player board provenance: `source`, `sourced_at`, `user_edited` — where `user_edited` is **captured at write time across ALL SIX board-write paths**: rank3 swipes (`/api/rank3` — the core Elo matchup loop and the app's primary board-building mechanism), tiers/save, tiers/copy-from-format, anchor/save, rankings/reorder, import-apply resolution taps (the repo's authoritative enumeration is the **call-site set** — override writes at server.py:6797 copy-from-format, 7504 tiers/save, 7677 anchor/save, 8060 rankings/reorder, 8230 import-apply, plus rank3's swipe family; `_refresh_taste_board_prior`'s docstring at server.py:4018 is stale — it omits import-apply even though import-apply calls the helper at server.py:8244 — A0 fixes it in passing). **Mechanism (a), named explicitly: server-side pre-write/post-write diff inside each route — no client protocol change**, so already-shipped builds and the web client stay safe; tiers/save's existing `cleared_pids`/`demoted_pids` and rank3's `ranked` array are already exact touched-id signals. **Fail-safe: any board write reaching `save_tier_overrides` from an uninstrumented path marks its ids `user_edited = true`**, and if a client-supplied signal is ever added, absent-signal ⇒ `user_edited = true`. **Note the two persistence families:** the override map (`save_tier_overrides`) and rank3's swipe family (`save_ranking_swipes`, server.py:5957) — the fail-safe backstop guards only the former, so an unenumerated swipe-class write does NOT inherit it; rank3's coverage comes from its explicit A0 instrumentation, not the backstop. Exact per-id attribution is unrecoverable retroactively (`apply_reorder` writes an override for every pool id), though a conservative divergence signal exists (`abs(elo − seed) > 1e-6`, already used by the taste prior) — it over-marks harmlessly. **Backfill policy: every pre-migration override is `user_edited = true`** | Schema + tests incl. a legacy-shaped fixture AND a rank3-only-built board fixture (guards against a vacuously-passing pinned-set test); UI copy exists for "this board predates provenance" |
| D2 | Re-seeding **never silently displaces a user-pinned rank.** Merge operates in **ordinal space**: user-edited players keep their absolute rank index (neighbours flow around them); the merge always emits a full permutation applied through `apply_reorder`, preserving order + tier-band occupancy (the "44 elite QBs" bug, FB #60/#69, is why — note: assert on order and tier-band occupancy, NOT exact Elo-multiset equality, since `apply_reorder`'s tie-break subtracts 0.001 per tied step). Conflict = an incoming order that would move a pinned player's index by > N. Resolution UI: per-row keep/replace **plus bulk "replace all / keep all"**, with a stated row-count threshold above which the per-row list is suppressed in favour of the bulk choice. **Escape hatch keyed on board STATE, not migration provenance: any fully-pinned board (all ids `user_edited`) gets the single all-or-nothing accept backed by the WS-A2 snapshot ring** — pre-migration boards are the dominant case (the all-true backfill makes the merge admit only the identity permutation), but a post-migration board that becomes fully pinned through heavy paste/reorder use hits the same dead-end and takes the same path | Merge tests assert pinned indices + tier-band occupancy post-merge AND that an all-pinned fixture reaches a resolvable state; Maestro `rank-resync-conflict.yaml` includes the legacy-shape assertion |
| D3 | 1 user-facing zero-credential source (FantasyCalc) + 1 test-only reference adapter (DynastyProcess) prove the contract | Fixture-based integration tests + live staging smoke |
| D4 | Assisted-export path ships (file pick / URL paste → existing matcher), proven against a real FantasyPros cheat-sheet CSV fixture | `test_rankings_import.py` extended |
| D5 | Paste still works and is discoverable; `ranks.import` stays ON | Existing Maestro import flow unchanged and green |
| D6 | Refresh is opt-in and produces **proposals/notifications, never silent mutations**. Server-scheduled refresh exists only for zero-credential sources; MFL refresh is **on-open/on-demand** (compatible with device-side custody if the device-auth programme moves MFL there) | Cron tick test; notification lands in existing inbox |
| D7 | **Use gate, not just storage gate:** no third-party credential is used for a purpose outside the flow that obtained it without an explicit in-flow re-consent naming the data read and the cadence, recorded as a per-purpose grant with independent revoke. No new credential storage for rankings: **WS-H reads the existing `mfl_credentials` row and stores nothing new** (if Q7 confirms a distinct APIKEY exists, this criterion is amended and the new storage priced explicitly) | Grant record schema + revoke test; `git grep` shows no new credential table |
| D8 | Every connector has a health check (shape assertion, row-count floor, canonical-player spot check) that on failure **self-disables the adapter in-process for the run and notifies the operator; the flag flip is manual** (the flag system is config+env compiled — `FLAG_KEYS` in `feature_flags.py` — with no runtime write path; a DB-backed kill switch is priced as an optional WS-B extension, not assumed) | Kill a fixture's shape → run skipped + notification fired; no claim of automatic flag mutation |
| D9 | Identity resolution: ≥95% match on top-200 **players** per shipped source, AND a **separate pick gate** — picks resolve to the 8-tier ladder or surface as unmatched, with a stated per-source pick-coverage finding (a pick-heavy MFL draft list could pass the player bar while unusable) | Asserted in tests + preview UI |
| D10 | Analytics `ranking_source_connected/refreshed/apply_failed/disconnected` + a refresh-notification opt-out event specced in the taxonomy **before build**; `rankings_import_applied` (fired at server.py:8215 but missing from `SERVER_FIRED_EVENTS`) registered in the same taxonomy PR. **That same PR must extend `record_event()` with a `platform` parameter** — the function currently never writes the `platform` column, so every server-fired event (including the cron-fired `refreshed`) lands NULL by construction and the gate would be unsatisfiable. **Derive `platform` from `device_info`/`source` when present, falling back to `'server'`** — a flat `'server'` default would stamp user-initiated client-triggered events routed through `record_event` (e.g. `rankings_import_applied`, which already passes `device_info`) as server events and corrupt later platform splits. Ramp assertion is per-event: `platform = 'server'` for genuinely server-fired, non-NULL client platform for client-fired | Taxonomy PR precedes build and includes the `record_event` change; live-table per-event check |

**Not express-eligible.** Touches schema, API contracts, flag surfaces, and analytics events — all four bright-line categories. Full gates (scope block → Maestro delta → docs table → sim run) apply per milestone.

## 2. Scope

### In
- **Provenance & ordinal merge foundation** (WS-A) incl. edit-capture retrofit, snapshot ring, and retrofit of paste onto the merge path.
- **Source registry & adapter contract** (`backend/ranking_sources/`): declarative `describe/fetch/normalize → existing matcher`; per-adapter flag + in-process health self-disable; `_api_obs` observability; adapters never touch the DB and have no write methods.
- **Adapters:** DynastyProcess (test-only reference), FantasyCalc (user-facing).
- **Assisted export:** file picker + URL paste alongside paste; CSV column auto-detection; remembered mapping (~3-tap re-import); in-app FantasyPros export walkthrough.
- **Authenticated connector (conditional): MFL `myDraftList`** (WS-H) — existing encrypted `mfl_credentials` cookie, header-only; gated on device-auth conformance, per-purpose consent, the encrypted-row precondition, and its discovery timebox.
- **Connection persistence + API surface** (WS-C) incl. a shared `_apply_board_order(...)` helper extracted from the paste path so paste and connectors cannot drift on side effects.
- **Opt-in refresh** (WS-F): `seed_once` (default) and `suggest` modes; `managed` auto-apply **deferred to v1.1**.
- **Mobile connect UI** (Chalkline), honest source grouping driven by `provides` (label component copy cannot override).
- **Legal/ToS memos**, the **KTC operator decision**, and **conformance to the device-auth credential decisions** (WS-G).

### Out (non-goals, stated so nobody re-adds them silently)
- Removing or hiding paste (`ranks.import` stays ON; any PR removing the entry point is rejected on sight).
- "Connect KeepTradeCut" / "Connect Dynasty Nerds" in any form without a signed license/partnership. No new scrapers, no new credential collection.
- Storing any user's third-party **password**; any new server-side credential custody (contradicts device-auth G1/G2); server-side replay of MFL session cookies on a schedule.
- `managed` auto-apply in v1. CAPTCHA/anti-bot circumvention, categorically.
- Web/extension connect UI (backend is client-agnostic; cheap follow-on).
- Writing FTF rankings back out to any platform (adapter contract has no write method).
- Multi-board ranking sets as a *feature* (but see Q4 — their **storage** may be reused).

### WS-A — Provenance & ordinal merge foundation *(BE + eng-architect)* — blocks all seeding/apply work
The board is an **ordinal permutation**, not per-player values: every write path funnels through `service.apply_reorder`, a pure permutation of the existing Elo multiset (deliberate — linear re-spreading caused the tier-occupancy bug), and `save_tier_overrides` persists a whole-pool `{player_id: elo}` map, so a single import touches every id. WS-A is specified against that reality:
- **A0 — edit capture across all six write paths** (rank3 swipes, tiers/save, tiers/copy-from-format, anchor/save, rankings/reorder, import-apply resolution): server-side pre/post-write diff inside each route (mechanism (a) — no client protocol change; old shipped builds and web stay safe), leaning on the exact signals that already exist (tiers/save `cleared_pids`/`demoted_pids`, rank3's `ranked` array). Fail-safe: uninstrumented path reaching `save_tier_overrides` ⇒ its ids marked `user_edited = true`. This precedes any schema choice.
- **A1 — provenance store:** per-player `{source, sourced_at, user_edited}`. **Q4 decides the shape among THREE options:** (i) widen the blob, (ii) new sibling table, (iii) **reuse `rank_sets` / `rank_set_entries` (`database.py:1582–1617`)** — an existing, unused, owner-scoped versioned per-player rank store `(rank_set_id, version, player_id, rank, elo)`. The written accept/reject for (iii) must answer its two known obstacles: the table carries **no `source`/`sourced_at`/`user_edited` columns**, and its owning model is **immutable-per-version** (publish bumps version; accuracy scoring locks onto snapshots) — at odds with a continuously mutated live board. Decided jointly with the rankings-marketplace plan, which owns the `ranks.*` flag namespace AND already has the live `ranks.rank_sets` flag gating this same substrate — otherwise two designs fight over one store. Migration additive + reversible, rehearsed on a prod DB copy (stated dataset + row-level comparison method; the rehearsal pulls real user data locally — handle per the secrets/privacy conventions). Backfill per D1: all pre-migration overrides `user_edited = true`.
- **A2 — snapshot ring:** generalize the one-shot `__pre_rookie_scope__` snapshot into an N-deep ring powering a user-facing one-tap undo — and backing the D2 all-or-nothing accept. **The WS-A LLD must decide storage location, not just depth/retention:** today's snapshot lives as a sibling key *inside the same `tier_overrides` blob* (database.py:3915–3925); an N-deep ring there multiplies the column per format and shares the single-write failure mode with the very blob it protects — same-blob vs sibling-table is a real decision.
- **A3 — ordinal merge engine:** `(current order, incoming order, pinned ids) → full permutation + conflicts`, where pinned (user-edited) players keep their absolute index, neighbours flow around them, conflict = incoming would move a pinned index by > N, and the output is always applied through `apply_reorder`. Assertions target order + tier-band occupancy, not exact Elo-multiset equality (tie-break drift). Must handle the all-pinned case per D2 (bulk resolution, not N per-row decisions), with an all-pinned fixture test proving a resolvable state. **Also a tiny-match test:** `apply_reorder` no-ops when fewer than 2 ids land in the pool — a near-empty connector result (e.g. a 1-player MFL draft list) must surface as "nothing to apply", never silently apply nothing while the UI reports success.
- **A4 — retrofit paste:** extract `_apply_board_order(...)` from `/api/rankings/import-apply` (server.py:8194–8249) carrying ALL its side effects — `save_tier_overrides`, `member_rankings` republish, taste-prior refresh, trends snapshot, analytics — and route paste through the merge engine. **Independently shippable value:** paste becomes non-destructive with zero UI change, even if the rest is cancelled.
**Done:** D1/D2 tests green incl. legacy fixture; migration rehearsal loses zero rows (else the initiative stops); `docs/data-dictionary.md` updated.
**Abort:** migration cannot be made additive+reversible on both engines → the whole initiative stops.

### WS-B — Adapter contract + registry + reference adapter *(BE)* — fetch/resolve half runs **parallel to WS-A**

Health checks per D8 (in-process self-disable + operator notification; optional DB-backed kill-switch table priced separately if the operator wants remote off). DynastyProcess ships as the reference adapter. Only the final done-bar ("DP adapter feeds the merge engine end-to-end") waits on A3 — everything else is DB-free pure functions.
**Done:** contract merged; tests cover happy/empty/unmatched/both formats/pick gate; health-red behavior per D8. No routes, no UI.

### WS-C — Persistence + API surface *(BE)*
Tables `ranking_connections` (`user_id, source_id, scoring_format, sync_mode ∈ {seed_once, suggest}, params_json, status ∈ {ok, needs_attention, needs_reauth}, last_fetch_at, last_apply_at, last_error`) and `ranking_connection_runs` (bounded, cron-pruned). No credential table.
Routes (all 404 while `ranks.connect` off; mutating routes behind `_gate_unverified_write`): `GET /api/rankings/sources`, `POST /api/rankings/connections` (validates by one live fetch), `GET .../preview` (resolved order + unmatched + match_rate + diff, no apply), `POST .../apply` (through `_apply_board_order`), `POST .../refresh` (rate-limited), `DELETE`.
Explicit decisions carried in this workstream:
- **Leaguemate blast radius:** the paste path republishes `member_rankings`, which changes other leaguemates' trade math. Decision (operator-confirmable, default **no**): consensus-source applies do NOT republish; user-authored applies do (they represent the user's actual opinion). Enumerated in Done + risk R13.
- **Row cap:** `_IMPORT_MAX_ROWS = 500` **hard-rejects with 400 `too_many_rows`** (server.py:8139 and 8182) — a full dynasty list over 500 rows is refused outright, not truncated; set an explicit connector cap with a boundary test.
- **Reset AND disconnect handling:** `reset_user_rankings` NULLs the board but would leave `ranking_connections` intact — reset also clears/flags connections so no "connected, last-synced" card points at a wiped board. Likewise **MFL disconnect**: `DELETE /api/mfl/auth-link` removes both the encrypted row and the session copy (server.py:21470–21478), leaving a `ranking_connections` row pointing at a credential that no longer exists — WS-F's `needs_reauth` path absorbs it, but disconnect is named here so no "connected" card survives with no credential behind it.
- Flags: `ranks.connect` + `ranks.source.*` are **code** changes (`FLAG_KEYS` in `backend/feature_flags.py`) plus `config/features.json` entries, added once as a single block; the `ranks.*` namespace is owned by the rankings-marketplace plan — coordinate the naming there (Q4's joint session).
**Done:** account-deletion + reset tests; no plaintext credential in any log/event/error (asserted by test, incl. the Sentry scrub the device-auth PRD lists as ungated do-now); `docs/api-reference.md` + `LLD.md` updated; route tests cover flag-off 404 / 401 / bad credential / zero-match / rate-limit / row-cap boundary.

### WS-F — Refresh scheduler + drift handling *(BE)*
Daily-tick pass (CRON_SECRET-guarded): for each `suggest` connection on a **zero-credential source** past `refresh_min_interval`, fetch → resolve → ordinal diff vs pinned board → notification ("N players moved on your FantasyCalc board — review"); applies nothing. `seed_once` never auto-refreshes. **MFL connections are never server-scheduled** (device-auth conformance): their `suggest` runs on-open/on-demand from the client. Trivial-delta suppression; weekly ceiling; quiet-hours bundling via `deliver_after`. Three consecutive failures → `needs_attention`, notify once; auth failures → `needs_reauth` immediately (never counted toward the three-failure backoff), surfacing re-auth in the connected card. **v1 ships a single global weekly pass** (per-user cadence is net-new machinery, deferred).
**Done:** each mode + the needs_reauth path proven by test; failure backoff + single-notification tested; `docs/runbook.md` entry; opt-out event live (>30% opt-out on the type → on-demand only).

### WS-G — Credential conformance *(SEC + eng-architect, OP sign-off)* — gate, not a build
Not a fresh ADR: a **conformance review against the merged device-auth decisions** (PRD 2026-08-12 + HLD decisions 2026-08-13: G1 no server-side JWT at rest, G2 MFL password must stop transiting FTF, D5 MFL login as a device-built call; MFL client registration is the precondition the MFL carve-out is contingent on). Outputs:
1. WS-H's transport decision — **including the required reconciliation of `docs/integrations/mfl.md` §2 ("there is no separate MFL API key — the credential *is* the session cookie"; APIKEY-style auth is export-restricted but plausibly the same secret in a query string) against the device-auth PRD's APIKEY framing. `docs/` wins per CLAUDE.md; whichever loses gets edited.** Until Q7 proves a distinct credential exists, WS-H's transport is the existing encrypted `mfl_credentials` cookie, `Cookie:` header only (never query string), and no "read-only by construction" claim is made — the same secret replayed as a Cookie can write trades, so R3's mitigation rests on the D7 use-gate, the no-server-scheduling rule, and no-new-storage. Also: what happens if custody moves fully device-side — server-scheduled MFL refresh is impossible and WS-H's refresh is on-open only, already assumed in WS-F.
2. **Consent posture:** the existing MFL in-app copy is documented-inaccurate (PRD §2: the password transits FTF "while the in-app copy tells them it doesn't"). Repairing that copy is an **unconditional pre-req to WS-H** — no second consumer ships on top of a credential whose consent story is wrong.
3. The per-purpose grant model backing D7 (grant record: purpose, data read, cadence, revoke).
4. Posture note for the ADR record: MFL's key-less path stores the cookie session-only (fail-closed for the DB — plaintext never persists — but unreachable by cron); ESPN 503s instead; whether to align is recorded as a decision, **not** treated as a bug fix, because the MFL login route is also the MFL-only user's verification path.
**Done:** conformance doc merged with operator sign-off; MFL disclosure copy fixed; grant schema agreed.

### WS-H — MFL `myDraftList` connector *(INT + MOB)* — conditional
Preconditions: WS-G done (incl. disclosure fix and the mfl.md/PRD transport reconciliation), and **connection creation requires an encrypted per-user `mfl_credentials` row** — not merely a global `token_encryption_available()` check, and not the session-only fallback: since WS-F already bars server scheduling for MFL, the session cookie technically suffices for on-open calls, but a connection whose credential dies with the session produces `needs_reauth` churn on every launch; refusing creation with specced copy beats that. The copy must also cover the confusing adjacent state: `GET /api/mfl/auth-link` reports `connected: true` on a key-less deployment via the session-only cookie, so "signed in to MFL, rankings connection unavailable on this deployment" needs explicit wording or it reads as a bug to support.
Transport: the existing encrypted `mfl_credentials` cookie, `Cookie:` header only (per WS-G). Read-only is enforced by contract + review — no `ranking_sources/` code path may import or call `mfl_write` — not claimed "by construction" of the credential.
