Mapped 2026-07-26 on branch `teardown-remediation` (HEAD 786f63d). All paths relative to repo root `/Users/teresadickens/Documents/Claude/Projects/Fantasy Trade Finder`. READ-ONLY survey; no code changed.

## Summary

Find-a-Trade is a **pull-based, per-request generation engine**, not a feed: each "Find a Trade" tap runs a league-wide sweep (v2 value math + v3 exact per-pair optimizer) that scores mutual-gain candidates against two personal Elo boards, then applies a stack of bounded post-gate multipliers (need-fit, block-boost, outlook direction, aggression A/B) and a light presentation layer (Thompson sampling over *package shape only*, league-wide diversity caps, likes-you pinning). Interaction capture is swipe-level (like/pass) plus generation-time "impressions"; the only closed learning loops are (a) per-player Elo nudges at K=8/4/20/20 and (b) the shape-bucket Beta posterior. There is **no learned acceptance model, no dwell signal, no view-level impression, no per-partner/per-attribute personalization, and no offline eval harness** — the training-data tables exist but nothing consumes them for ranking beyond a saturation penalty. Cold start is handled by DynastyProcess+KTC consensus seeding, confidence shrinkage, consensus-basis cards, and a provenance chip. The operator's newest direction (#156 Trade Finder Hub, flag ON 2026-07-25) is *intent-splitting the entry point* (guided/team/player/calculator), not ranking-loop learning.

## 1. Candidate generation

**Entry**: `POST /api/trades/generate` (backend/server.py:5610) spawns a daemon-thread job `_run_trade_job` (server.py:2178) → `TradeService.generate_trades` (backend/trade_service.py:1747). With `trade_engine.v2` on (config/features.json:27) the v2 path runs (trade_service.py:1807-1844); with `trade_engine.v3` on (features.json:34) each *ranked* opponent pair is routed to the exact optimizer (trade_service.py:2180-2211 → backend/trade_optimizer.py:185).

**Core algorithm (v2 single value space)**:
- Personal Elo → value via `elo_to_value` exponential (trade_service.py:449-464; k=0.0050, ref=1500, base=1000 — trade_service.py:118-120).
- Confidence shrinkage toward consensus seed, w = n/(n+4) (`_shrink_user_elo`, trade_service.py:544-564; `shrink_pseudocount` trade_service.py:150).
- **Marginal value over replacement** (flag `trade.marginal_value`, features.json:28): `replacement_levels` + `marginal_value` with position/format-aware bench credit (trade_service.py:858-954); surplus gate switches to `min_side_surplus_marginal`=60 (trade_service.py:170-174, 2457-2459).
- **Two-sided surplus gate**: both `user_surplus` and `opp_surplus` must clear MIN_SIDE (trade_service.py:2666-2670); package values per side via KTC-style `package_value_v2` with gamma=1.5 depth discount + crown-asset consolidation premium (flag `trade.crown_asset`, features.json:41; trade_service.py:480-534); waiver-slot cost on the side receiving more players (trade_service.py:2660-2664).
- **Harmonic-mean ranking**: composite = 0.70·min(hm,1500)/1500 + 0.30·fairness, × tier multiplier (trade_service.py:2676-2679; `_harmonic_mean` trade_service.py:537-541).
- **Fairness** = consensus package ratio with confidence range-overlap escape; for divergence cards the threshold is loosened to `fairness_floor_divergence`=0.55 (trade_service.py:2472-2473, 2557-2584, 132).
- Safety gates never relaxed: #108 user-raw-board 1-for-1 gate (`user_gain_ok_1for1` trade_service.py:579-603), #141 junk-filler gate w/ absolute floor 450 (`filler_ok` trade_service.py:606-639), untouchables dropped at pool source (trade_service.py:2698-2700).
- **Outlook now↔future blend** (`trade.outlook_blend`) is **OFF** (features.json:29) — per 2026-07-17 interview "age = tiebreak", labels stay, value edits don't (trade_service.py:2144-2152). The α-blend machinery exists (trade_service.py:958-1032) but is dormant.

**v3 exact optimizer** (backend/trade_optimizer.py:185-590): per-pair pools = top `v3_pool_size`=12 players/side by valuation divergence (trade_optimizer.py:255, 349-355; default trade_service.py:245); **exhaustive** enumeration of give-subsets (1-3) × receive-subsets (1-3) with |give|−|receive| ≤ 1, no time budget (trade_optimizer.py:441-460); lineup-feasibility hard constraint both rosters (trade_optimizer.py:151-167, 481); greedy diversity — Jaccard asset overlap between picked cards ≤ 0.4 (trade_optimizer.py:542-553); **sweetener pass** rescues ≤2 near-miss combos in a 0.15 fairness band by adding the cheapest consensus player from the under-paying roster (trade_optimizer.py:557-647). **Three-team cycles** (`find_three_team_cycles`, trade_optimizer.py:655-795, kidney-exchange style) are built but dark — `trade.three_team` false (features.json:35).

**Consensus fallback** for unranked opponents (`_generate_consensus_for_pair`, trade_service.py:2817-2993): 1-for-1 then 2-for-1 only, scored fairness × tier × `consensus_score_scale`=0.3 so they rank below divergence finds (trade_service.py:2953-2958); user must come out ahead on consensus (trade_service.py:2924-2927) and give-side consolidations respect a 15% raw-loss cap (trade_service.py:2930-2939).

**Post-gate composite multipliers** (all bounded reorders applied in the orchestration loop, trade_service.py:2259-2382): partner_fit (FB-47, `trade.finder_targeting` features.json:36; trade_service.py:2263-2270), need_fit ±7.5% (FB-96, `trade.need_fit` features.json:37; trade_service.py:2277-2287), trade-block boost +15% (FB-147, `trade.block_boost` features.json:47; trade_service.py:2296-2303), directional outlook (#175, `trade.outlook_direction` features.json:50; `outlook_direction_mult` trade_service.py:1111-1190 — rebuild-side penalty 3.0×shift, boost 1.0×shift, ~1-year age-gap near-exclusion ×0.15), lane labels (`trade.lanes` features.json:42; trade_service.py:2330-2334), aggression A/B (`trade.aggression_ab` features.json:44; trade_service.py:2341-2382 — experiment-engine override else MD5 bucket light/fair/generous, trade_service.py:1193-1199).

**Targeting inputs**: pinned give/receive players, `pinned_give_mode:'all'` package constraint (#174, server.py:5648-5655), `opponent_user_id` scoping (#156, server.py:5656-5660, trade_service.py:2117-2119), positional acquire/trade-away **hard filters** (trade_service.py:2543-2555), preference lists — untouchables/targets/not-interested (`trade.preference_lists` features.json:39; server.py:2298-2312). **#189 relaxed fallback**: empty targeted results rerun with staged gate relaxation, cards stamped `relaxed`+`relaxed_reason` (trade_service.py:1836-1844, 1943-1992). Owned draft picks injected as priced PICK pseudo-assets (`trade.picks_in_pool` features.json:49; server.py:2328-2347, `_inject_owned_picks` server.py:5330).

**Pool size/shape per generate call**: default `max_per_opponent`=5 (trade_service.py:1754); per-pair top-K heap K=max_cards×4=20 (trade_service.py:2588); global target = max(30, 5×6)=30 cards then early exit (trade_service.py:2142, 2395-2396); default fairness_threshold 0.75 (0.50 when pinned/opponent-scoped — server.py:5661-5664); + up to 3 likes-you injections. So a served deck is ~5-33 cards, ranked opponents visited first (trade_service.py:2131-2140).

## 2. Ordering / presentation policy

`_order_deck` (server.py:2073-2138), run after likes-you injection and before impression logging (server.py:2406-2434):
- **Thompson deck** (`trade.thompson_deck` features.json:32): arms are **package shapes only** — f"{len(give)}x{len(receive)}" ("1x1","2x1",…) because shape is the only feature derivable from both live cards and `trade_decisions` rows (design comment server.py:1975-1989). Posterior: Beta(1+likes, 2+passes) per shape from `load_trade_decision_shape_counts` (server.py:2095-2106; backend/database.py:3524-3573); one draw/shape/job, deterministic per-job seed (server.py:2020-2025); sort-key multiplier bounded to (0.5, 1.5) so exploration reorders across buckets but never inverts quality (server.py:2107-2110).
- **Deck diversity** (`trade.deck_diversity` features.json:33): league-wide — if a card's top receive asset appeared in ≥ `diversity_user_cap`=3 *other* members' decks in the last 7 days, key ×= 0.6 (server.py:2112-2127; `load_recent_impression_target_user_counts` database.py:3576-3613); intra-deck — max `deck_max_per_target`=3 cards per top receive asset, never dropping likes-you cards or shrinking below 5 (server.py:2044-2070, `_DECK_MIN_CARDS` server.py:1998; config trade_service.py:238-241).
- **Likes-you injection** (`trade.likes_you` features.json:30; `_inject_likes_you_cards` server.py:1849-1972): league-mates' 'like' decisions from the last 90 days whose mirror is still actionable are mirrored into the user's perspective; cap 3 (server.py:1846); existing card gets `likes_you=True` + composite boosted to deck-max+1.0, else a consensus-basis card is synthesized (server.py:1932-1968); skipped for pinned/opponent-scoped jobs (server.py:2378-2380). Likes-you cards stay pinned to the top through ordering (server.py:2129-2133) and through the client's own re-sort (mobile/src/screens/TradesScreen.tsx:1316-1331).
- **Client-side**: when the user's "trade fairness" toggle is off the deck is re-sorted by raw mismatch score (TradesScreen.tsx:1311-1331); phase-2 lane filter pills (Window/Value) filter the deck client-side (TradesScreen.tsx:299-302, 1323-1324, 2348-2364).

## 3. Interaction capture

**Swipe pipeline**: mobile deck gesture/tap → `POST /api/trades/swipe` (server.py:5807-5851). On each decision:
- `trade_decisions` row: user, league, trade_id, give/receive JSON, decision, created_at (database.py:271-280; `save_trade_decision` database.py:3375). **Not** logged: deck position, job_id, dwell, basis, likes_you, lane, scores.
- Elo write-through: `save_trade_swipes` persists pairwise winner/loser rows with k_factor (server.py:5877-5883; database.py:3303) and `record_trade_signal` applies them in-session (ranking_service.py:305-336).
- `record_event('trade_proposed'|'match_swiped')` into `user_events` with props decision, trade_id, give, receive, target, **aggression_variant, lane, fit_premium** (server.py:5886-5904) — the analytics join for phase-2 attributes.
- Like → mutual-match check (exact or fuzzy Jaccard τ=0.8 behind `trade.fuzzy_match`, features.json:31; server.py:5909-5920), match row + notifications + typed push (server.py:5929-6028).
- Restart-proof reconstruction from client-echoed card context (FB-46, server.py:5773-5804) — reconstructed cards have zeroed scores (server.py:5799-5801), so their decisions can't be joined back to generation metadata.

**Impressions**: `trade_impressions` — one row per card **per completed generation job**, in final deck order, with basis, likes_you, mismatch/fairness/composite, `position_in_deck`, shown_at (database.py:374-394; `log_trade_impressions` database.py:3480-3521; call site server.py:2436-2444). Crucially this is a *generation-time* record: rows are written whether or not the user ever scrolls to that card. The client-side counterpart `trade_card_viewed` (fires once per card reaching the top of the deck, props card_index/trade_id, first card gets ms_since_open + cold_start — TradesScreen.tsx:1398-1417) lives only in `user_events` and shares **no key** with `trade_impressions`.

**Other captured signals**: `deck_exhausted_viewed` w/ deck_size (TradesScreen.tsx:1683-1699), `swipe_undone` (TradesScreen.tsx:1033), bad-trade flag — distinct from pass, operator review queue (`POST /api/trades/flag` server.py:6065; `trade_flagged` TradesScreen.tsx:2012), #186 `trade_keep_side_tapped` (TradesScreen.tsx:1223), #190 `trade_edit_in_calculator_tapped` (TradesScreen.tsx:1233), `find_trades_tapped` (TradesScreen.tsx:2609), `deck_regenerated` (TradesScreen.tsx:1652), untouchable_toggled (TradesScreen.tsx:569). Edited cards (#86/#190): the edit overlays the top card and the swipe carries the **modified** package into every payload (TradesScreen.tsx:1348-1354), re-priced via the evaluate API (TradesScreen.tsx:1280-1295).

**Swipe-undo & signal cleanliness** (`ux.swipe_undo` features.json:98, ON): a *pass* swipe's POST is **delayed 5s** (`UNDO_HOLD_MS` TradesScreen.tsx:127-129) rather than reversed — there is no unswipe endpoint, so holding the write is the only way an undone pass stays out of the Elo/decision stream entirely (design note TradesScreen.tsx:987-1001). Undo rewinds the deck index and drops the pending write (TradesScreen.tsx:1023-1034); any newer disposition, deck reset, league switch, or unmount flushes the pending pass first (TradesScreen.tsx:1011-1043). Likes commit immediately (no undo). Net effect: pass signal is *cleaner* (accidental swipes recoverable) but the server never learns a pass was hesitated-then-undone — only the client event records it.

## 4. Model feedback loop

**K-factors** (backend/ranking_service.py:55-60, config-tunable via model_config): rank trio decisions `elo_k`=32; trade like `trade_k_like`=8; trade pass `trade_k_pass`=4; match accept `trade_k_accept`=20; decline correction `trade_k_decline_correction`=20 (net ≈ −12 after the like's +8 — ranking_service.py:347-350). Disposition route: `POST /api/trades/matches/<id>/disposition` (server.py:6816; K semantics documented server.py:6821-6828).

**Attribution**: strictly **pairwise player-level**. `record_trade_signal` pairs *every* winner against *every* loser at the flat K (ranking_service.py:322-335) — a 2-for-1 like emits 2 pairwise updates (each given player "loses" to the one received player) with no value weighting, no headliner/filler distinction, no side-package concept. Same decomposition for dispositions (ranking_service.py:338-365). Swipes are replayed from DB into the in-memory engine at session init (`replay_from_db` ranking_service.py:722-770).

**Hard preference filters** (not learned): untouchables/targets/not-interested from `asset_prefs` (server.py:2298-2312 → engine pool filters trade_service.py:2698-2706); acquire/trade-away positions from `league_preferences` as hard filters (server.py:2242-2253, trade_service.py:2543-2555); outlook declared or seeded (server.py:2255-2262).

**Trade-attribute-level learning**: the **only** one is the Thompson shape posterior — like/pass counts per package shape (database.py:3524-3573) feeding deck ordering. Nothing learns "this user likes consolidation trades", "prefers young WRs", "likes trading with manager X", or lane preference. The aggression bucket is a **static MD5 hash** of user_id (trade_service.py:1193-1199), optionally overridden by a (not-yet-launched) `trade.aggression` experiment (trade_service.py:2346-2364) — it is not updated by observed acceptance. The impressions table is explicitly labeled "training-data pipeline for the future acceptance model" (server.py:2436-2439; database.py:374-377) — that model does not exist.

## Honest gaps (what the loop does NOT do today)

1. **No learned acceptance model.** The impressions/decisions tables were built as its training data (database.py:374-377; server.py:2436-2439) but no model trains or scores on them. Ranking quality is entirely hand-tuned config (≈90 model_config knobs in trade_service.py:40-314).
2. **Personalization from swipes is thin.** Dispositions only move per-player Elo (flat pairwise K) and a 5-bucket shape posterior. Nothing learns partner affinity, value-band appetite, consolidation vs. splitting taste, lane/window taste, or pick appetite from behavior — those are all declared (prefs, outlook) or hashed (aggression).
3. **Impression ≠ view.** Every generated card is logged as "shown"; actual exposure lives in a disjoint client event stream with no join key. Position-in-deck CTR, depth-reached, and skip-vs-never-saw cannot be computed cleanly.
4. **No dwell, no hesitation, no partial-engagement signals.** Card expansion (#186 keep-side taps, calculator edits) is tracked as events but feeds nothing. Undone passes vanish server-side.
5. **Exploration isn't measured.** Thompson draws/propensities aren't logged; no offline replay or A/B on ordering exists; the experiments engine is live but unused for the deck.
6. **Pull-only cadence.** No background/daily deck build, no freshness push, 30-min cache; deck memory (`past_decision_keys`) prevents resurfacing but nothing schedules re-engagement.
7. **Presentment is single-lane linear.** One deck sorted by one composite; lanes are a client filter, not separate ranked feeds; likes-you pinning and diversity caps are the only non-score ordering forces.
8. **Cross-user signal use is minimal.** Likes-you mirroring and the 7-day league saturation penalty are the only collaborative signals; no "users like you liked" generalization, and consensus values come from external sources (DP/KTC), not from FTF's own swipe corpus.
