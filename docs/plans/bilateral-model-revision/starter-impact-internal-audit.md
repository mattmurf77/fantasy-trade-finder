# Starter impact: internal architecture and evidence audit

2026-09-22. Research lane 3 under the [parent specification](spec-starter-impact-research.md). Static source inspection only; no application imports, tests, generation, provider requests or production access. Latest inspected worktree HEAD: `29acac6432df6e2892d0e181a7ee08b3648c7280`. Source locations below describe code, not deployed configuration. This document changes no model, schema, flag or runtime. Provider verification belongs to the [Sleeper research](starter-impact-sleeper-research.md) and [alternative-source research](starter-impact-alternative-sources.md).

## Conclusion

Reuse the existing **weekly forecast import, legal point-lineup solver and immutable Win Now evidence storage**, initially for a separate bilateral starter-impact shadow. Do not relabel the current dynasty lineup proxy as points, feed full-season totals into one static lineup, or inherit Win Now's experimental season probabilities as calibrated truth.

The main prerequisites are a verified forecast/scoring contract, complete potentially relevant bench coverage, explicit availability and roster-move assumptions, and a frozen offer-time snapshot for both managers. The code already supplies useful components, but does not establish these prerequisites for the current bilateral model.

## 1. What exists now

### Bilateral generation deliberately reports Unknown

The owner engine builds available-player assets from **dynasty market value multiplied by an age factor**, then reoptimizes a value-based lineup and adds a 15% best-backup proxy by position. Neither the starting value nor that bench increment is projected fantasy production. [Asset construction](../../../backend/trade_gen_owner.py#L140), [lineup proxy](../../../backend/trade_gen_owner.py#L243).

The bilateral revision explicitly emits `starter_evidence.state="unknown"` and `projected_starter_delta=None`, identifying missing fresh scoring-compatible projections, horizon, availability and cut evidence. Preserve that truthful boundary until new evidence is qualified. [Current contract](../../../backend/trade_gen_bilateral_candidate.py#L80).

The server captures personal boards/preferences, roster IDs, cached starter slots and capacity; it does not attach player-week projections or raw scoring rules. This adapter also does not itself populate per-manager reserve/taxi `inactive_ids` from raw rosters, so the engine's ability to consume inactive IDs is not proof they are observed on this path. [Owner context](../../../backend/server.py#L14752), [slot/capacity capture](../../../backend/server.py#L14783), [generator inputs](../../../backend/server.py#L14824).

### Reusable roster legality, but a different point objective

`trade_roster` supports unique-player assignment across overlapping FLEX/SF slots, before/after roster checks, inactive holdings, capacity and explicit cuts. It checks constrained-group backup coverage, not just dedicated-position counts. Its assignment objective prioritizes occupancy and uses nonnegative dynasty values; use the **season point solver** for expected fantasy points, including negative-score cases. [Structural assignment](../../../backend/trade_roster.py#L51), [cuts and coverage](../../../backend/trade_roster.py#L144).

The roster adapter distinguishes observed Sleeper roster/slot/reserve/taxi facts from estimated templates for other platforms. The server's separate roster check fetches raw rosters and checks player metadata freshness; it still supplies outlook rather than real projections. A timestamp attached to constructing this context is not automatically the provider's observation timestamp. [Adapter](../../../backend/trade_roster_adapter.py#L7), [server integration](../../../backend/server.py#L5731).

`trade_outlook_utility` already has a whole-roster production component with explicit projection basis, units, freshness and full eligible-pool coverage. However, its input is one scalar per player, not a player-week schedule; one optimal lineup over period totals cannot reproduce weekly substitutions. Its current weights/confidence are not empirical acceptance probabilities. Extend the evidence contract explicitly rather than disguising a new weekly model as the old scalar input. [Projection gate and calculation](../../../backend/trade_outlook_utility.py#L140).

### Separate Win Now path already has weekly and season machinery

- **Forecasts:** provider-neutral immutable player/week raw-stat snapshots, season/horizon validation, certified bye rows, source/capture metadata and hashes. The importer explicitly requires conditional-on-playing stats and a week-specific availability probability or Unknown. [Import contract](../../../backend/season_forecasts.py#L110).
- **Scoring:** exact supported linear event coefficients and position-specific reception premiums; unsupported nonzero scoring rules fail. Superflex is a legal-slot constraint, not a QB stat multiplier. [Scoring](../../../backend/season_forecasts.py#L302).
- **League:** Sleeper scoring, lineup slots, observed rosters, reserve/taxi, remaining matchup schedule, settled standings, playoff rules, capacity and review delay. Current support deliberately excludes several formats/live states. [League adapter](../../../backend/win_now_service.py#L113), [rosters and schedule](../../../backend/win_now_service.py#L162).
- **Weekly points:** a maximum-weight legal assignment with one player per slot, FLEX/SF overlap and zero-point empty alternatives. It recomputes both exchanged rosters. [Point solver](../../../backend/season_simulator.py#L124), [weekly evaluator](../../../backend/season_simulator.py#L181).
- **Season impact:** paired full-league before/after simulation with stable player-week worlds and explicit buyer/partner output; it retains existing standings and uses actual fantasy matchups. `lineup_gain` is a **mean remaining-regular-week delta**, not a season total; near-three-week and playoff means are separate. [Trade evaluation](../../../backend/season_simulator.py#L381).
- **Retention:** immutable forecast/projection records, distinct refreshed scenario IDs, and separate Win Now like/pass decisions. These are useful storage precedents, not already connected bilateral learning outcomes. [Immutable writes](../../../backend/win_now_store.py#L27), [scenario identity](../../../backend/win_now_store.py#L158), [decisions](../../../backend/win_now_store.py#L199).

## 2. Gaps that prevent direct reuse as known bilateral impact

1. **Forecast conditionality is asserted by the importer, not proven by the feed adapter.** The Sleeper adapter turns no current injury label into availability `1.0`, and any injury label into Unknown for future weeks. It does not obtain a verified future-week participation probability. Require a source contract distinguishing conditional-on-playing stats from already risk-adjusted means; never apply an invented second availability discount. [Current conversion](../../../backend/season_forecasts.py#L273).
2. **Supported scoring keys do not prove each row contains every needed event.** `score_stat_vector` treats an absent stat key as zero. Accept that only where the provider contract says omission means zero; otherwise retain a missing-category state. Linear TEP is supported by events/primary position; threshold bonuses require expected bonus events or a distribution, not a bonus applied to mean yards. Unsupported IDP/K/DST cannot silently become zero. [Exact lookup](../../../backend/season_forecasts.py#L302).
3. **Existing bench warning is insufficient for a fully known optimal lineup claim.** Missing recorded starters fail; unknown-availability bench players with known stats get an optimistic-contributor check. Entirely unprojected bench players can be excluded with a warning if known players fill the lineup. Without a valid bound, that does not prove the omitted player could not start after this trade or replace a bye. The bilateral evaluator should require all potentially eligible rows, or return a qualified bound/Unknown—not silently narrow its candidate pool. [Coverage branches](../../../backend/season_simulator.py#L195).
4. **Reserve/taxi and availability are not future roster decisions.** Win Now excludes reserve/taxi IDs for the whole modeled horizon and treats them as locked assets in its search context. It does not model a returning player's legal activation, corresponding cut, or taxi eligibility change. Its simulator selects a lineup from expected forecasts, then samples availability without choosing a replacement when pre-lock absence becomes known. That is a fixed-lineup decision policy, not a complete manager-substitution model. [Inactive exclusion](../../../backend/win_now_service.py#L169), [search context](../../../backend/win_now_service.py#L315), [sampled fixed lineups](../../../backend/season_simulator.py#L272).
5. **Trade application alone does not resolve cuts.** The season evaluator exchanges owned players; structural legality handles explicit cuts separately. Win Now rejects unresolved mandatory drops. New point impact must use the same admitted, capacity-legal post-trade roster on both sides, including the actual cut plan. Do not count an extra bench asset for free. [Trade application](../../../backend/season_simulator.py#L102), [Win Now legality](../../../backend/win_now_optimizer.py#L152), [explicit cuts](../../../backend/trade_roster.py#L144).
6. **Freshness and scoring approximations are separate claims.** Serving applies a 15-minute forecast age limit plus conservative game-start cutoffs, whereas the generic freshness helper defaults to 24 hours. Date-only midnight UTC is a conservative cutoff, not a known kickoff time. Win Now explicitly removes four unsupported rare-event scoring categories while retaining raw/effective rules and warnings. Do not label this beta approximation exact league scoring in a new bilateral proof. [Serving admission/exclusions](../../../backend/win_now_service.py#L239), [generic freshness](../../../backend/season_forecasts.py#L329).
7. **Season probabilities remain experimental.** Independent normal residuals and heuristic scales do not model all game/team/injury correlations; paired Monte Carlo intervals measure simulation sampling error, not forecast/model uncertainty. The weekly point screen itself currently calls full-season/bracket validation; a narrow weekly evaluator should not unnecessarily inherit every probability-model restriction. [Validation](../../../backend/season_simulator.py#L42), [residual/world assumptions](../../../backend/season_simulator.py#L272), [interval labels](../../../backend/season_simulator.py#L414).

## 3. Proposed weekly-to-ROS calculation

This is a design, not implemented behavior.

Capture one owned league/forecast context containing exact manager/roster identities, eligibility and slots, raw/effective scoring, active/bench/reserve/taxi status, legal roster capacity/cuts, horizon and game locks, and provider identity/crosswalk/version. Preserve source observation/publication time separately from fetch/capture/expiry. Validate both managers' full relevant before/after pools, not just the exchanged players.

For each included fantasy week and manager:

1. Apply the exact trade and explicit legal cuts/activations to form the after roster. The baseline is the same manager's before roster under the same information and decision policy.
2. Score compatible raw expected events using that league's rules. If forecasts are conditional on playing, apply a justified availability probability **once**. If already unconditional, do not discount again. Certified bye/out for that week is zero; missing, stale, ambiguous ID and unknown availability remain different states.
3. Optimize the entire eligible lineup before and after, allowing bench replacements and overlapping FLEX/SF assignments without reusing a player. A zero-point bye player does not make the team's slot zero if a legal positive replacement exists. Record actual unavailable/empty-slot evidence separately; a zero-value assignment tie is not proof an available starter exists.
4. If a pre-lock availability scenario is modeled, choose replacements using information available at that decision time. Do not optimize on subsequently realized scores; do not allow a midgame injury replacement that league rules forbid. Keep this scenario policy and any independence assumptions versioned.
5. Retain weekly before/after totals, substitutions, delta, coverage and uncertainties for **both** managers. A whole-roster delta is not the sum of the offered players' point differences.

For a fixed included-week set `W`, ROS starter-point gain is `sum(after[w] - before[w] for w in W)`; mean weekly gain divides that sum by `len(W)`, identically on both sides. Weekly forecasts already carry bye availability: do not subtract byes again, divide season totals blindly by 17, or use separate player games-played denominators for team impact. Missing weeks do not disappear from the denominator. Completed actual points are unchanged history, not trade-created benefit. Full-season actual-plus-future totals and ROS-only forecasts must have different explicit types.

A season/ROS total alone cannot identify weekly starter displacement or concurrent byes. Rank-only or season-total-only data can be a labelled prior, but cannot fill a known numeric weekly starter-impact field. Playoff-week lineup strength is conditional opportunity; title probability additionally requires a qualified full-league schedule/standings/bracket model.

Keep a horizon vector—next week, near three weeks, remaining regular season, fantasy playoffs—before selecting an outlook policy. Declared contender/championship/rebuilder intentions may weight horizons differently, but weights must be specified before evaluation, not fitted to make retained examples pass. Dynasty capital and picks remain separate future-value components. A rebuilding manager need not gain immediate points to benefit; Unknown near-term impact is not zero, and structural lineup legality remains distinct from preference tradeoffs. Missing personal boards do not become observed preferences because forecast coverage improves.

## 4. Offer-time evidence and bounded implementation seams

Add a versioned frozen forecast-context reference **before** candidate construction/evaluation. Fetch/refresh outside per-offer loops; score the player-week grid and baseline lineups once per captured context. Keep request-local caches exact to ordered slots/eligibility, roster/cuts, scoring, horizon, forecast and decision-policy versions; reuse must not change output inventories or introduce search/offer caps.

Existing detached owner input capture and private per-offer request/proof persistence are useful integration seams. The new age channel is explicitly collection-only and projects offered rows; it is not forecast evidence. Weekly substitution needs a shared full relevant roster/week snapshot, with each offer storing a compact exact reference plus both managers' lineups/deltas and Unknown reasons. Avoid duplicating the full grid on thousands of cards. Existing immutable Win Now snapshots and shared deck diagnostic storage provide precedents. [Detached input evidence](../../../backend/trade_input_evidence.py#L154), [per-offer snapshot](../../../backend/server.py#L14894), [deck persistence](../../../backend/database.py#L6557).

A content hash proves identity, not freshness or authority. Admission, final publication and later new interest must check snapshot expiry, roster/slot/scoring revision and game-lock policy. Existing in-process personal-input epochs do not automatically cover provider projections, schedule updates or out-of-process roster changes. Preserve the original snapshot on a past like; create a separate current evaluation when interest becomes mutual, rather than rewriting historical belief. Publication should retain the existing durable-evidence-before-visible-prefix property and fail closed if required proof writes fail. [Publication boundary](../../../backend/server.py#L8680), [three-stage match attribution](../../../backend/server.py#L5662).

## 5. Evaluation and production-learning requirements

Before any new scoring/enforcement rollout, freeze source/semantics, coverage requirements and margins. Start with shadow weekly evidence, then evaluate separately before adding season odds or a ranking weight. Required falsification cases include both-manager reversal; no-op/zero delta; positive bye replacement; simultaneous byes; FLEX/SF competition and duplicate IDs; negative points; missing potentially starting bench; conditionality/double-discount errors; partial stat categories; IR return/activation and both-side cuts; unsupported scoring; current-week locks; mixed horizons; stale/mutated inputs; and failed durable writes. These are proposed checks, not tests run in this audit.

Evaluate full candidate and final inventories with per-stage attribution, known/Unknown counts and denominators by format, outlook, injury/bye and board coverage. Preserve no-result/error requests and the independent grader; no aggregate support-score improvement establishes acceptance. Measure source-bound first durable/full latency and peak memory on the actual serving path before enforcement. Do not trade an undocumented offer budget for speed. Use future held-out outcomes and genuinely archived pre-cutoff forecast vintages for forecast/calibration claims; revised historical feeds cannot recreate past knowledge. The existing strict season calibration validator supplies useful no-lookahead/cohort checks. [Calibration contract](../../../backend/season_calibration.py#L84).

For learning from the owner-authorized current deployment, keep these outcomes separate:

- **Generated / eligible / durably served / genuinely viewed:** a served impression is not a view. The selected-offer client checks exact package identity, measured viewport visibility, foreground/focus and a 500 ms clock; these are client-reported qualification facts, not server proof of attention. Legacy front-of-deck timing follows a different path. Record client build/surface/qualification and verify every treatment surface before pooling them. Missing view telemetry is not a rejection. [Exposure contract](../../../mobile/src/utils/offerExposure.ts#L17), [measured hook](../../../mobile/src/hooks/useSelectedOfferSignals.ts#L20), [legacy suppression](../../../mobile/src/screens/TradesScreen.tsx#L4286), [exact current surface](../../../mobile/src/screens/TradesScreen.tsx#L6138).
- **One-sided interest / retained mutual interest:** server writes authenticate actor and owned impression, while match attribution retains both original impressions plus a later current evaluation. Win Now like/pass is a separate decision stream. Repeated presentations are not independent trials; withdrawals/undo and non-overlapping interest intervals must not become retained mutuals. [Outcome write](../../../backend/server.py#L5510), [match attribution](../../../backend/server.py#L5662), [episode reducer](../../../backend/eval/scorecard_outcomes.py#L86).
- **Verified completion / recommendation overlap:** Sleeper ingestion retains completed transaction IDs and raw payloads. Existing suggestion matching may choose a partial asset-overlap match, uses current owner mappings unless supplied, can use sync time when trade time is missing, and does not require a qualified view. Its `was_recommended` is therefore not exact-concept, exposure-attributed conversion. Preserve useful overlap diagnostics, but require exact directional asset/pick lineage, historical manager identity, provider transaction/time and observation coverage for the framework's completion endpoint. Missing provider follow-up is Unknown, not noncompletion. [Transaction capture](../../../backend/sleeper_trades_service.py#L89), [matching](../../../backend/suggestion_telemetry.py#L256), [lookback/linking](../../../backend/suggestion_telemetry.py#L361).

The framework already requires an explicit origin, fixed eligible manager/league cohort, qualified exposures, mature follow-up and verified completion; it separates historical/retained mutuals and supports Unknown rather than treating silence as a pass. The source paths above do **not** demonstrate that production currently supplies a complete adapter/cohort/follow-up dataset satisfying that contract. Audit completeness before calculating its rates. Freeze eligible cohorts before treatment, retain no-request/error/empty cases, handle connected league/manager clusters and exact-concept multiplicity, and do not interpret an uncontrolled before/after deployment comparison as causal lift. [Cohort contract](../../../backend/eval/scorecard_outcomes.py#L342).

## Handoff

Build no new provider pipeline from this audit alone. The smallest justified next implementation is a licensed/qualified weekly snapshot adapter plus a pure two-manager weekly-impact shadow with complete provenance and explicit Unknown. Reuse the point-assignment primitive and storage patterns, address the listed semantic gaps, and separately qualify ROS aggregation, uncertain-availability substitution and season probabilities. This research neither reverses the previously recorded model/latency uncertainty nor supplies a new release-quality claim.
