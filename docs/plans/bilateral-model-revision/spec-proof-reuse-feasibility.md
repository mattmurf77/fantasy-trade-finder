# Request-local exact-proof reuse — feasibility before implementation

Parent-owned next performance investigation; no authorization to weaken final
validation. Current server re-evaluates every unchanged generated owner offer
against the same frozen request in `_owner_cards_valid`. This may be redundant,
but only a complete dependency/trust argument can justify reuse.

Agent C, after its round5 independent review, may READ code and propose a bounded
private experiment. Do not modify shared runtime or accept a client-provided hash,
historical proof or mutable context as trustworthy. Agent A remains owner of the
current two measured performance prototypes; coordinate rather than overlap.

Determine whether a request-local registry of server-generated exact proof
objects can authenticate reuse when ALL authoritative generation inputs and
dependencies are unchanged, the original immutable proof object is retained,
the card still matches terms/participants/prices, the selected constructor and
policy version remain valid, and all independent final significance/roster/
disposition/publication gates still run. Changed or unverifiable input must
fall back to full re-evaluation or fail closed, never reuse by trade ID alone.

Audit full player/roster/board/source/selection/preference/config/pick and league
identity dependencies, static tier bands, package-value/DP state and ambient
overrides. Existing assignment request hashes intentionally omit some settings
and normalize arrays; they are not automatically safe cache keys. Account for
partial-selection authority, equivalent asset permutations, stale/replaced proof,
same-arm revision flips, mutable cached side records and post-generation mutations.

Deliver a narrow design and falsification tests or a concrete reason reuse is
unsafe. Do not call it a speedup until a separately approved private full-worker
prototype matches every prior term/order/private proof/publication occurrence.
Retain all validation semantics; this is proof reuse under authenticated unchanged
dependencies, not removal of the final owner eligibility check.
