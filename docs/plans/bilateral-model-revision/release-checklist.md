# Release decision checklist — not executed activation instructions

Only the final decision in status/evaluation evidence may qualify an artifact.
Local tests and descriptive raw metrics alone are not a signed six-dimensional
promotion. The owner authorized conditional release or another coding round;
they did not waive the reviewed scorecard's missing-data or release gates.

## Automated / evidence prerequisites

- Exact source and config manifests; full tests, independent cross-review and
  hosted CI green on the intended commit/production runtime.
- Incumbent/candidate/final-policy comparisons separated; all six dimensions for
  both managers' give/receive/package, raw diagnostics, zero/error/Unknown counts
  and honest component-level sample independence retained.
- No known new safety, preference-price, selected-intent, efficient-precedence,
  full-inventory or first-action regression. Preserve reasonable counterparty
  benefit, not just cheaper terms for A.
- Independent four-side review anchors and allowed Unknown coverage, numerical
  improvement/noninferiority margins and critical segments ratified before a
  release comparison is called a pass. Insufficient data requires an explicitly
  scoped experiment decision, not a universal win claim.
- Model/policy versions, retention/eligibility/outcome horizons, monitoring owner,
  rollback artifact and attribution recorded. Generated/committed is not viewed;
  one-sided like/send is not mutual acceptance or provider completion.

## Manual physical-device checks (unexecuted; no simulator)

1. On a controlled real device/account and a known fresh league roster, capture
   actual tap time and first fully rendered card with actionable disposition
   buttons and a durable impression ID. Check cold request, valid prepared
   inventory and repeat request separately. Target ≤3s; report observed tails,
   errors and empty paths rather than timing a placeholder or cached singleton.
2. Browse beyond30 cards. The initial prefix must not change when later batches
   arrive; no duplicate/changed package identities or artificial end-of-deck.
3. Explicitly select give/receive assets and a partner; verify selection and
   visible relaxation semantics. Back navigation and More Offers retain their
   intended state; no automatic ranking/tag change from exploration.
4. For tanking and competitive contexts, inspect high-value focal trades and
   cheaper same-target alternatives. Confirm that explanations use tiers/pick
   equivalents and do not expose another manager's private board/support scores.
5. In the authorized test environment only, change revision during a long search
   and after its first batch. Stale undecided inventory must not republish. Like
   history, original terms and valuation evidence must survive rollback. Record
   unexpected error/empty UX; unit tests are not phone-flow verification.

## Conditional deployment workflow

Do not execute while decision is failed/insufficient evidence. When qualified,
push the reviewed branch/PR, attach the PR to this task, require exact-head CI,
merge and explicitly deploy the verified commit through the established Render
workflow. Inspect fresh autodeploy/service state first. Read existing model
settings, change ONLY `owner_bilateral_revision_enabled` through the audited
config endpoint, read effective state back, and verify actual generated version
and private provenance. Preserve all unrelated arms and controls.

Rollback sets the same knob to0, reads it back and verifies version-1 generation;
do not delete durable offers or relabel historical interests. If runtime rollback
is insufficient, redeploy the recorded prior artifact without changing data.
No client code changed here; a TestFlight upload is required only if subsequent
client changes actually demand one. Do not claim a build or release occurred
without its receipt and verification.
