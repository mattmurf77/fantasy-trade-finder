## Contract and rationale

`backend/trade_bilateral_presentment.py::present(cards, *, selected_give=(), selected_receive=(), opponent_user_id=None)` returns `(ordered_cards, diagnostics)`. Cards remain the same exact object occurrences, including duplicates; terms, score fields and immutable proof objects are untouched. There is no output cap or eligibility/removal operation. Explicit give/receive/partner searches return unchanged.

Current policy version is `bilateral-survivors-3`; only immutable, eligible, exact-bound `owner_v2_bilateral` / `owner-v2-bilateral-2` proofs with validated `same-focal-terms-1` metadata can move. Missing/malformed structural evidence, rejected proofs, prior model versions, explicit selections, already-published cards and inbound/injected/history-exception cards retain their exact absolute positions. Basis/lane source classes retain their slots. An unknown counterparty board does not become known; a counterparty's unqualified personal-intent flag does not invalidate otherwise eligible market/context evidence. The policy-three categorical evidence comparison below additionally constrains novelty.

Each eligible class preserves the constructor's native ordering as its fixed baseline, including efficient same-focal terms. Its first representative stays first. A fresh support-only sort was removed after cross-review demonstrated that it restored a more expensive same-target offer solely after increased liking. Later offers can exchange places to reduce repeated purpose, give focal, receive focal, partner and combined concept. Every swap requires both manager scores to differ by no more than `.025` between offers. Both destination scores must also remain within `.025` of their fixed native baseline scores; this prevents chained swaps from progressively eroding quality. Maximum displacement is 31 class positions, preventing indefinite deferral. These are versioned provisional serving constants, not independently calibrated acceptable-quality thresholds or acceptance probabilities.

The helper uses the candidate's pure `term_evidence_valid` / `term_precedence` API and existing immutable proofs. Surviving price dependencies are built once; novelty cannot move a dependent ahead of a predecessor or move its predecessor behind it. Actual absolute positions are checked even across distinct lane classes. Work is bounded by the 32-position lookahead and at most 64N dependency edges, plus family sorting; memory is O(N). No server, database, generation, provider or runtime config calls occur. The candidate module's shared ranking dependency loads its static tier definitions on initial import. Parent wiring must invoke this once after final authoritative removals and before first durable publication. Polling, cumulative first-batch stability, source attribution, private impression persistence and actual worker capture are parent-owned integration checks.

Bounded-audit limitation confirmed in Agent A's independent cross-review: filtering can remove some of the constructor's first 32 lower-cost representatives, so rebuilding families on survivors can discover a relation that the original full-inventory audit did not compare. If the surviving native order already inverts that newly discovered relation, presentation preserves its baseline rather than repairing the pre-existing inversion. The implemented guarantee is preserving previously audited native precedence and preventing new inversions during novelty; it is not an exhaustive same-target efficient frontier or a claim that every freshly discovered relation is satisfied. Full source/baseline/quality guards otherwise cleared Agent A's independent review.

Diagnostics are PRIVATE: `version`, `generator_version`, `count`, `eligible_count`, `moved_count`, `quality_tolerance`, `lookahead`, `candidate_comparisons`, `term_precedence_edges`, `baseline` (`candidate_native_order`), `reason`, and `occurrence_original_indices`. The last field maps each output position to its zero-based input occurrence position; unlike an object-ID map it preserves repeated references. It contains no raw rankings, Elo, participant IDs or claimed probabilities. No fields are added to public cards.

## Round four — categorical focal preservation

The parent authorized this bounded mechanism repair after the DEVELOPMENT-only stage attribution showed that support-tolerant novelty could reduce known personal focal buy/sell alignment. No independent grader score, coefficient, captured identity, constructor budget, offer eligibility, price or term was changed. The constructor version stays `owner-v2-bilateral-2`; the serving policy is separately versioned `bilateral-survivors-3`.

Each immutable proof supplies raw per-asset `market`, `viewer_personal` / `counterparty_personal` and corresponding source fields. Only the existing personal source set (`explicit`, `votes`, `cross_format`, `legacy`) with finite positive values establishes a known direction. BUY is favorable when personal exceeds market; SELL reverses that comparison. Categories are favorable, neutral or adverse, with only the existing numeric epsilon for equality. Missing/unrecognized sources and invalid personal values are Unknown, not neutral. Tier/ordinal preference scores, support scores, consensus-filled values and independent quality grades cannot supply a missing preference.

All assets exactly tied at the highest market value on each package side are protected, not merely the constructor's tie-broken named focal ID. Each manager's BUY and SELL profile independently stores its Unknown count and sorted known categories. A swap requires equal tie counts and equal Unknown counts at each of its TWO fixed baseline destinations; every sorted known category must be no worse. Thus a favorable co-headliner cannot disappear behind an existing adverse one, or behind missing evidence. Equal categorical profiles still permit useful novelty and asset-order permutations do not alter tie protection. Different tie shapes remain in native order. Malformed asset identity, missing asset records, invalid market values or an incompatible named focal ID protect the exact occurrence; huge numeric JSON values fail closed rather than raising out of the helper.

The comparison remains categorical: it does not claim equal preference intensity, identical contextual benefits, two-manager acceptance, or repairs to a constructor's already-adverse baseline. Neutral/adverse baseline cards remain available. The existing first-representative, support, price-dependency, bounded-displacement, protected-slot, explicit-search and exact-permutation guarantees are unchanged. Every original surviving offer is retained. Per-asset proof content is never added to public cards or helper diagnostics.
