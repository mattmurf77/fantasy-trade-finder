# Selected running-job join code walk

1. `generate_trades` admits only an already validated current-only request with give/receive pins or an opponent. It freezes the ordered raw selectors; the caller's search ID remains outside the join key so each response echoes its own attempt. Intent-only requests keep the existing organic index.
2. `_kickoff_trade_job` captures its ordinary execution context and member epochs. The selected path additionally retains the actual original service, trader, league and player identities, roster order, league seat and viewer account lifetime. Those references describe this live execution; they are not a serialized or atomically captured model input.
3. The join shape includes account/user, league, format, a digest of the session token, ordered raw and effective selections, mode, opponent, intent, exact fairness and presentation exemption. Nonempty request/config/flag signature and two nonempty source fingerprints are mandatory. An unsupported or oversized join identity falls back to unchanged full generation.
4. Fingerprint/source reads finish before `_trade_jobs_lock`. Under that lock, stale pointer entries are removed, then full shape, original source identity, epochs, signatures and fingerprints are compared. The existing running-policy check still covers revocation, model, significance, presentation, safety and roster-read ordering. An already terminal or stalled job cannot join; completion immediately after a valid locked claim is ordinary same-job continuation.
5. The index is capped at 128 digest-to-job-ID pointers. Eviction or a mismatch never cancels another selected job. Force always creates a fresh selected job, independent of the organic force-supersedes knob, and replaces only the matching join handle. Headless/synchronous/prepared/grading/replenishment and legacy calls never enter this new path.
6. A hit returns the existing job ID to the unchanged route response path. Authorization, current-only source checks, per-request preview admission/consumption, disposition projection and per-search ID delivery all remain active. A spent preview still blocks a new generate; same-deck status continuation retains its existing allowance.
7. Finish, revocation, timeout and stale-index pruning drop the job's strong identity references and full shape. The index cannot retain a private session graph after the job disappears. Job snapshots preserve identity references rather than deep-copying authorities, and public views never serialize either private field.
8. A miss starts the original worker exactly once with unchanged generation/final-evaluation/gate arguments. Neither budgets, candidate selection, quality rules, publication proof nor durable evidence is replaced by the join index. Completed selected results remain uncached.

The existing process-wide active-job count is not bounded by this change. Different simultaneous selections retain their independent semantics; global admission, navigation cancellation, completed exact-input reuse and the remaining cold-path latency are separate work. This backend change still changes Calibration's whole-backend revision and requires coordinated release/currentness rebuilding.
