## Dark-safety: no usable `move` in the FA response

Today's server sends no `move`. Every path below then lands where `d14b7308` does.

- **Nothing of a bad capability is used.** `capabilityOrNull` drops an absent, malformed or unknown-mode `move`, and `submit` with no known `league_platform` (`faMove.ts:213-218`, `:290-292`). With none, `rowMoveFields` drops every row's `move_kind` / `move_mode` / `move_line` (`faMove.ts:296-299`), so `move.copy` and the row's line are never read (review round 2, item 10). The sheet starts from both (`ClaimSheet.tsx:225-226`).
- **The gate says legacy.** `faMoveGate` returns `'legacy'` (`faMove.ts:257`), and `faMoveOpensSheet` is false (`faMove.ts:281-286`).
- **Free Agents routes as before.** `onAdd` opens the sheet iff `faMoveOpensSheet(move, row) || addPlatform === 'sleeper'`, else `explainNoAdd(addPlatform)` (`mobile/src/screens/FreeAgentsScreen.tsx:90-101`). With the first term false, that's `d14b7308`'s test (`d14b7308:mobile/src/screens/FreeAgentsScreen.tsx:78-85`). The Add variant uses the same expression (`FreeAgentsScreen.tsx:218`). Each row's `claimPending` is false: the store behind it is written only from a `submit`-mode pending result (`mobile/src/state/claimsPending.ts:17-32`; `claimSheetPlan.ts:139-152`), so the stats line is the drop line as before (`FreeAgentsScreen.tsx:219`, `:298-302`).
- **Usage Trends routes as before, and never waits.** `doAdd` keeps `resolveAddPlatform(lgId, isDemo)` → `explainNoAdd(platform)` for non-Sleeper and switch-then-open for Sleeper (`mobile/src/screens/UsageTrendsScreen.tsx:321-343`). It reads a league's capability only from the query cache, synchronously, before #509's own awaits (`:329`); nothing is fetched at the tap. The capability is prefetched in the background (below), under its own key, never the sheet's; on today's server it holds `move: null`, so the route is the old one, and the sheet still reads its own list after the switch, as on `d14b7308`. On today's server a visit makes one capability read, the focused league's on mount: the list prefetch waits for a `submit` focus (`faMove.ts:722`).
- **The sheet renders #509's hand-off.** `initialView` gives `{step: 'handoff', line: null}` for `legacy` (`claimSheetPlan.ts:89-110`). `submitLayout` is false (`ClaimSheet.tsx:263`), so the `if (!submitLayout)` render runs (`ClaimSheet.tsx:1074-1099`): header, bid, drop, then `handoffBlock` (`:844-850`), which is #509's CTA (`:651-659`; `fa-claim.open-sleeper`, the same label, `onPress={openSleeper}`, `disabled={bidTooHigh}`) and the footer. Same Modal, backdrop, sheet styles and scroll as `d14b7308:ClaimSheet.tsx:152-327`.
- **What differs in that render, and why.**
  - **The footer's words.** "Sleeper doesn't allow apps to submit claims — finish in Sleeper." (`d14b7308:ClaimSheet.tsx:319-321`) becomes the fallback "You'll finish this move in Sleeper." (`ClaimSheet.tsx:647`), since `move.copy` isn't read without a capability. The old line is false once `submit` is on anywhere; this is specified (scope §C state 1).
  - **Plumbing with today's values.** Cancel, the backdrop and `onRequestClose` go through `requestClose` (`ClaimSheet.tsx:425-430`), which is `onClose` while nothing is sending. Cancel, the bid input and the drop rows take `disabled={busy}` / `editable={!busy}`, always false here.   - **No new request.** The sheet makes no call of its own unless the user acts in the `submit` layout.

## 1. Host Add → `move.mode` → sheet, or NO_ADD_REASON

- **Free Agents.** The capability comes from the list's own read (`FreeAgentsScreen.tsx:80`). The tap routes it first (`:93`), keeps the capability as it was at the tap (`:94`) and mounts the sheet with it and a `refetch` (`:236-237`).
- **Usage Trends.** Two background prefetches fill the query cache under `['fa-move-capability', leagueId]`, both through `prefetchLeagueCapability` (`faMove.ts:702-709`: a 60 s staleTime and `retry: false`, so a failure costs one read where the app's default would retry once):
  - **On mount**, and when the focused league changes, the focused league's, for a real Sleeper league session only (`UsageTrendsScreen.tsx:156-159`).
  - **When an availability list opens** (the sheet, or a Version B row expanding), `prefetchCapabilities` (`UsageTrendsScreen.tsx:316-319`, `:435`, `:455`) calls `prefetchListCapabilities` (`faMove.ts:715-727`). It reads nothing unless the focused league's cached capability is `submit` (`:722`), so a dark server, or moves turned off, costs no list reads. Then it asks for at most six of the free-agent leagues, Sleeper first (`:724`).

  The cache keeps only `move` and the rows' move_* fields (`readLeagueCapability`, `faMove.ts:680-697`). At the tap, `capabilityAtTap` (`faMove.ts:732-737`) hands back a cached capability only if it's under 5 minutes old and hasn't been invalidated since (Stop roster moves, or a terminal sheet result, item 5). That one routes by `move.mode` first; anything else routes the legacy way at once (`UsageTrendsScreen.tsx:329-334`; `capabilityForRow`, `faMove.ts:748-754`). Then it switches league and opens the sheet with the row's fields, the capability and the tapped league's name (`UsageTrendsScreen.tsx:335-342`, `:740-742`). There's no busy wait and no spinner.
- **`move.mode` first.** In `submit` mode every step opens the sheet on any platform except MFL without a connection (`faMoveOpensSheet`, `faMove.ts:281-286`), so MFL and ESPN open it in Update 1 with no build. A **held row** (`move_mode: 'handoff'`) opens it too, also on ESPN/MFL, where it shows the server's `move_line` (fallback: "This move can't be made from Fleeced right now. Check ESPN.") rather than `NO_ADD_REASON`'s read-only text (`claimSheetPlan.ts:103-106`). `unsupported` on a non-Sleeper league is today's `NO_ADD_REASON` alert, byte for byte (`ClaimSheet.tsx:122-155`, unchanged; `check-sleeper-handoff.js` S9).

## 2. `faMoveGate` → connect, verify, consent or submit

`faMove.ts:249-274`, in order:

1. No usable capability → `legacy` (`:257`).
2. `unsupported` → `unsupported`; `handoff` → `handoff` (`:258-259`).
3. `submit`, not connected, on a platform with no connect screen in this binary (MFL) → `unsupported` (contract §6; `:261-263`).
4. A held row (any `move_mode`) → `handoff` (`:266`). A `claim` row while `move.claims` isn't true → `handoff`, state 14 before the tap (`:269`).
5. `expired` / `unverified` → `verify`; anything else but `ok`, including `other_account` and unknown values → `connect` (`:270-271`). Connect and verify beat consent.
6. Consent valid → `submit`; ticked → `submit_with_consent`; otherwise `consent` (`:272-273`). An unticked box never submits.

The sheet's first view follows the gate (`initialView`, `claimSheetPlan.ts:89-110`): connect/verify with the server's line, Ready for every submit step (consent is asked at the tap), MFL's `unsupported` as that platform's `NO_ADD_REASON` inside the sheet (`claimSheetPlan.ts:99-102`; rendered at `ClaimSheet.tsx:1031-1044` with only Done, `:984-985`).

## 3. Consent GET → step → POST …/move with `consent` (client half)

- **The selection.** `moveSelection` is the one source for the named CTA, the waiver lines and the request: the drop only while it's still in the candidates, and a claim's bid ($0 for an empty FAAB bid; none in a priority-waiver league) (`claimSheetPlan.ts:273-304`; `ClaimSheet.tsx:295-306`). The CTA comes from `moveCtaLabel` with contract §7's no-bid claim slots (`faMove.ts:957-974`), and a claim's lines from `waiverLines`: `waiver_line` with a drop, `waiver_line_no_drop` without, then `bid_line` only with a bid (`faMove.ts:978-986`; `ClaimSheet.tsx:882`).
- **The league, named (R28.26, D10(a)).** The ready step always shows the server's `league_line` or, with it absent, "In {league}" beside the named CTA, in every state that shows the CTA (6, and 10a/10b/10d/10e/11 inline) (`ClaimSheet.tsx:862-863`). The name comes from the host first (`leagueName` prop: Free Agents' session league, `mobile/src/screens/FreeAgentsScreen.tsx:238`; the tapped league in Usage Trends, `mobile/src/screens/UsageTrendsScreen.tsx:742`), then the session's league list (`ClaimSheet.tsx:215`). A move whose league can't be named gets no named CTA: the hand-off instead.
- **One consent read at a time.** `openConsent` is guarded by a ref, so a same-frame double tap (before `busy` renders) can't fire two consent GETs, or two sends after them (`ClaimSheet.tsx:480`); `send` has its own ref (`sendingRef`).
- **The tap.** `onNamedCta` asks the gate with `consent_until` against now (`ClaimSheet.tsx:539-550`). `consent` → `openConsent(true)` (`:477-511`), which reads through `fetchConsentStep` (`faMove.ts:376-392`): **NetInfo first**, so offline sends no GET; offline, or a GET that fails at the network level (status 0, the timer), is state 11 with nothing sent (`planNotSent`, `claimSheetPlan.ts:134-136`, whose line names no platform, since it's Fleeced's server that wasn't reached: the server's `offline_line` slot when the capability carries one, else "Couldn't connect right now, so nothing was sent.", `faMove.ts:907`); `valid` sends (the capability was stale); a block shows the step; a 403 `verification_required` (the route needs a verified session, contract §2) is state 4, Verify, through the same `planFailure` as the move route's 403 (`ClaimSheet.tsx:498-500`); any other server failure, a 404 or an incomplete block is F4's hand-off with `unavailable_line`.
- **The step.** `showConsent` (`ClaimSheet.tsx:513-536`) unticks every time, shows "terms changed" when the block's `reason` is `version` or this sheet showed another `copy_version` (`termsChanged`, `faMove.ts:416-418`; `ClaimSheet.tsx:516`), reports the block's own `reason` when it sends one (`consentShownReason`, `faMove.ts:464-470`; `ClaimSheet.tsx:518`, `:535`), and refuses to ask consent for a move it can't name (`:526`). The body is the server's `title`, paragraphs and `this_move` filled with the same `ctaLabel` (`:1013-1030`). The pinned block holds the **unticked** box (`:931`), Make the move with the server's `button_label`, disabled until ticked, with a VoiceOver hint (`:947`), Not now (`:956`), Do it in Sleeper instead, and legal's links row: the block's `links` (https only), else the app's Terms and Privacy built from `getBaseUrl()` like PaywallScreen's `openLegal` (`consentLinks`, `faMove.ts:348-360`; `ClaimSheet.tsx:966-981`), each opened through `openPlatform` with no catch (`:442-444`).
- **The send.** `send` re-asks the gate and returns unless it says `submit` / `submit_with_consent` (`ClaimSheet.tsx:554-562`), then calls `attemptMove` once with `...sel.request` and the echo (`:566-574`). `attemptMove` (`faMove.ts:812-846`) reads NetInfo first (offline: no request, no id, no event, `:817`), mints one id per tap (`:818`; `newAttemptId`, `faMove.ts:785-797`: `crypto.getRandomValues` when present, else `Math.random`, always v4-shaped, since Hermes has no Web Crypto), records `fa_move_write_attempted`, and sends `surface` with the body. `submitMove` (`faMove.ts:197-203`) goes through `apiRequest` with `timeoutMs: FA_MOVE_TIMEOUT_MS` = (76 + 15) × 1000 (`faMove.ts:166-174`; `mobile/src/api/client.ts:660`, `:712`).
- **Connect / Verify** (contract §6). `goConnect` hides the sheet (state kept) and opens `SleeperConnect`, or `EspnConnect` with no `reason: 'send'` (its send copy is about trades), after the slide-out (`ClaimSheet.tsx:453-464`). On the host's next focus (`:404`), `onConnectReturn` (`:378-403`) re-reads the list, bounded at 5 s (`refetchSafe`, `:412-414`; `withTimeout`, `faMove.ts:639-653`), and resumes through `resumeAfterConnect` (`claimSheetPlan.ts:258-269`): a failed re-read goes on as connected (consent or Ready; the server's 409s are the net). It never sends by itself.

The sheet adds no hook.
- **Codes → states.** `classifyMoveError` (`faMove.ts:588-623`) maps by suffix (`^(sleeper|mfl|espn)_…`, `:516-526`) through `STATE_BY_CODE` (`:547-569`); `write_failed` with a `kind` is state 11. No answer, the timer, status 0 and a 5xx with no usable code are state 12; any other 4xx with an unknown code is the 12-style neutral panel.
- **The sheet** (`applyOutcome`, `ClaimSheet.tsx:588-620`, applying each plan in one place, `apply`, `:623-640`). The plans are pure (`claimSheetPlan.ts`):
  - 200 `complete` / `pending` → the result panel with the server's `title` and `lines` (`planResponse`, `claimSheetPlan.ts:139-152`). A pending claim also marks the Free Agents row "Claim pending" for the app session (`ClaimSheet.tsx:635`; `FreeAgentsScreen.tsx:219`, `:298-302`).
  - `planFailure` (`claimSheetPlan.ts:155-233`):
    - 1 (`feature_disabled`), 14 (`claims_off`) → the hand-off with a line, bid and drop kept (`:165`, `:196`).
    - 3, 4 → the connect / verify step with the server's message, and `fa_move_connect_shown` (`:167-174`). **MFL** (no connect screen) → that platform's `NO_ADD_REASON` in the sheet, for connect, verify and rejected alike, never a Connect button that does nothing.

    - 10a → the drop list shows **whenever a drop is required**, even when the client saw open slots (`dropListShown`, `:308-311`), with the server's message (focused) and a list refresh (`:179`). 10b clears the stale pick and refreshes (`:186`). 10d recomputes the bid error against the server's `remaining` (`:192`). 10e re-reads the list (bounded) and names the corrected kind with a chalk line (`:194`; `planKindChanged`, `:238-254`).

    - 10c, 10f, 10g, 13 → the result panel with the server's message in `--neg` (`:200-217`). 13 offers Connect again (not on MFL).

- **State 7.** Busy from the tap until the outcome is shown (`ClaimSheet.tsx:554-586`). `requestClose` is a no-op while busy, and the backdrop, Cancel and both Modals' `onRequestClose` go through it (`:425-430`, `:699`, `:1076`, `:1138`). ## Choices the contract and scope left open

- **Usage Trends routes from the cache only** (release-lead's QA, round 6): a capability prefetched when an availability list opened, or the focused league's, prefetched once on mount and on a focus change for a real Sleeper league session (never demo, local or no league; round 6b, `mobile/src/screens/UsageTrendsScreen.tsx:156-159`). An Add on a league whose read hasn't come back yet gets the #509 hand-off or alert at once. So does one whose cached entry is over 5 minutes old or invalidated (round 7). The list prefetch is gated and capped (round 7, release-lead's P2-A). Unbounded, one opened list made a read per free-agent league (13 for 14 leagues, each a live Sleeper rosters GET on the server), retried once on failure. Now nothing is read until the focused league is `submit`, then at most six leagues, Sleeper first, with no retry. Six is release-lead's number. Its availability sheet's footer reads "Add opens a quick check before the move. Trade opens the trade finder in that league." (marketing A1).
- **The fallback copy is marketing's final** (addendum 17 §A): the finality, waiver and bid lines are legal's with `{platform}` filled ("Final on {platform}. Fleeced can't undo it."; "This places a waiver claim for {add} (dropping {drop} if it clears). {platform} processes it on its waiver schedule."; "Bid: {bid}"); the window line reads "Roster moves: on until {date}"; the added-result title is "Done". `check-fa-move` Z1 pins every changed string verbatim.
- **`unsupported` on a Sleeper league** (not a value the server sends) keeps the legacy hand-off, because `NO_ADD_REASON` has no Sleeper entry.
- **In-sheet `unsupported`** (MFL's connect / verify / rejected, MFL not connected at open) shows that platform's `NO_ADD_REASON` with only Done. "Do it in {platform} instead" and the result panels' Open buttons are Sleeper-only, since this binary has only Sleeper's opener.
- **Any per-row `move_mode`** (not only exactly `'handoff'`, e.g. `'HANDOFF'`) holds the row in hand-off (`faMove.ts:266`): the conservative reading. A `consent_until` that isn't an ISO string (a number, say) is not a grant (`faMove.ts:302`).
- **Legal's links are per link:** Terms and Privacy are always both present, the server's valid one where it sent one, else the app's own (`consentLinks`, `faMove.ts:348`). A server link takes Fleeced's slot only by its exact label, "Terms" or "Privacy", trimmed and in any case (`:356`; round 7). A "Sleeper terms" link, or a URL that merely contains `/terms`, follows them as an extra link.
- **`open_platform` is reserved and unread** in this binary; the hand-off CTA keeps #509's approved literal (pinned by `check-sleeper-handoff.js` S2).
- **A claim while `move.claims` isn't true** is a hand-off before the tap (`faMove.ts:269`), not only after a 422.
- **A priority-waiver claim has no bid**, so it uses `cta_claim_no_bid` / `cta_claim_drop_no_bid` and no `bid_line`. `{bid}` groups thousands ("$1,000"), like the sheet's budget line.
- **"Do it in Sleeper instead"** switches the sheet to the hand-off with bid and drop kept (consent.md §2.1). The result panels' "Open in Sleeper" opens Sleeper directly.
- **The consent step requires a nameable move.** If `this_move` can't be filled, no consent is asked and the sheet goes to the hand-off.
- **`connect_shown.reason`** is `unknown` for a `connect` value outside the closed set (analytics-lead, round 3; `connectShownReason`, `faMove.ts:437-441`; `ClaimSheet.tsx:1159-1161`); the UI still shows the plain connect step.
- **`consent_shown.reason` when the block has none** is read client-side: a changed `copy_version` → `version`; a Stop roster moves in this app run → `withdrawn`; a known grant no longer valid → `lapsed`; otherwise `first`. An unknown server value is dropped.
- **Legal's links:** a link without a label or an `https://` URL is dropped; Terms and Privacy are then filled per link from the app's own pages, labelled "Terms" and "Privacy".
- **A connect return whose re-read fails** goes on as connected; a wrong guess is caught by the server's 409 not_linked / expired.
- **"Claim pending" is Free Agents only.** Usage Trends' rows are two components (`UsageTrendCard`'s text button and `UsageStatsTable`'s icon-only cell, kept text-free by `check-usage-trends` 2o), so showing it there is a layout call for design-lead. The store is keyed by league + player, so a Usage Trends claim still marks the Free Agents row.
- **A 2xx the client can't read** is state 12 and records `write_failed {unknown, 200}` (left as is; platforms-eng is telling analytics-lead).
- **testIDs.** The named CTA and the consent step's Make the move are both `fa-claim.make-move` (never on screen together); the result panels' Open in Sleeper reuses `fa-claim.do-in-sleeper`; the in-sheet `NO_ADD_REASON` title reuses `fa-claim.result`.
- **`attempt_id` survives ingest.** It joins `_HEX_ID_PROPS` in `backend/analytics_ingest.py`, like `search_id`, so an id with a 16-digit run isn't scrubbed.
