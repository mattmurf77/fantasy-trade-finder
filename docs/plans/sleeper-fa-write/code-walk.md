## Dark-safety: no usable `move` in the FA response

Today's server sends no `move`. Every path below then lands where `d14b7308` does.

- **Nothing of a bad capability is used.** `capabilityOrNull` drops an absent, malformed or unknown-mode `move`, and `submit` with no known `league_platform` (`faMove.ts:210-215`, `:287-289`). With none, `rowMoveFields` drops every row's `move_kind` / `move_mode` / `move_line` (`faMove.ts:293-296`), so `move.copy` and the row's line are never read (review round 2, item 10). The sheet starts from both (`ClaimSheet.tsx:227-228`).
- **The gate says legacy.** `faMoveGate` returns `'legacy'` (`faMove.ts:254`), and `faMoveOpensSheet` is false (`faMove.ts:278-283`).
- **Free Agents routes as before.** `onAdd` opens the sheet iff `faMoveOpensSheet(move, row) || addPlatform === 'sleeper'`, else `explainNoAdd(addPlatform)` (`mobile/src/screens/FreeAgentsScreen.tsx:90-101`). With the first term false, that's `d14b7308`'s test (`d14b7308:mobile/src/screens/FreeAgentsScreen.tsx:78-85`). The Add variant uses the same expression (`FreeAgentsScreen.tsx:218`). Each row's `claimPending` is false: the store behind it is written only from a `submit`-mode pending result (`mobile/src/state/claimsPending.ts:17-32`; `claimSheetPlan.ts:138-151`), so the stats line is the drop line as before (`FreeAgentsScreen.tsx:219`, `:298-302`).
- **Usage Trends routes as before, and never waits.** `doAdd` keeps `resolveAddPlatform(lgId, isDemo)` → `explainNoAdd(platform)` for non-Sleeper and switch-then-open for Sleeper (`mobile/src/screens/UsageTrendsScreen.tsx:330-354`). It reads a league's capability only from the query cache, synchronously, before #509's own awaits (`:337-340`); nothing is fetched at the tap. The capability is prefetched in the background when an availability list opens (below), under its own key, never the sheet's; on today's server it holds `move: null`, so the route is the old one, and the sheet still reads its own list after the switch, as on `d14b7308`.
- **The sheet renders #509's hand-off.** `initialView` gives `{step: 'handoff', line: null}` for `legacy` (`claimSheetPlan.ts:89-110`). `submitLayout` is false (`ClaimSheet.tsx:265`), so the `if (!submitLayout)` render runs (`ClaimSheet.tsx:1070-1095`): header, bid, drop, then `handoffBlock` (`:842-848`), which is #509's CTA (`:649-657`; `fa-claim.open-sleeper`, the same label, `onPress={openSleeper}`, `disabled={bidTooHigh}`) and the footer. Same Modal, backdrop, sheet styles and scroll as `d14b7308:ClaimSheet.tsx:152-327`.
- **What differs in that render, and why.**
  - **The footer's words.** "Sleeper doesn't allow apps to submit claims — finish in Sleeper." (`d14b7308:ClaimSheet.tsx:319-321`) becomes the fallback "You'll finish this move in Sleeper." (`ClaimSheet.tsx:645`), since `move.copy` isn't read without a capability. The old line is false once `submit` is on anywhere; this is specified (scope §C state 1).
  - **Plumbing with today's values.** Cancel, the backdrop and `onRequestClose` go through `requestClose` (`ClaimSheet.tsx:424-429`), which is `onClose` while nothing is sending. Cancel, the bid input and the drop rows take `disabled={busy}` / `editable={!busy}`, always false here. The header text is `` `Claim ${row.name}` `` (`:641-644`). `dropListShown` is #509's expression when no drop has been required (`claimSheetPlan.ts:307-310`). A selected drop that leaves the candidates is cleared (`ClaimSheet.tsx:331`); in the hand-off that's invisible.
  - **No new request.** The sheet makes no call of its own unless the user acts in the `submit` layout.

## 1. Host Add → `move.mode` → sheet, or NO_ADD_REASON

- **Free Agents.** The capability comes from the list's own read (`FreeAgentsScreen.tsx:80`). The tap routes it first (`:93`), keeps the capability as it was at the tap (`:94`) and mounts the sheet with it and a `refetch` (`:236-237`).
- **Usage Trends.** When the availability sheet opens, or a Version B row expands, `prefetchCapabilities` prefetches each listed free-agent league's capability through the query cache under `['fa-move-capability', leagueId]` with a 60 s staleTime (`UsageTrendsScreen.tsx:318-328`, `:446`, `:466`; `faMoveCapabilityKey`, `readLeagueCapability` and `capabilityForRow`, `faMove.ts:656-690`). The cache keeps only `move` and the rows' move_* fields. At the tap, a cached capability routes by `move.mode` first; an uncached one routes the legacy way at once (`UsageTrendsScreen.tsx:337-345`). Then it switches league and opens the sheet with the row's fields, the capability and the tapped league's name (`UsageTrendsScreen.tsx:346-353`, `:751-753`). There's no busy wait and no spinner.
- **`move.mode` first.** In `submit` mode every step opens the sheet on any platform except MFL without a connection (`faMoveOpensSheet`, `faMove.ts:278-283`), so MFL and ESPN open it in Update 1 with no build. A **held row** (`move_mode: 'handoff'`) opens it too, also on ESPN/MFL, where it shows the server's `move_line` (fallback: "This move can't be made from Fleeced right now. Check ESPN.") rather than `NO_ADD_REASON`'s read-only text (`claimSheetPlan.ts:103-106`). `unsupported` on a non-Sleeper league is today's `NO_ADD_REASON` alert, byte for byte (`ClaimSheet.tsx:121-157`, unchanged; `check-sleeper-handoff.js` S9).

## 2. `faMoveGate` → connect, verify, consent or submit

`faMove.ts:246-271`, in order:

1. No usable capability → `legacy` (`:254`).
2. `unsupported` → `unsupported`; `handoff` → `handoff` (`:255-256`).
3. `submit`, not connected, on a platform with no connect screen in this binary (MFL) → `unsupported` (contract §6; `:258-260`).
4. A held row (any `move_mode`) → `handoff` (`:263`). A `claim` row while `move.claims` isn't true → `handoff`, state 14 before the tap (`:266`).
5. `expired` / `unverified` → `verify`; anything else but `ok`, including `other_account` and unknown values → `connect` (`:267-268`). Connect and verify beat consent.
6. Consent valid → `submit`; ticked → `submit_with_consent`; otherwise `consent` (`:269-270`). An unticked box never submits.

The sheet's first view follows the gate (`initialView`, `claimSheetPlan.ts:89-110`): connect/verify with the server's line, Ready for every submit step (consent is asked at the tap), MFL's `unsupported` as that platform's `NO_ADD_REASON` inside the sheet (`claimSheetPlan.ts:99-102`; rendered at `ClaimSheet.tsx:1027-1040` with only Done, `:980-981`).

## 3. Consent GET → step → POST …/move with `consent` (client half)

- **The selection.** `moveSelection` is the one source for the named CTA, the waiver lines and the request: the drop only while it's still in the candidates, and a claim's bid ($0 for an empty FAAB bid; none in a priority-waiver league) (`claimSheetPlan.ts:272-303`; `ClaimSheet.tsx:297-308`). The CTA comes from `moveCtaLabel` with contract §7's no-bid claim slots (`faMove.ts:892-909`), and a claim's lines from `waiverLines`: `waiver_line` with a drop, `waiver_line_no_drop` without, then `bid_line` only with a bid (`faMove.ts:913-921`; `ClaimSheet.tsx:880`).
- **The league, named (R28.26, D10(a)).** The ready step always shows the server's `league_line` or, with it absent, "In {league}" beside the named CTA, in every state that shows the CTA (6, and 10a/10b/10d/10e/11 inline) (`ClaimSheet.tsx:860-861`). The name comes from the host first (`leagueName` prop: Free Agents' session league, `mobile/src/screens/FreeAgentsScreen.tsx:238`; the tapped league in Usage Trends, `mobile/src/screens/UsageTrendsScreen.tsx:753`), then the session's league list (`ClaimSheet.tsx:217`). A move whose league can't be named gets no named CTA: the hand-off instead.
- **One consent read at a time.** `openConsent` is guarded by a ref, so a same-frame double tap (before `busy` renders) can't fire two consent GETs, or two sends after them (`ClaimSheet.tsx:478`); `send` has its own ref (`sendingRef`).
- **The tap.** `onNamedCta` asks the gate with `consent_until` against now (`ClaimSheet.tsx:537-548`). `consent` → `openConsent(true)` (`:475-509`), which reads through `fetchConsentStep` (`faMove.ts:371-387`): **NetInfo first**, so offline sends no GET; offline, or a GET that fails at the network level (status 0, the timer), is state 11 with nothing sent (`planNotSent`, whose line names no platform: "Couldn't connect right now, so nothing was sent.", `offline_line`, `faMove.ts:842`, since it's Fleeced's server that wasn't reached); `valid` sends (the capability was stale); a block shows the step; a 403 `verification_required` (the route needs a verified session, contract §2) is state 4, Verify, through the same `planFailure` as the move route's 403 (`ClaimSheet.tsx:496-498`); any other server failure, a 404 or an incomplete block is F4's hand-off with `unavailable_line`.
- **The step.** `showConsent` (`ClaimSheet.tsx:511-534`) unticks every time, shows "terms changed" when the block's `reason` is `version` or this sheet showed another `copy_version` (`termsChanged`, `faMove.ts:410-412`; `ClaimSheet.tsx:514`), reports the block's own `reason` when it sends one (`consentShownReason`, `faMove.ts:458-464`; `ClaimSheet.tsx:516`, `:533`), and refuses to ask consent for a move it can't name (`:524`). The body is the server's `title`, paragraphs and `this_move` filled with the same `ctaLabel` (`:1009-1026`). The pinned block holds the **unticked** box (`:927`), Make the move with the server's `button_label`, disabled until ticked, with a VoiceOver hint (`:943`), Not now (`:952`), Do it in Sleeper instead, and legal's links row: the block's `links` (https only), else the app's Terms and Privacy built from `getBaseUrl()` like PaywallScreen's `openLegal` (`consentLinks`, `faMove.ts:345-355`; `ClaimSheet.tsx:962-977`), each opened through `openPlatform` with no catch (`:440-442`).
- **The send.** `send` re-asks the gate and returns unless it says `submit` / `submit_with_consent` (`ClaimSheet.tsx:552-560`), then calls `attemptMove` once with `...sel.request` and the echo (`:564-572`). `attemptMove` (`faMove.ts:748-782`) reads NetInfo first (offline: no request, no id, no event, `:753`), mints one id per tap (`:754`; `newAttemptId`, `faMove.ts:721-733`: `crypto.getRandomValues` when present, else `Math.random`, always v4-shaped, since Hermes has no Web Crypto), records `fa_move_write_attempted`, and sends `surface` with the body. `submitMove` (`faMove.ts:194-200`) goes through `apiRequest` with `timeoutMs: FA_MOVE_TIMEOUT_MS` = (76 + 15) × 1000 (`faMove.ts:163-171`; `mobile/src/api/client.ts:486`, `:541`).
- **Connect / Verify** (contract §6). `goConnect` hides the sheet (state kept) and opens `SleeperConnect`, or `EspnConnect` with no `reason: 'send'` (its send copy is about trades), after the slide-out (`ClaimSheet.tsx:451-462`). On the host's next focus (`:406`), `onConnectReturn` (`:380-405`) re-reads the list, bounded at 5 s (`refetchSafe`, `:414-416`; `withTimeout`, `faMove.ts:633-647`), and resumes through `resumeAfterConnect` (`claimSheetPlan.ts:257-268`): a failed re-read goes on as connected (consent or Ready; the server's 409s are the net). It never sends by itself.

## 5. Result → held page discarded → Done → FA invalidation

- **The held trade page.** `submitMove` goes through `apiRequest`, whose `_noteWrite` reports the path when the request is sent and when it settles (`client.ts:487`, `:503`). `devicePageStore` discards every held page for any path `discardsDevicePages` names (`mobile/src/state/devicePageStore.ts:150`), which includes the move (`mobile/src/utils/devicePage.ts:256-261`; `check-device-first-page.js` 1k, which also pins devicePage's `FA_MOVE_PATH` equal to `faMove.ts`'s, since importing across them would cycle through `client.ts`; `docs/cross-client-invariants.md` lists it with the other discard triggers). The sheet adds no hook.
- **Codes → states.** `classifyMoveError` (`faMove.ts:582-617`) maps by suffix (`^(sleeper|mfl|espn)_…`, `:510-520`) through `STATE_BY_CODE` (`:541-563`); `write_failed` with a `kind` is state 11. No answer, the timer, status 0 and a 5xx with no usable code are state 12; any other 4xx with an unknown code is the 12-style neutral panel.
- **The sheet** (`applyOutcome`, `ClaimSheet.tsx:586-618`, applying each plan in one place, `apply`, `:621-638`). The plans are pure (`claimSheetPlan.ts`):
  - 200 `complete` / `pending` → the result panel with the server's `title` and `lines` (`planResponse`, `claimSheetPlan.ts:138-151`). A pending claim also marks the Free Agents row "Claim pending" for the app session (`ClaimSheet.tsx:633`; `FreeAgentsScreen.tsx:219`, `:298-302`).
  - `planFailure` (`claimSheetPlan.ts:154-232`):
    - 1 (`feature_disabled`), 14 (`claims_off`) → the hand-off with a line, bid and drop kept (`:164`, `:195`).
    - 3, 4 → the connect / verify step with the server's message, and `fa_move_connect_shown` (`:166-173`). **MFL** (no connect screen) → that platform's `NO_ADD_REASON` in the sheet, for connect, verify and rejected alike, never a Connect button that does nothing.
    - 5 → the consent step with the 409's block, or the hand-off if it has none (`:174`).
    - 10a → the drop list shows **whenever a drop is required**, even when the client saw open slots (`dropListShown`, `:307-310`), with the server's message (focused) and a list refresh (`:178`). 10b clears the stale pick and refreshes (`:185`). 10d recomputes the bid error against the server's `remaining` (`:191`). 10e re-reads the list (bounded) and names the corrected kind with a chalk line (`:193`; `planKindChanged`, `:237-253`).
    - 11 → Ready with a `--neg` "nothing was sent" line above the same named CTA (`:197`; offline is `planNotSent`, `:133-135`). The retry is a fresh tap with a fresh id; a consent the offline tap carried goes with it.
    - 400 / an unrecognised 4xx → contract §4's **neutral** panel: the server's own words, dim, no "wasn't made" refusal title, no retry (`claimSheetPlan.ts:203`).
    - 10c, 10f, 10g, 13 → the result panel with the server's message in `--neg` (`:199-216`). 13 offers Connect again (not on MFL).
    - 12 → "Check before resending", the server's words only for its own codes, Open in Sleeper primary, Done, and **no retry** (`:217-230`; `ClaimSheet.tsx:982-1004`).
- **State 7.** Busy from the tap until the outcome is shown (`ClaimSheet.tsx:552-584`). `requestClose` is a no-op while busy, and the backdrop, Cancel and both Modals' `onRequestClose` go through it (`:424-429`, `:697`, `:1072`, `:1134`). The named CTA and Make the move take `loading={busy}`, never `disabled` for busy (`:873`, `:945`): #364's busy rule, with its Button ported (`mobile/src/components/chalkline/Button.tsx:80`, only `disabled` dims), so a working button keeps full brightness with its spinner, takes no tap and reads busy to VoiceOver; `onNamedCta` and `send` also ignore taps while busy. "Still sending" appears at 8 s (`ClaimSheet.tsx:340`).
- **Accessibility.** "Still sending…" is announced when it appears (`ClaimSheet.tsx:343`); the window line's **Turn off** is its own button, not nested text (`:898`); on 10d the bid error takes VoiceOver focus each time the server's budget answer changes it (`:361`, `:728`). Settings announces the failed-DELETE line (`SettingsLeaguesScreen.tsx:142`), since iOS ignores `accessibilityLiveRegion`.
- **The pinned block** measures its content (`blockContent`, the same width and height in both parents) and asks `actionBlockPinned`, which adds the pinned chrome back and has hysteresis, so it never flips back and forth at the threshold (`ClaimSheet.tsx:1102-1115`; `claimSheetPlan.ts:315-327`).
- **"Nothing was sent" only when provable (R28.27, G15).** Only state 11 says it: `offline_line` (offline at the tap, a consent GET with no answer: Fleeced wasn't reached) and `not_sent_line` ("Couldn't reach {platform}…", the server's 502 with a `kind`) are the only fallbacks with those words. 10f (the platform refused) and 13 (connection rejected) never do, since the platform received the request: their fallback title is "This move wasn't made" and their lines are the server's own. `check-fa-move` B3 checks every failure state's fallback text.
- **Done → invalidation.** Every terminal plan carries `refresh`, which invalidates the `['free-agents', leagueId]` prefix (`ClaimSheet.tsx:420-422`, `:631`). That covers both hosts' keys, so the list, the drop list, FAAB and the capability refresh together.

## 6. Withdrawals (Settings)

- **Client half: Settings › Leagues.** One `RosterMovesRow` per platform the user has a league on (`mobile/src/screens/settings/SettingsLeaguesScreen.tsx:55-61`, `:82-84`). Each reads `readConsentStatus` (`faMove.ts:396-406`): 200 `valid: false` when there's no grant (contract §2), and a 404 (an older server) or a 403 `verification_required` (the route needs a verified session) read the same way: no row. It uses `retry: false` (`SettingsLeaguesScreen.tsx:107-112`) and renders nothing unless `valid: true` (`:156`). The read opts into the shared client's `quietStatuses: [403, 404]` (`faMove.ts:391`; `mobile/src/api/client.ts:491`), so those routine answers on a dark or unverified visit emit no `api_request_failed`; a 500 still does.
- **Stop roster moves** is one tap, no dialog (`SettingsLeaguesScreen.tsx:128-146`): `DELETE`, then the server's `notice` replaces the row verbatim with VoiceOver focus, and the consent and FA queries are invalidated. **A failed DELETE, a 403 `verification_required` included, keeps the row** (the grant stays in force) with "Couldn't turn off roster moves. Try again." (marketing A3.9) (`:140`, `:172-176`).
- **Disconnect, expiry, rejection.** Server PR. The client's side of a rejection is state 13 (item 5).

## Choices the contract and scope left open

- **Usage Trends routes from the cache only** (release-lead's QA, round 6): a capability prefetched when an availability list opened, or the focused league's, prefetched once on mount and on a focus change for a real Sleeper league session (never demo, local or no league; round 6b, `mobile/src/screens/UsageTrendsScreen.tsx:156-163`). An Add on a league whose read hasn't come back yet gets the #509 hand-off or alert at once. Its availability sheet's footer reads "Add opens a quick check before the move. Trade opens the trade finder in that league." (marketing A1).
- **The fallback copy is marketing's final** (addendum 17 §A): the finality, waiver and bid lines are legal's with `{platform}` filled ("Final on {platform}. Fleeced can't undo it."; "This places a waiver claim for {add} (dropping {drop} if it clears). {platform} processes it on its waiver schedule."; "Bid: {bid}"); the window line reads "Roster moves: on until {date}"; the added-result title is "Done". `check-fa-move` Z1 pins every changed string verbatim.
- **`unsupported` on a Sleeper league** (not a value the server sends) keeps the legacy hand-off, because `NO_ADD_REASON` has no Sleeper entry.
- **In-sheet `unsupported`** (MFL's connect / verify / rejected, MFL not connected at open) shows that platform's `NO_ADD_REASON` with only Done. "Do it in {platform} instead" and the result panels' Open buttons are Sleeper-only, since this binary has only Sleeper's opener.
- **Any per-row `move_mode`** (not only exactly `'handoff'`, e.g. `'HANDOFF'`) holds the row in hand-off (`faMove.ts:263`): the conservative reading. A `consent_until` that isn't an ISO string (a number, say) is not a grant (`faMove.ts:299`).
- **Legal's links are per link:** Terms and Privacy are always both present, the server's valid one where it sent one, else the app's own (`consentLinks`, `faMove.ts:345`).
- **`open_platform` is reserved and unread** in this binary; the hand-off CTA keeps #509's approved literal (pinned by `check-sleeper-handoff.js` S2).
- **A claim while `move.claims` isn't true** is a hand-off before the tap (`faMove.ts:266`), not only after a 422.
- **A priority-waiver claim has no bid**, so it uses `cta_claim_no_bid` / `cta_claim_drop_no_bid` and no `bid_line`. `{bid}` groups thousands ("$1,000"), like the sheet's budget line.
- **"Do it in Sleeper instead"** switches the sheet to the hand-off with bid and drop kept (consent.md §2.1). The result panels' "Open in Sleeper" opens Sleeper directly.
- **The consent step requires a nameable move.** If `this_move` can't be filled, no consent is asked and the sheet goes to the hand-off.
- **`connect_shown.reason`** is `unknown` for a `connect` value outside the closed set (analytics-lead, round 3; `connectShownReason`, `faMove.ts:431-435`; `ClaimSheet.tsx:1155-1157`); the UI still shows the plain connect step.
- **`consent_shown.reason` when the block has none** is read client-side: a changed `copy_version` → `version`; a Stop roster moves in this app run → `withdrawn`; a known grant no longer valid → `lapsed`; otherwise `first`. An unknown server value is dropped.
- **Legal's links:** a link without a label or an `https://` URL is dropped; Terms and Privacy are then filled per link from the app's own pages, labelled "Terms" and "Privacy".
- **A connect return whose re-read fails** goes on as connected; a wrong guess is caught by the server's 409 not_linked / expired.
- **"Claim pending" is Free Agents only.** Usage Trends' rows are two components (`UsageTrendCard`'s text button and `UsageStatsTable`'s icon-only cell, kept text-free by `check-usage-trends` 2o), so showing it there is a layout call for design-lead. The store is keyed by league + player, so a Usage Trends claim still marks the Free Agents row.
- **A 2xx the client can't read** is state 12 and records `write_failed {unknown, 200}` (left as is; platforms-eng is telling analytics-lead).
- **testIDs.** The named CTA and the consent step's Make the move are both `fa-claim.make-move` (never on screen together); the result panels' Open in Sleeper reuses `fa-claim.do-in-sleeper`; the in-sheet `NO_ADD_REASON` title reuses `fa-claim.result`.
- **`attempt_id` survives ingest.** It joins `_HEX_ID_PROPS` in `backend/analytics_ingest.py`, like `search_id`, so an id with a 16-digit run isn't scrubbed.
