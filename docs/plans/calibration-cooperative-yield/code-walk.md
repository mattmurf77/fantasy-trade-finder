# Code walk: bounded advisory pauses

`outlook_calibration.drain_queue` creates one `_CooperativeYield` for its leased serial batch and forwards it to every `build_session` call. All production Calibration workers enter through `_worker_main → drain_queue`; admin/public enqueue paths wake that same worker. Legacy blind grading is separate. Direct synthetic build callers may omit the callback, preserving their old execution seam.

`_CooperativeYield` (outlook_calibration.py:171) checks pressure at most once per 100 ms work interval. It waits in 100 ms increments, at most ten, then records the end of the wait plus the next work interval. Continuous pressure therefore cannot pause again on every candidate. The 100 ms bound is monotonic elapsed time without advisory sleeping, not an OS/GIL guarantee of CPU service. If the pressure reader fails it gives bounded deference; if the clock or sleep fails, advisory scheduling disables for that batch and computation continues. `BaseException` shutdown controls are not swallowed.

The pressure adapter (outlook_calibration.py:212) calls the existing `_projection_foreground_busy`, which locks only the live job registry and tests native `_job_live` plus exclusion of prepared inventory. It does no provider/SQL work under the lock. This is deliberately conservative: session-init pregeneration, mobile passive prewarm and old-league live jobs also count. Validated tap search IDs are presently response metadata, not a stored attendance lease. No job is canceled/reprioritized by this patch, and the old-league resource issue remains separate.

`build_session` (outlook_calibration.py:219) pauses before provider capture, passes the callback privately to each full `run_arm`, and gives it checkpoints while validating the final review-selection inventory. The pre-capture pause precedes the existing input identity window; it neither splits that window nor substitutes an older source. Its captured snapshot, randomized arm order, unique inventory, bounded review selection and final atomic database write are unchanged. No scheduler pressure exception reaches the arm-error catcher. Lease heartbeat/loss handling and save/finish lease fences are unchanged.

`CapturedComparison.run_arm` (outlook_calibration_adapter.py:153) passes `_check_current` separately to the real model generator and `check_current` separately to `_owner_cards_valid`, whose fresh evaluator already checks every occurrence. The callback never enters copied model context, source identity, config or proof JSON. Coarse checkpoints surround generation, validation, roster, significance, presentment and quality stages. Each stage still runs fully in its original order. Provider fetches and individual non-checkpointed gate calls are not preempted.

The finite candidate-count budgets remain unchanged; wall time is diagnostic only. Diagnostics may record a longer generation `elapsed_seconds`; all counts, verdicts, order and complete proofs must remain equal. Background completion may be later while foreground computation gains CPU time. This is scheduling fairness, not a reduction in required model work, a new quality policy or a 200 ms guarantee.

Acceptance requires source-bound full paired-arm parity and actual organic-worker native/final/public/strict/durable parity under controlled local overlap, plus deterministic callback/lease/progress tests. Local first-publication and memory samples do not establish hosted capacity or physical-device success. Root owns release and current Calibration regeneration because the backend code revision changes.
