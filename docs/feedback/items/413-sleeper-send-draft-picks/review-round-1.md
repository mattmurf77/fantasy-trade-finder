## Rulings on the Author's open questions

**1. Grid source — `load_draft_picks(league_id)` platform-only. Ruling: platform-only, and user-asserted rows 422 `sleeper_pick_unmapped` by design; the PRD must say so.** Reason: (a) a user-asserted row's `original_roster_id` is "an OPAQUE, LEAGUE-LOCAL slot label … never resolved against a platform" (`database.py:10218-10221`, `seed_pick_grid`), so it cannot be encoded into a Sleeper roster id even in principle — it is not a Sleeper pick. (b) Can a Sleeper client display one? Technically the assignment routes have no platform guard (only `feature_disabled` / `not_in_league`, `server.py:14502-14545`, `:14591-14640`) and `picks.assign_tradeable` is ON (`config/features.json:219`), so `_pick_read_source()` (`server.py:11150-11165`) unions user rows into `/api/league/picks` (`:10854`) and `_inject_owned_picks`. But the only assignment UI is the ESPN Draft Room (`picks_not_assigned` is ESPN-only, `:10840`, `:11347`), so a Sleeper league acquires user rows only by hand-crafted API calls. (c) Even then the encoder must not trust them: Sleeper's `traded_picks`/rosters can validate a platform row and nothing else. Put in PRD §4: "A user-asserted (`source='user'`) row can only exist on a Sleeper league via a direct API call; it 422s `sleeper_pick_unmapped` because its `original_roster_id` is an opaque slot label, not a Sleeper roster id — the default platform source is the containment, not an oversight." Guardrail 8 keeps its wording.

**2. Mobile alert copy — rewrite, keep the structure.** Approve: title `Couldn’t send`, no `goConnect`, no `detail`, no pick ids, branches after `roster_not_found` and before the catch-all. Rewrite the bodies count-aware, mirroring `SendInMflButton.tsx:143-146` (`const n = body?.picks?.length ?? 0`):
- `sleeper_pick_unmapped`: `` `${n || 'Some'} draft pick${n === 1 ? '' : 's'} in this trade couldn’t be matched to a pick in this Sleeper league, so nothing was sent. Generic picks like “Early 1st” can’t be sent — use a specific pick.` ``
- `sleeper_pick_not_owned`: `` `${n || 'Some'} draft pick${n === 1 ? '' : 's'} in this trade ${n === 1 ? 'has' : 'have'} already changed hands, so nothing was sent. Rebuild the trade and try again.` ``
Sentence case, curly apostrophes, em dash, no emoji — matches Chalkline body copy (`docs/design/design-system.md:103`) and the existing alert ladder. Server `detail`/`message` (objection 1) use the "Some" form verbatim so fielded builds read the same sentence.

**3. T-11 — patch `_save_deck_outcome_safe`.** Ruling: mock, not flag-driving. Driving `deck.signal_v2` requires a `deck_impressions` row owned by the user and served ≤30d (`server.py:4783-4796`) plus the flag patch — a fixture the route file does not have and would duplicate `test_deck_signal` coverage. The call site at `:16264` is the only way this route writes an outcome, so the mock proves route-level ordering exactly. Pair it with the positive assertion in objection 5, otherwise the mock-only approach cannot distinguish "gate before the call" from "call deleted".

**4. TestFlight honesty — objections 2 and 3.** Once `detail` rides on the 422s, every step runs on any fielded build; the new build changes only the refusal wording. TF-5/TF-6 become opportunistic; TF-3 records "not run" as a legal outcome.
