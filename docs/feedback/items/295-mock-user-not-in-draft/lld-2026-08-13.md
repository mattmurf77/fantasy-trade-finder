## 1. The eight §14 decisions

Each: the decision, the invariant it upholds, and where the exact code shape

### 1.1 Persona/roster keying vs `resolved_order` (§14-1)

**Decision: key `resolved_personas` over the ordered union
`owners ∪ resolved_order`; leave roster exclusion fail-soft and document it.**

```python
resolved_personas = {
    str(o): dict(((personas or {}).get(str(o))
                  or {"outlook": DEFAULT_OUTLOOK, "source": PERSONA_DEFAULT}))
    for o in dict.fromkeys([*owners, *resolved_order])
}
```

(`dict.fromkeys` is the order-preserving union — owners first, then any
order-only entries.) An order-only entry therefore always has a persona row in
the snapshot (`{outlook: "not_sure", source: "default"}`) — semantically
identical to `advance_cpu`'s fail-soft default at
`mock_draft_service.py:1191-1193`, which **stays** as engine defence for
hand-built states. Rationale: `settings` is the complete record of a mock
(HLD §4.2 reason 2); a persona map that silently omits a team the slot table
can put on the clock breaks that, and `settings_echo.personas` is a client
join key (`MockDraftScreen.tsx:293`) — a missing key renders a null persona
line, which is graceful but incomplete for one line of cost.

Roster exclusion: an order entry absent from `ctx.rosters` simply has no
pre-draft roster to exclude and no severity input — its CPU picks come from
the shared pool with flat needs. That is **the contract**, stated in
`build_settings`' docstring (§2.1), not a bug to engineer around: the session
cannot supply a roster for a member it does not know.

Upholds: INV-4 (order-only entries are first-class slots), the
settings-snapshot-completeness half of INV-6's "no broken state is ever
constructed".

### 1.2 The short-order floor (§14-2)

**Decision: an explicit `order` shorter than `MOCK_MIN_TEAMS` is treated as
*not an order* — `build_settings` falls back to the seeded shuffle of
`owners`, labels it `randomized`, and drops `traded_slots` with it.**

```python
if order is not None and len(order) < MOCK_MIN_TEAMS:
    # §14-2: a degenerate platform order below the mock's own floor is not
    # an order (server precedent at server.py:11915 — "a partial slot map
    # is not an order"). Fall back to the labelled shuffle, and drop the
    # overlay with it: a traded pick is meaningless without the slots it
    # trades between.
    order = None
    traded_slots = None
```

placed at the top of the order-resolution block, before the existing
`if order:` branch. Not a refusal, not silent acceptance:

- A refusal would need a new reason string (bright-line vocabulary growth)
  for a state no live league has ever produced, and it would break G2 — the
  probe counted `owners` and said `can_start: true, teams ≥ 4`; refusing at
  create tells the client something the probe did not.
- Accepting would size a 2-team draft under a probe that promised ≥ 4 —
  INV-4 kept the letter and betrayed the point.
- The fallback keeps both: `teams == len(resolved_order) == len(owners)`
  matches the probe's count, the user is in the shuffle (owners include the
  caller, INV-1), and the client's shipped KD-6 disclosure
  (`mock-setup.order-notice`, `settings_echo.order_source: "randomized"`)
  states honestly that the order is invented-and-labelled.

Upholds: INV-4, INV-5/G2 probe-create agreement, KD-6.

### 1.3 R2 string-coercion and de-dup — the shared helpers (§14-3)

**Decision: two new module-level helpers in `backend/server.py`, and the four
sites become calls.** R1≡R4 and R2≡R3 are shared construction (INV-2, INV-3),
not four parallel edits:

```python
def _mock_owner_ids(sess: dict) -> list[str]:
    """INV-1/INV-3 — THE construction of the engine's `owners`: the session
    members (caller-excluded by app convention, server.py:14655/:14661) plus
    the caller, str-coerced, de-duplicated, order-preserving. Both the create
    path (R1) and the capability probe (R4) call this and nothing else, so
    probe and create cannot count teams differently (G2). An empty session
    user_id is never appended — the refusal ladder then answers
    `user_not_in_draft` (T-295-09's phantom-owner tripwire)."""
    members = list(getattr(sess.get("league"), "members", []) or [])
    out: list[str] = []
    seen: set[str] = set()
    for uid in (*(str(m.user_id) for m in members),
                str(sess.get("user_id") or "")):
        if uid and uid not in seen:
            seen.add(uid)
            out.append(uid)
    return out


def _mock_rosters(sess: dict) -> dict[str, list[str]]:
    """INV-1/INV-2 — THE construction of the engine's `rosters`: member
    rosters plus the caller's session roster (session shape server.py:2010,
    read pattern :4638). The caller's entry is assigned AFTER the member
    comprehension, so if a client ever sends the caller inside
    `opponent_rosters` the dict key de-duplicates and the session's own
    `user_roster` wins — the session is the caller's authoritative roster.
    Create (R2) and resume (R3) both call this, so `rostered_ids` and the
    severity inputs are identical on both paths and `consensus_rank` cannot
    shift between create and resume."""
    members = list(getattr(sess.get("league"), "members", []) or [])
    rosters = {str(m.user_id): [str(p) for p in (m.roster or [])]
               for m in members}
    uid = str(sess.get("user_id") or "")
    if uid:
        rosters[uid] = [str(p) for p in (sess.get("user_roster") or [])]
    return rosters
```

Coercion rules, pinned: owner ids are `str()`-coerced at construction (both
helpers); player ids are `str()`-coerced inside `_mock_rosters`; the empty
string is never an owner and never a roster key. Caller position in `owners`
is last — order is irrelevant (the randomized branch shuffles; the assigned
branch indexes `order`), so no reordering churn in existing fixtures.

**Plus one D-16 companion (line-level finding, §11.3):** `_mock_usernames`
gains an optional `session_user` so the caller is *named*:

```python
def _mock_usernames(league_id: str, members,
                    session_user: tuple[str, str | None] | None = None) -> dict[str, str]:
```

After the two existing loops:

```python
    if session_user:
        uid, display = session_user
        uid = str(uid or "")
        if uid and uid not in out:
            name = _mock_owner_name(uid, stored.get(uid), display)
            if name:
                out[uid] = name
    return out
```

Both context builders pass
`session_user=(str(sess.get("user_id") or ""), sess.get("display_name"))`.
Without this, a repaired mock on a Sleeper league with no `league_members`
rows renders the user's own recap-round rows as "Unassigned"
(`MockDraftScreen.tsx:718` `nameOf.get(...) ?? 'Unassigned'`) — the user
would finally be *in* the draft and unnamed in it.

### 1.4 `user_owner_id` keyword plumb-through (§14-4)

**Decision: keyword-only, `None`-defaulted, `None` skips the rung.** End to
end:

| Layer | Exact shape |
|---|---|
| `start_refusal` | `def start_refusal(ctx, owners, *, user_owner_id: str | None = None) -> str | None` — fourth rung, **last** (after `league_too_small`): `if (user_owner_id is not None and str(user_owner_id) not in {str(o) for o in owners or ()}): return REASON_USER_NOT_IN_DRAFT`. `None` = a legacy positional caller; the rung is skipped, so every existing call site and test is byte-compatible. The empty string is *not* `None`: a `user_id == ""` session refuses (T-295-09). |
| `capability` | signature gains the same keyword; body becomes `reason = start_refusal(ctx, owners, user_owner_id=user_owner_id)`. Payload shape unchanged — `reason` simply may now carry the fourth string. |
| `_mock_capability` (probe, R4) | `return mds.capability(ctx, _mock_owner_ids(sess), user_owner_id=str(sess.get("user_id") or ""))` |
| GET route (no row) | unchanged code — `empty_payload(REASON_NO_ACTIVE_MOCK, _mock_capability(...))`; the ride-along `capability` now carries `can_start: false, reason: "user_not_in_draft"` when the rung fires, which is what lets the entry card disable **without a POST** (§3.3). |
| Create route | `refusal = mds.start_refusal(ctx, owners, user_owner_id=user_id)` at `server.py:12056`. |
| `build_settings` (the raise) | after order resolution and `teams = len(resolved_order)`: `if str(user_owner_id) not in resolved_order: raise UserNotInDraft(str(user_owner_id))` — INV-6, before any slot table or persisted row exists. |
| Resume / pick / abandon | **nothing** — a persisted row's `settings.user_owner_id ∈ settings.order` by INV-6; re-checking at resume would be a second enforcement point with no new information. |

The guard is mode-blind: both enforcement points run identically for
`cpu` and `manual` (T-305-04).

### 1.5 Error-shape parity (§14-5)

**`bad_mode` — 400, request-shape error, `bad_basis` parity:**

```python
mode = str(body.get("mode") or mds.MODE_CPU)
if mode not in (mds.MODE_CPU, mds.MODE_MANUAL):
    return jsonify({"error": "bad_mode"}), 400
```

Body: exactly `{"error": "bad_mode"}`, status 400 — byte-parallel to
`{"error": "bad_basis"}` at `server.py:12017`. Placement: in the POST arm,
immediately after the `rounds` validation block (`:12038-12046`) and **before**
`_mock_league_context` — cheap request validation precedes expensive
resolution, same as `rounds`. Absent / `null` / `""` all default to `"cpu"`
(the `or` — same idiom as `bad_basis`'s `(… or BASIS_CONSENSUS)`), so a
shipped 1.12.x client that sends no `mode` is untouched.

**`user_not_in_draft` — 200 typed-empty, never 4xx.** Two producers, one
byte-identical body:

1. The ladder rung (create route, `:12056-12058`, unchanged mapping):
   `return jsonify(mds.empty_payload(refusal))` →
   `{"schema": 1, "empty": true, "reason": "user_not_in_draft"}`.
2. The engine raise, mapped at the route — the **only new try/except**, wrapping
   the `build_settings` call alone (not `new_state`/`advance_cpu`):

```python
    try:
        settings = mds.build_settings(
            ctx, owners=owners, user_owner_id=user_id, rounds=rounds,
            draft_type=body.get("type") or real["type"],
            order=real["order"], order_source=real["order_source"],
            traded_slots=real["traded_slots"],
            personas=_mock_personas(league_id, sess),
            mode=mode,
            rng=random.Random(rng_seed))
    except mds.UserNotInDraft:
        return jsonify(mds.empty_payload(mds.REASON_USER_NOT_IN_DRAFT))
```

This is route-owned exception→shape mapping, the same posture as the pick
route's `NotYourTurn`/`PlayerUnavailable` arms (`:12113-12116`) — except those
map to 4xx because they are *user* errors on a healthy mock, while this maps
to the typed-empty because it is a *league/contract* condition the ladder
vocabulary already names. Clients never learn which enforcement point fired.
A raise NOT caught here would fall to the generic `@app.errorhandler` 500 —
T-295-13 pins the mapping for exactly that half-implementation.

The GET path never produces `user_not_in_draft` as a top-level `reason` — it
rides the `capability` object only (top-level GET reasons stay
`no_active_mock`).

## 6. Compatibility and migration

- **Pre-mode persisted rows: read-time default, no migration, no backfill.**
  Every reader is `settings.get("mode", MODE_CPU)` (`next_pick`,
  `state_payload`). A pre-build CPU row resumed post-build behaves
  byte-identically (T-305-05) and echoes `mode: "cpu"`.
- **Determinism:** the per-pick stream `Random(rng_seed·10007 + pick_no)` is
  untouched; user picks are inputs, not draws; manual mode never consults the
  per-pick RNG; the seed still drives the order shuffle identically in both
  modes. Honest restatement (HLD §8): the *same seed* produces a *different
  draft* pre- vs post-repair — membership and teams changed — but persisted
  rows replay under their own snapshotted settings.
- **Shipped 1.12.x clients:** `mode` optional on POST (absent = today's
  behaviour); new echo keys are additive and ignored; the new reason string
  degrades through the open enum + `default:` arm to generic copy. No forced
  upgrade.
- **Old servers × new clients:** `mode` in the POST body is an unknown key —
  Flask's `body.get` world ignores it; the client's echo reads are nullable;
  `resolveUserOwnerId` falls back to the shipped heuristic, which is sound in
  the only mode an old server can produce.

### 11.1 `settings_echo` needs `user_owner_id` — HLD §9's "entire contract delta" was one field short

The shipped client identifies the user's team by inference
(`resolveUserOwnerId`, `MockDraftScreen.tsx:740-747`): `on_the_clock.is_user
→ roster_id`, else `my_picks[0]`. Its own comment concedes the reason:
"`settings_echo` does not echo `user_owner_id`". **Manual mode breaks both
legs**: `is_user` is true on *every* owned slot (the roster_id is whichever
team is up — wrong team), and `my_picks` is empty until the user's own team
has picked. Every downstream consumer — the "Your picks" chips, the ticker's
*mine* highlight, the recap's "Your draft", `for_own_team`, and the HLD's own
§4.5 clock-card variant (which requires knowing the user's team to detect
"another team") — would misattribute. The one-line echo addition
(`state_payload`, §2.1) is the minimal honest fix; the client reads it first
and keeps the shipped inference as the old-server fallback, which is sound in
the only mode old servers have. **The PRD and the api-reference delta must
carry this field**; if the orchestrator rejects the contract growth, the
fallback alternative is reading the app session's `user.user_id` (equal to
`settings.user_owner_id` by construction) — workable, but it moves a payload
fact into a cross-store coupling and is not what this LLD specifies.

### 11.2 Old-corpus R15/R16 (co-owner degrade-not-refuse) are dead — the PRD must not resurrect them

`prd.md` §4 R15 degraded an assigned order lacking the caller to a randomized
shuffle so a co-owner could still mock, and T-295-14 pinned it. The plan §2.3
and HLD §3.3 supersede this with the `UserNotInDraft` raise → typed-empty: a
caller in `owners` but absent from the platform order is now **refused**, in
both modes. Consequence worth stating plainly for the operator: a co-owner
(an id in `co_owners`, never in round-1 `original_user_id`) gets
`user_not_in_draft` instead of a randomized mock. That is the binding design
(loud beats accommodating on a state that signals bad data); T-295-14's
premise is void and it is not carried. If co-owner accommodation is wanted, it
is a new decision for the operator, not a silent LLD revival.

### 11.3 D-16 fifth site: the usernames map lacks the caller

The HLD's R1–R4 tables cover `owners` and `rosters` but `_mock_usernames`
(`server.py:11717-11760`) also iterates the caller-excluded `members` (plus
`league_members` rows, which a plain Sleeper league may not have). Post-repair
the user is *in* the draft but *unnamed*: recap round rows render "Unassigned"
for their picks (`MockDraftScreen.tsx:718`). §1.3's `session_user` parameter
closes it inside R2's shared construction. Same invariant (INV-1: "every
membership-derived engine input includes the caller") — usernames are a
membership-derived input the HLD's table did not enumerate.

### 11.4 The pre-POST disabled entry requires consuming the GET `capability` — a typed-but-unread field today

HLD §3.3 promises "the client can render a disabled entry state without ever
POSTing", but `DraftRoomScreen`'s `mockBlock` ladder (`:298-355`) reads only
`postRefusal` (POST answers) and board-derived facts — the GET ride-along
`capability` is not in the client's types and not consumed. §3.1/§3.3 add the
`MockCapability` type and the `probeReason` derivation. Without this, the arm
would be POST-only and the user would meet the refusal one tap late (the
shipped `cpu_model_unvalidated` pattern) — tolerable, but not what the HLD
states.

### 11.5 Everything else survived

The one-lever claim (INV-7) verified: `next_pick:1061` is the only `is_user`
producer; `advance_cpu:1181`, `apply_user_pick:1219`, and the create-time
advance all consume it; no second mode-conditional site was needed anywhere.
The recap/`my_picks` claim verified at `state_payload:1333`. The zero-egress
audit of every specified diff line is clean. The `cpu_model_unvalidated`
mode-blindness stands (rung unreachable, `CPU_MODEL_VALIDATED = True` at
`:300`).
