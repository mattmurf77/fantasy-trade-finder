## 1. Context — the feature has never worked

**The mock draft has never let any user pick, on any league, on any platform,
since it was enabled** (2026-08-08, `6caca35`). This is the **third** report of
the same defect: #295 and #296 (v1.12.0, Sleeper), then #305 (v1.12.1, ESPN —
Newton's 13-pick rounds in a 14-team league are the same missing caller
observed as arithmetic). Root cause, re-verified at file:line in plan §1: the
app-wide session convention keeps the caller **out** of
`sess["league"].members`, and the mock-draft resolution layer read that list
as "everyone in the league" at four sites — so `owners` never contained the
user, `is_user` never fired, and every mock was born complete with zero user
picks and no error.

**What "fixed" means, and nothing less:**

1. The user is **in** their own mock — in the order rail, on the clock at
   their real slots, their rostered players out of the pool — on **every**
   platform branch (Sleeper assigned order, Sleeper randomized, ESPN/MFL
   randomized) — and picks land.
2. The #305 loop works as shipped-engine contract: sim → stop at the user's
   turn → pick from undrafted → resume to the next user turn → recap.
3. **Both modes** work: `cpu` (computer drafters pick other teams) and the new
   `manual` (the user picks for every team) — #305's priority feature.
4. The **next** silent exclusion is a loud refusal: `user_not_in_draft`, one
   vocabulary, two enforcement points, and a born-broken mock can never be
   persisted (INV-6).

There is no "before" to restore, so no verification may compare against prior
behaviour; every acceptance shows the user drafting. A green suite was not
evidence last time — hence the sabotage rule in §7.

## 2. Requirements — the repair (R-series)

Every requirement names its LLD section (the code shape lives there — this
document does not restate line-level diffs) and the HLD invariant it upholds.
"Verified by" names §7 tests.

### R1 — one shared constructor for `owners`, caller included

`backend/server.py` gains module-level `_mock_owner_ids(sess)` exactly per LLD
§1.3: session members plus the caller, `str()`-coerced, de-duplicated
order-preserving, caller last; the **empty string is never appended**. Both
`_mock_league_context` (create) and `_mock_capability` (probe) call it and
nothing else — probe and create cannot count teams differently. *(LLD §1.3,
§2.2 · INV-1, INV-3/G2 · verified by T-295-01, T-295-04, T-295-08, T-295-09.)*

### R2 — one shared constructor for `rosters`, caller's roster included

`_mock_rosters(sess)` per LLD §1.3: member rosters plus
`{str(user_id): sess["user_roster"]}`, player ids `str()`-coerced, the
caller's session roster assigned **after** the member comprehension (the
session wins if a client ever leaks the caller into `opponent_rosters`). Both
`_mock_league_context` and `_mock_context_from_row` call it, so
`rostered_ids` — and therefore the frozen consensus pool and every
`consensus_rank` — are identical on create and resume. *(LLD §1.3, §2.2 ·
INV-1, INV-2 · verified by T-295-01, T-295-07.)*

### R3 — the caller is named: `_mock_usernames` gains `session_user`

The fifth membership site (LLD §11.3, D-16 companion): `_mock_usernames`
accepts optional `session_user=(user_id, display_name)` and appends the
caller's resolved name when absent. Both context builders pass it. Without
this, a repaired mock on a plain Sleeper league renders the user's own recap
rows as "Unassigned" — in the draft and unnamed in it. *(LLD §1.3, §11.3 ·
INV-1 · verified inside T-295-01's username assertions.)*

### R4 — `teams` derives from the resolved order; short orders floor to the shuffle

In `build_settings`: `teams = len(resolved_order)`, computed **after** order
resolution — `owners` never sizes the draft. An explicit `order` shorter than
`MOCK_MIN_TEAMS` is *not an order*: fall back to the seeded shuffle of
`owners`, label `order_source: "randomized"`, and drop `traded_slots` with it
(a traded pick is meaningless without the slots it trades between). Not a
refusal — the probe promised `can_start` off the owners count and create must
not contradict it (G2). *(LLD §1.2, §2.1 · INV-4, INV-5 · verified by
T-295-03, T-295-16.)*

### R5 — personas key over `owners ∪ resolved_order`; roster exclusion stays fail-soft

`resolved_personas` covers the order-preserving union of `owners` and
`resolved_order` (LLD §1.1's `dict.fromkeys` shape), so every team the slot
table can put on the clock has a persona row (`{outlook: "not_sure", source:
"default"}` for order-only entries). An order entry with no session roster
simply has no pre-draft exclusion — that is the documented contract in
`build_settings`' docstring, not a bug. `advance_cpu`'s fail-soft default
stays as engine defence. *(LLD §1.1 · INV-4, INV-6's
settings-completeness half · verified by T-295-15.)*

### R6 — fourth refusal rung: `user_not_in_draft`, last, keyword-only

`REASON_USER_NOT_IN_DRAFT = "user_not_in_draft"`. `start_refusal` gains
keyword-only `user_owner_id: str | None = None`; the rung is checked **last**
(after `league_too_small` — least actionable last), fires when the id is
non-`None` and absent from `owners`; `None` skips the rung (legacy positional
callers byte-compatible); the **empty string is not `None`** — a `user_id ==
""` session refuses. `capability()` forwards the keyword; `_mock_capability`
passes `str(sess.get("user_id") or "")`; the create route passes `user_id`.
The rung is mode-blind. *(LLD §1.4 · INV-5 · verified by T-295-05, T-295-09,
T-305-04.)*

### R7 — engine backstop: `UserNotInDraft` raise, mapped to the same typed-empty

`build_settings` raises `class UserNotInDraft(MockDraftError)` (`code =
REASON_USER_NOT_IN_DRAFT`) when `str(user_owner_id) not in resolved_order`,
immediately after `teams` is derived and **before any row exists** — a
user-less mock can be refused but never persisted. The create route wraps the
`build_settings` call **alone** in `try/except mds.UserNotInDraft` and returns
`jsonify(mds.empty_payload(mds.REASON_USER_NOT_IN_DRAFT))` — byte-identical to
the rung's refusal; clients never learn which enforcement point fired. An
uncaught raise would 500 through the generic errorhandler — T-295-13 pins the
mapping. Resume/pick/abandon re-check **nothing** (INV-6 makes a persisted row
sound by construction). *(LLD §1.4, §1.5 · INV-6 · verified by T-295-06,
T-295-13, T-305-04.)*

### R8 — `settings_echo.user_owner_id` (LLD §11.1 contract addition — first-class)

`state_payload`'s `settings_echo` gains `"user_owner_id"` (always present on
state payloads). This is what makes "my team" knowable in manual mode: the
shipped client inference (`is_user` → `roster_id`, else `my_picks[0]`) is
**unsound** there — `is_user` is true on every owned slot. The client
(`resolveUserOwnerId`) reads the echo first and keeps the shipped inference
only as the old-server fallback, where it is sound because old servers have
only cpu mode. Every "my team" consumer — chips, ticker highlight, recap,
`for_own_team` — keys off this id, **never** off `by`. *(LLD §2.1, §3.4,
§11.1 · HLD §4.3/§4.4 · verified by T-305-06, T-305-02.)*

### R9 — the GET `capability` ride-along is typed and consumed (LLD §11.4 — first-class)

`mobile/src/api/mockDraft.ts` gains the `MockCapability` interface (shape
frozen in §5.6) and `MockDraftEmpty` gains `capability?: MockCapability`.
`DraftRoomScreen` derives `probeReason` from a `no_active_mock` empty's
`capability.reason` and the blocked-entry arm keys on
`postRefusal === 'user_not_in_draft' || probeReason === 'user_not_in_draft'` —
so the entry card renders **disabled before any POST**, which is the HLD §3.3
promise the shipped client never implemented. *(LLD §3.1, §3.3, §11.4 ·
verified by T-295-10.)*

### R10 — client refusal surfaces

One `emptyCopy` arm (`case 'user_not_in_draft':`, must not equal the
`default:` string) in `MockDraftScreen`; one `mockBlock` arm with testID
`mock-entry.blocked.user_not_in_draft` in `DraftRoomScreen`, placed after the
`class_not_loaded` arm (server-answer group, before board-derived arms);
`MockEmptyReason` union gains `'user_not_in_draft'`. Strings in §4.4/§4.5.
*(LLD §1.6, §3.3, §3.4 · verified by T-295-10.)*

## 3. Requirements — manual mode (M-series)

### M1 — POST `mode` field, validated at the route

`POST /api/mock-draft` body gains optional `mode` ∈ `"cpu" | "manual"`,
default `"cpu"`. Absent, `null`, and `""` all coerce to `"cpu"` (the
`bad_basis` `or`-idiom — a shipped 1.12.x client is byte-untouched); any other
value → `400 {"error": "bad_mode"}`, byte-parallel to `bad_basis`, placed
after the `rounds` validation and before `_mock_league_context` (cheap
validation before expensive resolution). *(LLD §1.5, §2.2 · INV-8 · verified
by T-305-03.)*

### M2 — `mode` is a create-time-immutable settings key

Engine constants `MODE_CPU = "cpu"` / `MODE_MANUAL = "manual"`. `mode` is
snapshotted into `settings` at create (engine-side coercion to `MODE_CPU` for
non-members keeps `build_settings` total; the route already 400'd real
garbage) and never mutates — no schema change, no new flag, no migration.
*(LLD §2.1 · HLD §4.2's four reasons · verified by T-305-01, T-305-05.)*

### M3 — one engine lever, in `next_pick`, and nowhere else

`slot["is_user"] = owner is not None and (mode == MODE_MANUAL or owner ==
settings.user_owner_id)`, with `mode = settings.get("mode", MODE_CPU)`. **No
other site may read `mode` for a turn decision** (INV-7). Create-time stop at
pick 1, per-pick one-slot advance, completion, recap, and abandon all fall out
of shipped code. *(LLD §2.1 · INV-7 · verified by T-305-01, T-305-02,
T-305-07.)*

### M4 — `settings_echo.mode`, always present, the only mode truth

`settings_echo` gains `"mode"` on every state payload; pre-mode persisted rows
echo the effective value (`settings.get("mode", MODE_CPU)`), so clients need
no undefined branch and must never infer mode from `by`, pick cadence, or
`on_the_clock`. *(LLD §2.1, §6 · HLD §4.4 · verified by T-305-05, T-305-06.)*

### M5 — setup-sheet mode control

`MockSetupSheet` gains a two-option segmented control below the Pick-order
field, `TypeSeg` pattern verbatim (Chalkline: ice active segment, no new
colors), testIDs `mock-setup.mode.cpu` / `mock-setup.mode.manual`, default
CPU (pending Q2, §11), both segments `disabled={busy}`, state re-seeded to
`'cpu'` on each open. `MockSetupResult` gains `mode`; `createMockDraft` gains
optional `mode` with body spread only when set. Field hint and footNote
branch on mode — strings in §4.1. *(LLD §3.1, §3.2 · verified by M-2 flow +
T-305-01 end-to-end.)*

### M6 — the clock card names whose team the user is picking for

`OnTheClockCard` gains `forOwnTeam` (computed at the call site:
`!onClock?.roster_id || !userOwnerId || String(onClock.roster_id) ===
userOwnerId`). When `isUser && !forOwnTeam` (manual mode, another team's
slot): the headline becomes the picking-for variant and a sub-line with
testID `mock-draft.clock.picking-for` renders; owner name comes from the
existing `clockName` join — no new data. When `forOwnTeam`, byte-identical to
today. The confirm-bar meta's `your pick` label becomes conditional. Strings
in §4.2/§4.3. Pick-sheet reachability needs no change (`isUserTurn` drives
it). *(LLD §3.4 · verified by M-2 flow.)*

### M7 — recap semantics carry; `by` never means "my team"

`my_picks` = picks with `picked_by_user_id == settings.user_owner_id` — in
manual mode a strict subset of `picks[]` even though every pick is
`by: "user"`. No client logic may key "my team" off `by`; `mock_completed`'s
`user_picks` counts `my_picks.length`. *(HLD §4.3 · verified by T-305-02.)*

### M8 — compatibility is total

Pre-mode rows: read-time default, byte-identical resume (T-305-05). Shipped
clients: `mode` optional, new echo keys additive, new reason degrades through
the open enum + `default:` arm. New client × old server: echo reads nullable,
`resolveUserOwnerId` falls back to the shipped inference. Determinism: manual
mode never consults the per-pick RNG; the seed still drives the order shuffle
identically in both modes. *(LLD §6 · verified by T-305-03, T-305-05,
T-305-07.)*

## 4. Copy — final strings

These are the finals for every placeholder LLD §1.6 flagged. Register rules,
per the operator's #205 tenets and the shipped arms' own voice: plain words; a
blocked state states a fact and offers **no remedy that cannot succeed**; no
jargon a non-tech-savvy user must already know ("manual mode" never appears in
user-facing copy — the choice is described, not named); no ids in copy.
Byte-exactness matters (Maestro law-1 matches source bytes): strings landing
in `MockDraftScreen.tsx` and `MockSetupSheet.tsx` use the **curly apostrophe
`’`** (their file convention — "You’re on the clock", "You’re drafting for");
strings landing in `DraftRoomScreen.tsx` use the straight apostrophe (its
`mockBlock` convention — "don't", "isn't"). Every
string below lands in a named copy arm or testID from LLD §1.6.

### 4.1 `MockSetupSheet` — the mode control (M5)

| Element | String |
|---|---|
| Field label | `You pick for` |
| Segment, testID `mock-setup.mode.cpu` (default) | `Your team` |
| Segment, testID `mock-setup.mode.manual` | `Every team` |
| Field hint, cpu selected (`fieldHint` style) | `Computer drafters handle the other teams and stop when you’re up.` |
| Field hint, manual selected | `You make each team’s pick, in draft order, from first to last.` |
| footNote, cpu selected | *(shipped string, unchanged)* `Nothing here is written to your league. Computer drafters pick for the other {teams − 1} teams.` |
| footNote, manual selected | `Nothing here is written to your league. You’re making every pick in this mock.` |

Why short segments + a hint rather than the LLD's placeholder sentence-length
labels: the `TypeSeg` control renders two half-width segments ("Linear" /
"Snake"); a sentence does not fit, and the sheet's existing Pick-order field
already carries a `fieldHint` line — the mode field reuses that shape. The
field label + segment reads as one sentence ("You pick for → Your team /
Every team"), which is the #205 bar: the choice is self-evident without
knowing how the app works.

### 4.2 `MockDraftScreen` — the clock card (M6)

| State | Headline (`clockWho`) | Sub-line |
|---|---|---|

tapped "Every team" ten minutes ago is reminded, at the moment of confusion

## 5. API contract, frozen

The build agents code against these bytes. Complete delta over the shipped
contract: POST body `mode`; `settings_echo` gains `mode` + `user_owner_id`;
fourth ladder rung `user_not_in_draft` (rung and raise, one vocabulary);
`400 bad_mode`. Everything else — routes, statuses, `order[]`/`picks[]`
shapes, recap fields, abandon semantics, `SCHEMA = 1` — unchanged.

### 5.1 Create — CPU mode (default)

```
POST /api/mock-draft
{"league_id": "1312140920132497408", "rounds": 4, "type": "linear"}
```

→ `200`, full state payload. The repaired invariants visible on the ffv3
shape (12-team assigned linear order, operator at slot 8):

```jsonc
  "league_id": "1312140920132497408", "season": 2026,
  "on_the_clock": {"pick_no": 8, "round": 1, "slot": 8,
                    "roster_id": "313560442465169408", "is_user": true},
  "order": [ /* 48 rows: slots 1..12 × 4 rounds; slot 12's manager present */ ],
  "picks": [ /* picks 1..7, all "by": "cpu" */ ],
  "undrafted": [ /* pool minus ALL 12 rosters, including the caller's */ ],
  "my_picks": [],
  "settings_echo": {
    "rounds": 4, "type": "linear", "teams": 12,
    "order_source": "assigned",
    "personas": { /* every id in owners ∪ order, incl. the caller */ },
    "noise": {"bpa_prob": 0.10, "reach_decay": 0.70, "max_reach": 3.0},
    "consensus_pool_size": 79,

```

### 5.2 Create — manual mode

```
POST /api/mock-draft
{"league_id": "espn:11896", "rounds": 4, "mode": "manual"}
```

→ `200`: `"status": "active"`, `"picks": []` (zero CPU picks),
`"on_the_clock": {"pick_no": 1, "round": 1, "slot": 1, "roster_id": "<slot
1's owner — any team>", "is_user": true}`, `"my_picks": []`,
`settings_echo.mode: "manual"`, `settings_echo.teams: 14` (Newton: 13
caller-excluded members + caller), `order_source: "randomized"` (ESPN is
structurally randomized).

### 5.3 Create — refusals and errors

```jsonc
// mode ∉ {"cpu","manual"} and not absent/null/"" → request-shape error:
400 {"error": "bad_mode"}

// ladder rung OR engine raise — byte-identical, indistinguishable by design:
200 {"schema": 1, "empty": true, "reason": "user_not_in_draft"}
// exactly these three keys — no capability object on a POST refusal
```

The other create-time refusals (`class_not_loaded`, `cpu_model_unvalidated`,
`league_too_small`) and errors (`league_id is required`, `bad_basis`,
`not_rookie_draft`, 404s, auth) are unchanged. Ladder order:
`class_not_loaded` → `cpu_model_unvalidated` → `league_too_small` →
`user_not_in_draft` (last).

### 5.4 Pick — both modes

```
POST /api/mock-draft/pick   {"mock_id": 41, "player_id": "12345"}
```

→ `200`, full state. **CPU mode:** the appended pick is `"by": "user"` with
`picked_by_user_id` = the user's id; then CPU picks follow to the user's next
slot or completion. **Manual mode:** exactly one pick appended (`"by":
"user"`, `picked_by_user_id` = whichever team owned the slot); `on_the_clock`
advances exactly one slot, `is_user: true` again. Errors unchanged: 409
`not_your_turn` · 400 `player_unavailable` · 404 `mock_not_found`.

### 5.5 Recap (`status: "complete"`)

Identical shape in both modes. `my_picks` = picks with
`picked_by_user_id == settings_echo.user_owner_id` — in manual mode a strict
subset of `picks[]` even though every pick is `by: "user"`. Clients must not
key "my team" off `by`.

### 5.6 GET — typed-empty with the `capability` ride-along

The GET's top-level `reason` vocabulary is unchanged (`no_active_mock` — the
new string never appears top-level on GET). The ride-along now carries the
fourth rung:

```jsonc
200 {"schema": 1, "empty": true, "reason": "no_active_mock",
     "capability": {"can_start": false, "reason": "user_not_in_draft",
                    "teams": 3, "min_teams": 4, "rounds_default": 4,
                    "rounds_max": 8, "type": null, "order_source": null}}
```

Client typing, frozen (`mobile/src/api/mockDraft.ts`):

```ts
export type MockDraftMode = 'cpu' | 'manual';

export interface MockCapability {
  can_start: boolean;
  reason: MockEmptyReason | null;
  teams: number;
  min_teams: number;
  rounds_default: number;
  rounds_max: number;
  type: MockDraftType | null;
  order_source: MockOrderSource | null;
}

// MockDraftEmpty gains:            capability?: MockCapability;
// MockEmptyReason union gains:     | 'user_not_in_draft'
// MockSettingsEcho gains:          mode: MockDraftMode | null;
//                                  user_owner_id: string | null;
// createMockDraft params gain:     mode?: MockDraftMode
//   body spread: ...(params.mode ? { mode: params.mode } : {})   — a
//   1.12.x-shaped call is byte-identical on the wire.
```

Both new echo fields are nullable **in the type only** (old-server safety);
the new server always sends both.

## 6. Analytics

server-side bulk-clear emits nothing.
