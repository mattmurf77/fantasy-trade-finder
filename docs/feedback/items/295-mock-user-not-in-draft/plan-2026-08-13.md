## 1. Root cause, re-verified on `3b64a44`

All four defect sites survive verbatim; only line numbers moved (the old plan's `:11533-11622` block now sits at `:11763-11851` after intervening batches).

**The convention.** `/api/session/init` builds `league.members` **only** from the client's `opponent_rosters` (`backend/server.py:14582`, `:14634`) and the DB-merge step explicitly refuses to add the caller back: `backend/server.py:14655` `existing_member_ids = {m.user_id for m in members} | {user_id}` and `:14661` `continue  # already in the list or is the logged-in user`. Every client filters the caller out before sending — verified current example: `mobile/src/api/espn.ts:216` `.filter((m) => m.user_id !== user.user_id)`.

**Primary site — `backend/server.py:11796`** (`_mock_league_context` return):

```python
    ), [str(m.user_id) for m in members]
```

`members` is `sess["league"].members` (`:11773-11774`). This `owners` list — the leaguemates, never the league — flows into `mds.start_refusal(ctx, owners)` at `:12056` and `mds.build_settings(ctx, owners=owners, user_owner_id=user_id, …)` at `:12071-12077`.

**Enabling site — `backend/mock_draft_service.py:988-1000, :1026`** (`build_settings`): `teams = len(owners)` (`:989`); no supplied `order` ⇒ seeded shuffle **of `owners`** (`:998-999`); and `user_owner_id` is written into settings unvalidated (`:1026`) — it is in neither `owners` nor the resolved order and nothing complains.

**Consequence — `backend/mock_draft_service.py:1061`** (`next_pick`): `slot["is_user"] = owner is not None and owner == settings["user_owner_id"]` never matches, so `advance_cpu`'s user-stop (`:1181-1182`) never fires and the loop at `:1176-1212` drafts every slot; `_append` flips `status` to complete (`:1240-1241`). The create route then persists a born-complete mock (`server.py:12078-12082`). No refusal, no error: `start_refusal` (`mock_draft_service.py:426-443`) has exactly three rungs — `class_not_loaded`, `cpu_model_unvalidated`, `league_too_small` — and none checks the user.

## 2. The repair (#295/#296/#305 defect half)

Carried from the old plan §6 — re-judged against current code and still right. Both halves ship together: the repair fixes today's leagues; the guard makes the next silent exclusion a visible refusal.

### 2.1 Membership repair — four sites in `backend/server.py`

| # | Site (current lines) | Change |
|---|---|---|
| R1 | `_mock_league_context`, `:11796` | `owners` = member ids **plus** `str(sess["user_id"])`, de-duplicated. Order irrelevant: the randomized branch shuffles; the assigned branch indexes off `order`. |
| R2 | `_mock_league_context`, `:11775` | `rosters` gains `{str(sess["user_id"]): sess["user_roster"]}` so `rostered` (`:11777`) covers the caller (session shape: `server.py:2010`). |
| R3 | `_mock_context_from_row`, `:11812`/`:11827` | identical roster addition — create and resume must compute the same `rostered_ids`. |
| R4 | `_mock_capability`, `:11851` | same owners construction as R1, so probe and create count teams identically (G2 invariant). |

### 2.2 `teams`/`order` consistency — `mock_draft_service.build_settings`

When an explicit `order` is supplied, `teams` and the slot table derive from `len(resolved_order)` (`:989`, `:1007`), not `len(owners)`. Without this, R1 fixes the missing user on the randomized branch but the assigned branch (now live on ffv3, §1) still truncates the last slot whenever the two lengths differ.

### 2.3 Fail-loud guard — fourth refusal rung + engine raise

- **(a)** `start_refusal(ctx, owners, *, user_owner_id: str | None = None)` gains `REASON_USER_NOT_IN_DRAFT = "user_not_in_draft"` as the **last** rung (after `league_too_small`, on the shipped ladder's own ordering logic, `:429-435`). Keyword-only with `None` default so the existing positional call sites and tests are untouched. `capability()` (`:446-475`) forwards the same argument so probe and create cannot diverge; the create route (`server.py:12056`) passes `user_id`.
- **(b)** `build_settings` raises new `UserNotInDraft(MockDraftError)` (alongside `NotYourTurn` `:310` / `PlayerUnavailable` `:314`) when `str(user_owner_id) not in resolved_order` — catches the case the ladder cannot see: user in `owners` but absent from a platform order (stale roster takeover, commissioner rebuild). The create route wraps the call and maps it to `jsonify(mds.empty_payload(mds.REASON_USER_NOT_IN_DRAFT))` — byte-identical shape to the ladder's refusal.
- **Client compatibility:** the reason enum is open by construction — `mobile/src/api/mockDraft.ts:35-39` types it `… | (string & {})` and `MockDraftScreen.tsx`'s `emptyCopy` has a `default:` arm (`:785-796`). Shipped 1.12.x builds degrade to "This mock draft isn't available right now." The mobile delta is one `emptyCopy` arm plus one `mockBlock` arm + testID `mock-entry.blocked.user_not_in_draft` in `DraftRoomScreen.tsx` (the `mockBlock` ladder at `:297-357`).

The guard applies in **both** modes (§3): manual mode still mocks *this user's league*, so a draft without the user's team is refused there too.

#305's stated loop — sim → stop at user's turn → pick from undrafted → resume to next user turn — is **already the shipped engine's contract** (`advance_cpu` stop at `:1181-1182`; `apply_user_pick` validate → append → re-advance at `:1215-1228`). R1 alone makes it reachable. No engine loop changes are needed for the defect half.

### 2.4 Alternatives — unchanged from old plan §6.4

All six alternative/rejection verdicts re-checked and carried: fix-in-clients (rejected — four builders plus every installed 1.12.x keeps the bug), widen `league.members` (rejected — ~20 consumers want leaguemates; FB #41 went the other way), `load_league_members` as source (rejected as primary — per-login snapshot, under/over-counts; cross-check only), derive-from-platform-order (rejected — fails the randomized branch, which is every ESPN/MFL league including Newton), guard-only, repair-only (both rejected).

## 3. Manual-draft-for-all-teams mode (#305 priority)

New scope the old spec never had. Design principle: **a toggle on the existing engine, not a new engine.** One request field, one settings key, one engine lever, one sheet control.

### 3.1 API shape

- `POST /api/mock-draft` body gains optional **`mode: "cpu" | "manual"`**, default `"cpu"`. Unknown values → 400 `bad_mode` (closed set, server-validated — cheaper than a silent default on a typo'd client).
- Persisted as `settings["mode"]` inside the existing `settings` JSON column (`mock_drafts` table, `backend/database.py:1655-1668`) — **no schema change**; rows created before this build lack the key and `settings.get("mode", "cpu")` keeps every persisted mock replaying identically.
- `settings_echo` (`mock_draft_service.py:1334-1343`) gains `mode`, so a resumed client knows which mock it holds. `capability` payload is unchanged (mode is a request, not a league property).
- **Rejected shapes:** a new route (`/api/mock-draft/manual`) — duplicates the whole lifecycle for one branch; riding `settings_echo` only without a request field — the client has to say it somewhere, and `mode` in the create body is the minimal honest place; a feature flag for the mode — `draft.mock` already gates the whole surface, and a per-mode flag would drag in the five-file flag-registration affair (`LAUNCHED_FLAG_DEFAULTS` map-replace trap, `_load_from_json` unknown-key drop, pin-store/route-params trap — `mobile/src/state/useFeatureFlags.ts:45`) for zero gating value. **No new flag.**

### 3.2 Engine lever — one line of truth

In `next_pick` (`mock_draft_service.py:1052-1062`):

```python
slot["is_user"] = (settings.get("mode") == MODE_MANUAL and owner is not None) \
    or (owner is not None and owner == settings.get("user_owner_id"))
```

(New constants `MODE_CPU = "cpu"` / `MODE_MANUAL = "manual"` beside the existing enums at `:60-91`.) Everything else falls out of shipped code, verified against current sources:

- **Create:** `advance_cpu` (`server.py:12079`) hits `slot["is_user"]` true at pick 1 and returns immediately — zero CPU picks, `status: active`.
- **Pick:** `apply_user_pick` (`:1215-1228`) validates the turn off the same flag, appends with `by: BY_USER`, and its trailing `advance_cpu` returns at the next slot. The human picks every slot in draft order.
- **Completion/recap:** `_append`'s total-picks check (`:1240-1241`) and `state_payload`'s `my_picks` filter (`:1333` — keyed on `picked_by_user_id == user_owner`, **not** on `by`) both work unchanged: the recap's "My picks" stays the user's own team even though every pick is `by: "user"`. That is the intended semantics — `by` records *who moved the piece*, `picked_by_user_id` records *whose team it is*.
- **Abandon (#292 semantics):** untouched — abandon is row-status bookkeeping (`server.py:12123+`), mode-blind.
- **Determinism:** `rng_seed` persists as today; in manual mode the RNG is simply never consulted (no CPU picks), so replay is trivially exact.
- **Refusal ladder:** unchanged for manual mode, including the `cpu_model_unvalidated` rung. Strictly, that rung is irrelevant when no bot ever picks — but `CPU_MODEL_VALIDATED` is `True` (`:300`, operator override `6caca35`), the rung is unreachable today, and special-casing the ladder by mode would fork the G2 probe contract for a state that cannot occur. Noted for the HLD; do not build it.

### 3.3 Client surface

- **`MockSetupSheet.tsx`** (`mobile/src/components/draft/MockSetupSheet.tsx`): `MockSetupResult` (`:50-53`) gains `mode: MockDraftMode`; one new two-option segmented control below the Linear/Snake row (same control pattern, testIDs `mock-setup.mode.cpu` / `mock-setup.mode.manual`), default CPU. Copy direction: "**Computer picks other teams**" / "**You pick for every team**". Chalkline rules apply (ice for the active segment; no new colors).
- **`mockDraft.ts`**: `MockDraftMode` type, `mode?` on `createMockDraft` params (`:145-159`), `mode` on `MockSettingsEcho` (`:84-91`).
- **`DraftRoomScreen.tsx`**: `createMock` mutation (`:278-294`) passes `setup.mode` through. No entry-card changes for the mode itself.
- **`MockDraftScreen.tsx`**: the on-the-clock card (`mock-draft.on-the-clock`, `:558`) must state **whose team the user is picking for** when `is_user` is true but `roster_id ≠` the session user — owner name resolves from the `order[]` payload rows the screen already holds (`owner_username`). In CPU mode nothing changes (the card is only ever the user's own team). The confirm bar (`mock-draft.confirm`, `:468`), undrafted list, ticker, and recap need no structural change.

### 3.4 Interaction with the repair

None by construction: the repair fixes *who is in the draft* (context layer); the mode changes *who is on the clock* (turn layer). The `UserNotInDraft` guard fires identically in both modes (§2.3).

## 4. The Newton arithmetic — 13 picks per round in a 14-team league, explained

Newton Dynasty League is **ESPN league 11896, `settings.size: 14`** (live-captured fixture `backend/tests/fixtures/espn_league_11896_standings_2026-08-08.json`, provenance header confirms real ESPN v3 API capture). The chain, every link at file:line on current main:

1. ESPN session-init sends 13 opponents: `mobile/src/api/espn.ts:216` filters the caller out of the members it builds (`.filter((m) => m.user_id !== user.user_id)`); 14 teams ⇒ 13 members.
2. `_mock_league_context` returns those 13 as `owners` (`server.py:11796`).
3. `_mock_real_draft` returns `{order: None, order_source: "randomized"}` for any non-Sleeper platform (`server.py:11880-11885`, `platform != dbs.SLEEPER` early return) — ESPN can never supply an order.
4. `build_settings`: `teams = len(owners) = 13` (`mock_draft_service.py:989`); order = shuffle of those same 13 (`:998-999`).
5. `pick_slots(rounds, 13, type)` emits **exactly 13 picks per round** (`:923-929`, `slots = range(1, teams+1)`).
6. The user is in none of the 13 order entries ⇒ `is_user` never true (`:1061`) ⇒ never prompted; `advance_cpu` completes the board on create (`:1176-1212`).

**"13 picks per round" and "not prompted" are the same defect observed twice** — both are `owners` missing the caller. It is the old plan's §1.1 randomized-branch failure on a new platform and a new size; the diagnosis needed no amendment, and the repro arithmetic confirms rather than contradicts it. Post-R1: owners = 14, teams = 14, 14 picks per round, user on the clock at their shuffled slot. (No assigned-order case exists for ESPN — step 3 is structural.)
