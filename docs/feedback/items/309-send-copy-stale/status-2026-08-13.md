## 5. Plan defects found (report-back items)

1. **`release-inline-strip.json` cannot work on this harness** (plan §3
   Maestro delta). `trades_home_inline.strip` is an EXPERIMENT
   `client_config.flags` overlay, not a `FLAG_KEYS` entry:
   `backend/feature_flags.py:_load_from_env` filters `FTF_FLAGS` to
   `DEFAULT_FLAGS` keys, so the fixture key is silently dropped, and
   `seed_ui_test_db.py` seeds no experiments rows so `/api/feature-flags`
   returns empty `configs` (precedent: `capture/calc.yaml` header — "the
   hermetic backend leaves this unit on control"). Consequence: no Maestro
   flow can render `TradingWithStrip` today. Adaptation:
   `trades-banner-region.yaml` runs under plain `release` and proves the
   #315 details-row path end-to-end; the #314 move is pinned structurally
   (`check-trades-banner-region.js` §1). Unblocking the strip on-sim needs
   either seeder experiment support or promoting the overlay key into
   `FLAG_KEYS` — both out of this wave's scope (the latter crosses the
   flag-surface bright line).
2. **The plan's flow asserts `trades.prefs-changed-strip`** after a
   sheet-only session, but `handleEditSheetClose` arms the strip only when
   `deck.length > 0` (TradesScreen). Deterministically reaching it would
   spend the flow's 60s budget generating a deck to prove #257's existing
   contract, not this wave's changes — assertion dropped from the flow
   (documented in its header).
3. *(Minor)* Plan §5 line refs drifted a few lines from the base (e.g.
   `:4954` vs actual mount sites) — cosmetic, no effect on the build.
