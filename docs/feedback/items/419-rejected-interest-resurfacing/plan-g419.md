## 2. State and identity contract to preserve

- **Deck pass is not match Decline, inbox Dismiss, or withdrawal.** `/swipe` accepts `like|pass`; `/pass-reason` records the same pass through progressive writes. `/matches/<id>/disposition` accepts `accept|decline`; `/matches/<id>/dismiss` is visibility-only; `/awaiting/dismiss` withdraws only the caller's own live like rows using `retracted_at`. Do not repurpose those rows as evidence that another actor changed their mind.
- **D-067 governs this bounded exact-pass fix:** hard exact-pair exclusion for the existing configurable 14-day window, immediate across format services, no near-duplicate expansion, no deck-size floor rescue. Served but unacted cards are allowed to reappear. See `living-memory/DECISIONS.md:876`.
- **D-170 is not a rejection bypass.** Hand-built `calcq_` likes bypass preference/quality gates, but still honor past-swipe replay and R4 (`DECISIONS.md:1116`; `server.py:3583` and `:3629`). Preserve the exemption from fairness, not an exemption from the recipient's decision.
- **Exact means direction-aware sets, not card ID.** A gives `{a}` / receives `{b}` is B gives `{b}` / receives `{a}`; reordering IDs or issuing a new `likesyou_<random>` ID does not create a new package. Keep actor, league and resolved partner boundaries. Never collapse give/receive into one unordered union or suppress every package containing either player.
- Current persisted decisions have no target-user column (`database.py:9228` explains roster-based partner recovery). Existing service exclusion sets omit partner/league because they are held by league-specific services. Any helper shared across sessions must explicitly retain actor/league scope and must not leak an exclusion across two leagues holding the same NFL players.
- `trade_concept_id` is optional/dark attribution, not a universally populated decision key. Do not depend on it to fix live or historical records. Fuzzy mirror matching (`database.py:8820`, Jaccard plus low-value guard) is **matching**, not authority to fuzzy-suppress a pass or to transfer fresh consent to a changed package.
- Two current “Undo” operations are different: the mobile short pass Undo cancels a held POST (`TradesScreen.tsx:2397`, `:5567`); `/suppressions/undo` (`server.py:13884`) lifts the newest near-duplicate suppression only. Neither is a general persisted-pass reversal. Preserve these meanings; no new unswipe endpoint in this patch.
- Do not use #419 to implement the separate owner timing/standing-offer redesign, a new interest-expiry clock, original-value replay, ranking changes, or an experiment winner. Keep current/challenger/gen_v2, all package math, thresholds and feature flags unchanged.

## 3. Minimal implementation proposal and ownership

### Author scope after review

0. **Incident-first source-interest reconciliation:** derive a candidate's actionable interest from its actual source-like time and the latest exact, appropriately oriented decisions by both participants. A later recipient pass resolves that **older source offer**; expiry of discovery cooldown must not resurrect the same old positive evidence. Do this read-side, keeping immutable action history and each actor's true ownership. A newer deliberate source like may represent a fresh offer, still subject to existing active recipient cooldown; a receiver's later deliberate like is fresh positive evidence, not an automatic match manufactured by the filter. The reviewer must ratify these precedence cases before code, including legacy-amnesty treatment: D-067 amnesty governs discovery suppression, whereas this fix proposes that an old positive is no longer actionable after an actual later rejection. This is **not** a permanent player/package ban, a changed general cooldown, or an invented interest-expiry clock. Apply the shared interpretation to badge injection first; audit mirror matching, queued-like idempotency and Awaiting for contradictory readers before accepting the scope. Do not claim those sibling lifecycles fixed without tests.

1. **Backend disposition binding:** extract the existing D-067 live exact-pass bind into a small shared helper and invoke it from ordinary and reasoned pass paths. Preserve first-write/progressive refinement semantics and best-effort persistence behavior. Bind both exclusion sets across all relevant format services, including the alias-only legacy session. No duplicate outcomes, reason rows, Elo or notifications.
2. **Backend snapshot consistency:** enforce current exact-pass state at the existing public deck snapshot/serve boundary, covering both cached complete jobs and running/provisional results. Preserve order and metadata for surviving cards. Review the call graph before selecting helper parameters: old job IDs and workers must not resurrect a committed pass, and a job from another league must not be filtered with the caller's current-league service. Invalidation may supplement, but cannot replace, read/publication-time safety. Do not mutate frozen impression history to make it resemble a later filtered response.
3. **Restoration parity:** reuse one narrowly factored current per-decision window/amnesty calculation in normal and replenishment session building. Keep existing knobs and legacy behavior, including conservative malformed-timestamp handling; do not invent a new retention period. Cover day-eight through day-fourteen passes in the alternate builder.
4. **Mobile replay consistency, separate owner seam:** keep successfully committed passes out of the working deck when lane selection resets its cursor or a stale snapshot is merged. Scope state by exact package + opponent + league, not only regenerated card ID. Pending Undo and failed writes must remain reversible; reason-layer writes already report a committed pass, so their success must not depend on a second successful swipe. Avoid broad navigation/refactor work. The author should demonstrate whether the backend fix alone closes the selected UI reproduction before taking this seam.
