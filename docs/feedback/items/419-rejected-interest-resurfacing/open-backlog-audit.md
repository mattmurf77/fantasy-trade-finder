# Open feedback backlog — shipped-code audit

**Audit date:** 2026-09-06. **Scope:** all 45 open database records in the read-only snapshot fetched at 04:03:22 UTC; `new` and `in_progress` below are the database statuses, not inferred implementation statuses. **Code baseline:** `4026ebc81eaae50b345b42421641125c5b8d413e`. No feedback status was changed by this audit.

Reports are paraphrased without reporter identities, account/league identifiers, screenshots or raw report bodies. Private database/settings snapshots are not publication artifacts. This is a point-in-time audit, not a promise that every historical report is reproducible today.

## Bottom line

The strongest closure candidates are **#344 (nested settings), #345 (ranking chooser navigation), and #356 (resolved current-year pick-slot labels)**. Their requested behavior exists in current code, the relevant controls are enabled in the fresh production readback, and release history supports delivery. They are recommendations for a separately authorized status decision, not status changes.

**#417 is implemented by the September 5 owner-search work, but native runtime/delivery verification is still owed. #418 is not fixed on the live baseline:** its named fix exists on other branches, while the current send handler still leaves the shop tile in place. The five old `in_progress` items **#360/#361/#365/#371/#372 are implemented but remain dark**, not fixed for users. **#400 still literally offers “Getting too much.” #408 still narrates the inferred outlook after another option is selected.**

There are **3 closure candidates, 8 implemented-but-unverified items, 12 partial items, 20 still-open items, and 2 product-disposition items**. Every record is listed once below. The aggregate is intentionally conservative: a generally correct implementation or a passing unrelated test does not establish that an unexplained historical anomaly was repaired.
