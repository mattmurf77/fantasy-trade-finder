## P0 — the journey breaks

### 1. The ✕-overlay dead-ends every card it is used on
`TradeCard.tsx:680-683` closes the sheet on a layer-1 tile tap, but the host's `handleReasonLayer1` (`TradesScreen.tsx:4338-4354`) banks the pass with `advance('pass', { deferDeckAdvance: true })` and only fronts the next card from layer 2 (`commitReasonAdvance`, `:4332-4336`). Once banked, ✓/✕/swipe/VoiceOver are all disabled for that card (`:4005-4012`, `:6067-6073`). With the sheet unmounted (RN `Modal` with `visible=false`), layer 2 can never be reached. **User:** flag on → deck → ✕ → tap *Value* → sheet closes, card stays, nothing responds. Guard `check-calc-merged-behavior.js:57-62` *requires* the close; checklist steps 15–16 encode the same wrong contract.
**Fix:** keep the sheet up through layer 2 (close on `onLayer2Select`/`onLayer2Send`, which already do); decide what backdrop-dismiss means after a tile is banked (disable it, or commit the advance). Flip guard assertion 5 and rewrite checklist 15–16.

### 2. Four beats can never advance
n10, n16, n17, n18 are `advance: 'action'` (`analystScript.ts:357,416,426,436`). Action beats move only when something calls `advanceGuideIfActive('<id>')` (`useGuide.ts:523`); tap-anywhere is off for them (`AnalystGuide.tsx:240`). No call site exists for any `n1x` beat — `git grep advanceGuideIfActive` → `s0.2 s1.1 s2.wait s2.2 n2a n5` only. **User:** "Tap In league…" → taps it → bubble stays until ✕ (logged `guide_step_skipped`). Same at add-player, Include toggle, Find a Trade.
**Fix:** `advanceGuideIfActive('n10','action')` in `switchMode` when `m==='league'`; `'n16'` in the give-side `onPick`; `'n17'` in the toggle; `'n18'` in `onFindATrade`. Add a guard assertion: every `advance:'action'` beat id appears in an `advanceGuideIfActive(` call.

### 3. The deck half of the tour (n19–n24) is unreachable
Three independent reasons. (a) n18 never advances (above). (b) `onFindATrade` → `navigation.navigate('TradesHome')` (`TradeCalculatorScreen.tsx:656`): `TradesHome` has no `getId` and the call passes no `pop`, so React Navigation 7.5.3 **pushes a second `TradesHome`** (`@react-navigation/routers/src/StackRouter.tsx:372-390`) — the calculator stays mounted, the hold stays up, and no generation fires because nothing in `TradesScreen` observes pin changes from outside (only `handoff.autoRun` at `:2399-2409` regenerates on arrival). (c) n19/n21/n22 target `trades.pass-btn`, `trades.package-toggle`, `trades.fairness-help`, none of which is ever registered as a guide target (`TradesScreen.tsx:3003-3006` registers four other ids); `check-calc-tour.js:98-106` deliberately omits them. The package toggle only renders with ≥2 give pins (`:5327`) and the tour adds one player; fairness-help is hidden on `firstRun` (`:5126-5136`).
**Note:** the prior session's status/checklist and three of the five reviewers assumed the navigate *pops* the calculator and its cleanup kills the tour. Verified otherwise — but the outcome for the user is the same.
**Fix:** on Find a Trade, `setHandoff({ opponent, autoRun: true })` (the #330 path already regenerates and emits `find_trades_tapped`) and navigate with `{ pop: true }`; register the three deck refs; make n21 conditional on the package toggle existing; own the tour lifecycle above the screen (a module/RootNav effect that ends it on finish / dismiss / tab change), not on calculator unmount.

### 4. The tour was written against a flag state that is dark — and the outlook beat is dark under a second flag
`onboarding.guide_v2` is `false` (`config/features.json:112`, the documented v2 rollback lever). With it off, `useGuide.requestStep` skips the entire v2 block (`useGuide.ts:352-385`): **no spotlights** (`targeted = v2 && !!step.target`, `:400`), `degradeLine` never used (`AnalystGuide.tsx:172-173`), no display caps, no retirement, and the guide never claims the arbiter slot (`:395`). Every beat shows as a floating bubble with deictic copy ("This is your canvas", "Tap the meter…") pointing at nothing. Separately, the outlook row is `OutlookBiasReceipt`, which returns null unless `trade.outlook_direction` is on (`OutlookBiasReceipt.tsx:74-91`; flag is `false`, `features.json:60`) *and* an outlook is already set — so the merged page has no outlook section and no Change control, `TradeDnaSheet` is mounted but unreachable, and n11's "Set outlook" CTA opens nothing because the runner passes no `onAccept` (`calcTour.ts:76-80`; `AnalystGuide.tsx:319`). Neither flag is mentioned in status.md, the checklist, or D-150.
**Fix:** list `onboarding.v2`, `onboarding.guided_avatar`, `onboarding.guide_v2`, `ux.prompt_arbiter`, `trade.outlook_direction` as flip prerequisites with required values, or decouple: render an unconditional outlook row (name + Change, honest "Not set" state) and pass `onAccept: openOutlook` through the runner.

### 5. The ✓ like/queue cell is a permanently disabled control that two beats and the checklist describe as working
`InLeagueCalculator.tsx:1007` `disabled={!onLikeTrade || !bothSides}`; the prop comment (`:73-76`) says "the queue behaviour lands in W2". `git grep onLikeTrade` → only the component; `TradeCalculatorScreen.tsx:611-658` never passes it. There is no backend route to queue a hand-built trade for a counterparty (the deck's like needs a server-minted `trade_id`). n15 spotlights a 40%-opacity button; checklist steps 7 and 12 tell the operator to tap and VoiceOver it; D-150 Decision 3 and status.md present it as built.
**Fix (bright line — needs an API contract):** decide the mechanism (mint via the share-package route then like, or a new "submit package as like" endpoint), or remove the cell + n15 until it exists and correct status/D-150/checklist.

## P1 — must fix before the flip

### 6. "Include Players" is only half a contract
Give side: `pinned_give_mode:'all'` with 2+ pins → every pin required (`trade_optimizer.py:515-518`). Receive side: `:522` `if pinned_recv_set and not (set(recv_ids) & pinned_recv_set)` — **any one** suffices (same in `trade_service.py:5771`, `:6089-6090`); there is no `pinned_receive_mode`. Canvas = send A, receive X+Y → A-for-X alone is served. Also: a canvas pick outside `picks_pool_cap` (default 6, `database.py:2404`) is never on `user_roster`, so `pinned_all` rejects every subset → zero cards with the wrong message ("try turning fairness off"). And the Team dropdown is ignored — `onFindATrade` writes pins only, never `setHandoff`/`setSheetOpponent`, so the sweep is not scoped to the partner the user chose.
**Fix (bright line):** add `pinned_receive_mode:'all'` through `api/trades.ts` → `server.py:11546-11558` → the three enumerators; force-inject pinned pick ids regardless of the cap (or validate pins server-side with a named reason); pass the partner as the handoff opponent.

### 7. The ✕-overlay is app-wide, not "just this version of the calculator"
`TradeCard.tsx:205` `const reasonsAsOverlay = useFlag('calc.merged_layout')` — a flag read, no origin signal. Flag on ⇒ every deck card for every user gets the overlay, the opposite of round-2 ruling 1 and plan §7 W2 ("this page only"). Checklist A5 only tests flag-off.
**Fix:** carry an "arrived from calculator" signal (a field on `useFinderTargets` set in `onFindATrade`, consumed on TradesHome focus, cleared on any other deck entry / pin clear / league switch) and pass `reasonsAsOverlay` as a prop — or get the operator to re-rule "all decks".

### 8. Auto-start has no first-visit gate, and re-entry is brittle
`TradeCalculatorScreen.tsx:131-137` starts the tour on **every** mount (no receipt, no `once`). "Back to calculator" pushes a fresh `TradeCalculator` (`TradesScreen.tsx:6290-6293`) → tour restarts. With `guide_v2` off there is no bound at all; with it on, `maxDisplayCount: 3` per beat is exhausted after three landings, after which every beat is refused, `requestAt` steps straight to `endTour('finished')`, and **"Show me around" renders but does nothing** (`calcTour.ts:83`; `useGuide.ts:356-361`; counts are never reset). Returning v1-tour testers get *one* `n*` beat per app version (`useGuide.ts:377-384`) — the spec said "including current testers". Testers who ever tapped "Skip the tour" (`guideDismissed`) never see the tour *or* the link (`calcTour.ts:93`; `TradeCalculatorScreen.tsx:630`). "Show me around" mid-tour ends the run without dismissing the active bubble, so the stale bubble lingers and the restart shows nothing (`calcTour.ts:96-101`; `useGuide.ts:388-391`).
**Fix:** record a local `calc_tour_completed` receipt in `endTour('finished')` and gate auto-start on it; let the explicit `show_me_around` path bypass/reset the per-beat cap and exempt tour beats from `v1_release_cap`; in `startCalcTour`, `dismissActiveStep` a running tour beat before re-requesting; render the link independent of `guideDismissed` (re-enable for the tour's scope).

### 9. The end-of-deck exits land in the wrong place
"Back to calculator" arrives with no params → `mode` resets to `'live'` (Real values) (`TradeCalculatorScreen.tsx:114`; draft restore only ever restores `'live'`, `:196`), an empty canvas (`InLeagueCalculator` state is not persisted), and the tour re-fires. "Search without \<player\>" renders only for `singlePin` (exactly one pin total + `trade.asset_ideas`, `TradesScreen.tsx:1263-1270`) — a 1-send + 1-receive canvas or any packageMode canvas gets no unpin path — and `handleClearPin` (`:2514-2534`) restores a snapshot only captured on the keep-side path, so from the calculator it empties the deck and does **not** regenerate. Both exits also live inside the `deck.replenishment` summary branch only (`:3413-3417`, `:6251`).
**Fix:** navigate back with the existing `prefill` shape (`{ opponentUserId, giveIds, receiveIds }` rebuilt from the pins — it already forces league mode and suppresses the auto-tour); after `handleClearPin()` dispatch `generateMutation.mutate({})`; render the unpin exit for any pin count.

### 10. Switching leagues from the new League dropdown leaves a stale canvas
`TradeCalculatorScreen.tsx:615-620` keys the component `'manual'`, not on `league.league_id`; `InLeagueCalculator` holds `opponentId/giveIds/receiveIds` in state (`:190-192`) with no `[leagueId]` effect; `playerById` resolves from the universal pool, so the old league's players still render, and `evalQ` (`:409-421`) fires the **old opponent id against the new league**. The pin store does self-clear — this is the component's local state.
**Fix:** `key={\`manual-${league.league_id}\`}` or a `[leagueId]` reset effect.

### 11. The merged layout silently drops things the spec said to keep, and the action row is not in-frame
`{!merged ? … : null}` at `InLeagueCalculator.tsx:736-853` removes the **scoring-format chips** (the #166/#167 session override), the "@user ranked in X — values converted to Y" honesty note, and the #306 partner summary / R·R*·NR explanation; the merged header adds no format control. The spec's one "important": "fits in the frame". The outlook row is a 1–2-line receipt, not collapsible (`OutlookBiasReceipt.tsx:98-119`).
**Fix:** format chips into the header (or the League row); summary line + note into the team sheet rows; render the row as a pinned footer outside the ScrollView via `setPinnedBottomBarHeight`; either build the disclosure or record the reinterpretation as a ruling.
