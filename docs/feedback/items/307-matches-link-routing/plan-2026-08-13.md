## 1. Headline

**Both items are fast-track bugs — no schema, no API change, no new flag.**

- **#308 is a copy/juxtaposition defect plus one latent cache bug, not a broken
  gate.** The fold line's gate is the server's `insufficient_data` flag from
  `/api/league/contrarian`, which counts users with stored rankings **in the
  active scoring format only** (caller included). The bar two lines above it —
  the "5 members ranked" the operator is looking at — comes from
  `/api/league/coverage`, which counts **any-format** ranked leaguemates
  (caller excluded). ffv3's five ranked members are real; fewer than three of
  them have boards in the session's active format, so the contrarian math
  genuinely can't run. The gate is *correct for its computation* (deviations
  from a community mean require comparable same-format boards); the copy lies
  about what the gate measures. Fix the copy to state the real condition with
  the server's own numbers — the insufficient payload already carries
  `ranked_users` and `needed` (`backend/server.py:14140-14148`); the client
  throws them away (`mobile/src/api/league.ts:380-382`).
- **#307 is a missing nav param, and the receiving mechanism is already live.**
  The Mutual-matches tile already deep-links to the Matches tab with a
  `segment` param that MatchesScreen consumes via a param-effect
  (`MatchesScreen.tsx:116-119`) — the FB-91 pattern, proven in production. The
  league filter is a sibling piece of plain local state
  (`filterLeagueId`, `MatchesScreen.tsx:75`) that nothing feeds from params.
  Extend the same proven pattern with a `leagueId` param. **#300's dead-path
  check done:** unlike TradesScreen's `trades.sheet_targeting` sheet-state
  flag that ignores route params, `filterLeagueId` is a bare `useState` with
  no store, no flag, and no competing writer — the chip row's `onPress`
  (`MatchesScreen.tsx:580`) is its only setter. Params are a live mechanism on
  this screen (segment proves it); there is no dead path to fall into.

Ownership note up front: `MatchesScreen.tsx` belongs to the Matches group this
wave. #307's receiving side is therefore frozen as an exact contract (§4.4)
for the orchestrator to route — this group edits only `LeagueScreen.tsx`,
`LeagueProgressModule.tsx`, `api/league.ts`, `utils/leagueUnlocks.ts`, tests,
and flows.

## 3. #308 — Leaderboards fold line vs. reality

### 3.1 Current behaviour (evidence chain)

| Step | File:line | What it does |

| Gate | `mobile/src/screens/LeagueScreen.tsx:427,822` | `showFoldLine = contrarianQuery.data?.insufficient_data === true` — pure server flag, no client recount |

| The "5" | `mobile/src/screens/LeagueScreen.tsx:393,820` → `/api/league/coverage` → `get_ranking_coverage` (`backend/database.py:6485-6495`) | Distinct users in `member_rankings` for the league, **no scoring_format filter** (any format), **caller excluded**; module renders `rankedMates + 1` with a "(you)" note (`LeagueProgressModule.tsx:116,146`) |

| Latent cache bug | `mobile/src/screens/LeagueScreen.tsx:233-239` | `queryKey: ['league-contrarian', leagueId]` omits `activeFormat` — the response varies with the session format but the 5-min cache key doesn't (the sibling `progress` query at :253 gets this right: `['progress', leagueId, activeFormat]`). A format toggle serves the other format's verdict for up to 5 minutes |

**Verdict: the bug is the copy (and its juxtaposition with a
different-population count), not the count and not the gate.**

- The gate is mathematically required: contrarian scores are deviations from a
  community mean (`server.py:14136-14137`), and boards in different scoring
  formats are not comparable. Do not loosen it.
- The count is correct for *its* purpose (any-format ranked mates drives the
  mutual-match unlock, `utils/leagueUnlocks.ts` — a deliberately different
  threshold, per the module's own header comment
  `LeagueProgressModule.tsx:22-26`).
- The copy claims a threshold ("3 leaguemates") over the population the bar
  shows. It is wrong twice: the gate's population is format-scoped (a mate
  ranked only in the other format doesn't count), and it is caller-inclusive
  ("3 leaguemates" should read "3 members" — the same caller-excluded-members
  convention family that bit the mock draft as its third victim,
  `living-memory/CHANGELOG.md:16`; here it's copy, not a query, but same
  confusion). With 5 any-format mates and <3 in-format users, ffv3 renders a
  5/N bar directly above "needs 3" — the report.

### 3.2 Fix (exact shapes)

**No backend change.** The route already returns everything needed:

```json
{"insufficient_data": true, "ranked_users": 2, "needed": 1, "format": "sf_tep", ...}
```

**(a) `mobile/src/api/league.ts` — thread the fields through** (additive,
existing consumers unaffected):

```ts
export async function getContrarianLeaderboard(leagueId: string): Promise<{
  rows: ContrarianRow[];
  insufficient_data: boolean;
  message?: string;
  ranked_users?: number;   // NEW — in-format users incl. caller
  needed?: number;         // NEW — 3 - ranked_users
  format?: string;         // NEW — echo of the format the server gated on
}>
```

Insufficient branch returns
`{ rows: [], insufficient_data: true, message, ranked_users: raw.ranked_users, needed: raw.needed, format: raw.format }`.

**(b) `mobile/src/utils/leagueUnlocks.ts` — pure copy helper** (zero runtime
imports, same idiom as the rest of the file so the node test covers it):

```ts
export const CONTRARIAN_UNLOCK_USERS = 3; // /api/league/contrarian gate, caller INCLUDED, active format only

const FOLD_FORMAT_LABEL: Record<string, string> = {
  '1qb_ppr': '1QB',
  sf_tep: 'SF TEP',
}; // mirrors TopBar's FORMAT_TILE_LABEL (TopBar.tsx:117-120) — propose pinning both in cross-client-invariants (§7)

/** Fold-line sentence for the leaderboards/contrarian unlock.
 *  needed/format come from the contrarian insufficient payload; both
 *  nullable because placeholderData can briefly serve a stale shape. */
export function contrarianFoldLine(
  needed: number | null | undefined,
  format: string | null | undefined,
): string {
  const label = format ? FOLD_FORMAT_LABEL[format] : undefined;
  const where = label ? ` in ${label}` : '';
  if (needed == null || needed <= 0) {
    return `Leaderboards and contrarian ranks appear once ${CONTRARIAN_UNLOCK_USERS} members have ranked${where}.`;
  }
  return (
    `Leaderboards and contrarian ranks appear once ${CONTRARIAN_UNLOCK_USERS} members ` +
    `have ranked${where} — ${needed} more to go.`
  );
}
```

"Members" (not "leaguemates") is deliberate: the gate counts the caller, and
the bar above already labels its own count "(you)". The format clause is what
dissolves the ffv3 contradiction: "…once 3 members have ranked in SF TEP — 1
more to go." sits honestly under a 5/12 any-format bar.

**(c) `mobile/src/components/LeagueProgressModule.tsx` — dynamic fold line:**

```ts
/** Fold-line inputs from the contrarian insufficient payload. */
foldNeeded?: number | null;
foldFormat?: string | null;
```

Line 215-218 becomes `{contrarianFoldLine(foldNeeded, foldFormat)}` (import
from `../utils/leagueUnlocks`). Add `testID="league.progress-foldline"` to the
fold `Text` for flows. `showFoldLine` semantics unchanged; compact variant
still never renders it (`MatchesScreen.tsx:658-667` passes neither prop).

**(d) `mobile/src/screens/LeagueScreen.tsx` — two edits:**

- `queryKey: ['league-contrarian', leagueId, activeFormat]` (:234) — the
  latent staleness fix; `activeFormat` is already in scope for the `progress`
  key at :253.
- Pass the new props at :817-830:
  `foldNeeded={contrarianQuery.data?.needed ?? null}`
  `foldFormat={contrarianQuery.data?.format ?? null}`.

Chalkline: no visual change — same `styles.foldLine` token usage, text only.
