### Persistent sessions (teardown 06-03 P3, flag `auth.persistent_sessions` — W3B)

Sessions live in an in-memory dict (the hot path). With the flag ON, **verified** sessions additionally get a durable row in the `sessions` table (token stored as a SHA-256 hash) and are transparently **rebuilt from that row** on a memory miss — so deploys/restarts and the 4h idle memory sweep no longer sign out account-anchored users. Mechanics:

- **Who persists:** only sessions with `verified=True` (Sleeper-JWT proof or an Apple/Google anchor), never demo sessions. Username-only **unverified** sessions stay memory-only on purpose: their 4h idle TTL + restart loss bounds the squatting window (anyone can mint a session by naming a Sleeper username), and persistence must not extend it.
- **Expiry:** rolling **90 days** idle for persisted sessions (heartbeat refresh throttled to ≥10 min between DB writes; checked at read time and purged by the cleanup loop). Unverified sessions keep the 4h posture exactly.
- **Restore shape:** `acct_*` sessions rebuild fully (account-only empty-league session — immediately usable). Sleeper-keyed sessions rebuild user-scoped (rankings work; league-backed routes 409 `session_not_initialized` until the client's normal `/api/session/init` re-handshake, which reuses the same token and keeps its verified state).
- **Evictions delete durable rows too:** `/api/session/signout` (own token), `DELETE /api/account` (all rows for the user), `POST /api/account/link-sleeper` (the migrated `acct_*` working key's rows), `DELETE /api/test-users/<id>`, and a token re-pointed at a different user in `/api/session/init`. Verified-owner lockout of squatters is denial-based (per-request read/write gates), not eviction-based — and squatter sessions are never persisted, so no row exists to clean.
- **Flag OFF:** no rows written, no DB fallback on miss — byte-identical legacy behavior (in-memory only, 4h idle, lost on restart).

### Verified sessions & the write gate (account-auth P1)

A session is **verified** when the app captured a Sleeper JWT whose `user_id` claim matches the session's user **and** the token was proven live against Sleeper's authenticated GraphQL API (`sleeper_write.verify_token_live` — Sleeper is the signature oracle, since the JWT's HS256 signature can't be checked locally). Verification happens in `POST /api/sleeper/link`; it stamps `sess["verified"]` and persists `users.verified_at`/`verified_via='sleeper'` (shared with P2's Apple/Google anchors).

Every mutating user route (`rank3`, `reset`, `rankings/reorder`, `rankings/import-apply`, `rankings/submit`, `tiers/save|copy-from-format|dismiss`, `anchor/save|scale`, `ranking-method`, `scoring/switch`, `trades/swipe|generate|flag|pass-reason|queue`, `trades/matches/*/dismiss|disposition`, `league/preferences|asset-prefs|scoring`, `notifications/read|read-all|dismiss-all|register-device|prefs`, `feedback`, `sleeper/link` DELETE) runs the gate (`@_gate_unverified_write`):

| Caller | Result |
|---|---|
| Verified session | allow |
| Unverified, user_id has a verified controller (`users.verified_via` set) | **403 `{error: verification_required}`** — first-verified-controller-wins, even during grace |
| Unverified, no controller, grace (`auth.enforce_verified_writes` false) | allow + one `AUTH-GRACE` log line (runbook monitors the funnel) |
| Unverified, no controller, enforcement on | **403 `verification_required`** |

Hard-verified regardless of grace: `POST /api/sleeper/link` (carries its own proof — see Send in Sleeper below), `POST /api/trades/propose`, `POST /api/trades/propose-mfl`, `POST /api/trades/respond-mfl`, `POST /api/account/reset-rankings`.

### The read gate (account-auth P2.5 — read privacy)

"Ranks hidden behind an account" (#102) covers reads too: the write gate alone still let a username-only session *view* the victim's board. Board-content READ routes run `@_gate_unverified_read`, which mirrors **only** the write gate's verified-controller branch:

| Caller | Result |
|---|---|
| Verified session | allow |
| Unverified, user_id has a verified controller (`users.verified_via` set) | **403 `{error: verification_required}`** — no grace: the owner has proven control, squatters get nothing (`AUTH-DENY unverified_read` log line) |
| Unverified, no controller | allow — onboarding users must see their own board, so `auth.enforce_verified_writes` is deliberately **not** consulted for reads |

**Gated reads** (the user's own board / board-derived content): `GET /api/rankings`, `/api/progress`, `/api/rankings/progress`, `/api/me/streak`, `/api/tiers/status`, `/api/tiers/community-diff`, `/api/tiers/stability`, `/api/anchor/scale` (GET side; POST side keeps the write gate), `/api/trades`, `/api/trades/status`, `/api/trades/liked`, `/api/trades/matches`, `/api/trades/matches/all`, `/api/trades/awaiting`, `/api/league/preferences` (GET), `/api/league/asset-prefs` (GET), `/api/league/free-agents` (priced by the caller's board — #143), `/api/draft/board` (flag `draft.room` — blanket decorator, **deliberately tighter than the `power-rankings` inline precedent**: see the note under [Draft room](#draft-room-flag-draftroom)), `/api/feedback/mine`, `/api/notifications`, `/api/trends/risers-fallers`, `/api/trends/contrarian`, `/api/trends/consensus-gap`, `/api/extension/rankings`, plus **Mode B of `POST /api/trade/evaluate`** (gated inline — it prices by the caller's board; Mode A stays public).

**Deliberately left open** (documented decisions, not omissions): `/api/trade/values` + `/api/trade/evaluate` Mode A (public calculator by design), `/api/tier-config` (global band table, no user data), `/api/leaderboard` (community content; `is_self` tagging only), `/api/trio` + `/api/skips` (onboarding surface — the trio/skip list doesn't expose the board's ordering), `/api/portfolio` (Sleeper-public roster exposure, no Elo), `/api/leagues`, `/api/league/summary` (counts of the caller's matches, no content), `/api/league/coverage|members|member-unlock-states|activity|contrarian|format-stats` (league-shared aggregates by design), `/api/league/rank-chip` (consensus-basis power rank only — league-shared consensus values, no personal/board data, same class as `/api/league/summary`), `/api/market/movers` (universal-pool consensus value trend — no user/board/league content, same class as `/api/tier-config`; flag `market.movers`), `/api/notifications/prefs` GET (settings toggles, not board content), `/api/session/init` + `/api/session/ping` + `/api/sleeper/link` GET (must work for unverified sessions — they drive the verify prompt itself), `/og/*`, `/s/*`, `/u/*`, `/api/profile/*` (public share surfaces by explicit product design).

**Client contract:** the mobile API client (`mobile/src/api/client.ts`) treats any 403 `verification_required` as a central signal — it flips `useSession.verification` so the existing `VerifyAccountBanner` appears; gated screens' load-error states show "Verify your account to view your data." **Known limitation:** web + extension clients have no verification flow yet, so once an owner verifies on mobile, their own username-only web/extension sessions read-403 until those clients grow a capture path (same asymmetry the write gate already has).

### `/api/session/init` — league identity (co-owned rosters)

Two optional, additive body fields, both defaulting to the caller's own values.
A client that omits them is byte-identical to pre-2026-08-15 behavior, so old
binaries are unaffected.

| Field | Meaning |
|---|---|
| `league_user_id` | The caller's **league identity**: the `owner_id` of the Sleeper roster they own **or co-own**. Equals `user_id` for a sole owner. |
| `league_display_name` | That owner's Sleeper display name. |

Sleeper rosters carry an optional `co_owners` array, and a co-owner is an
**alias** of the roster's primary `owner_id` within that league — never a
separate team. `league_members` is a league-**shared** table (every member's
session_init writes into it), so keying the caller's row on `league_user_id` is
what makes a co-owned roster land on exactly one row whichever co-manager syncs
it. Keying it on the caller instead gives a 12-team league 13 rows with one
roster duplicated, and the DB-member merge then hands the trade engine a
phantom copy of the caller's own team.

The caller's own `user_id` remains their **account identity** and still governs
everything account-scoped: rankings, swipes, tier overrides, entitlements,
analytics, notifications, feedback. Server-side the two are read via
`server._league_user_id(sess)` and `sess["user_id"]` respectively; the
predicate lives in `backend/sleeper_roster.py` and is mirrored in
`mobile/src/api/sleeper.ts` + `web/js/app.js`. Sleeper only — ESPN / MFL /
Fleaflicker have no co-owner concept and their builders omit both fields.
Background: `docs/plans/sleeper-co-owner-rosters/scope.md`.

`/api/session/init` response — additive field:

```
"verification": {
  "session_verified": false,   // THIS session proved control
  "user_verified":    false,   // some controller has verified this user_id
  "verified_via":     null,    // 'sleeper' | 'apple' | 'google' | null
  "enforced":         false    // auth.enforce_verified_writes (grace over)
}
```

## Account auth (identity anchors — `auth.accounts` flag, ships dark)

Account-auth plan P2 + P2.6 account-first (docs/plans/account-auth-plan-2026-07-11.md). Logic in `backend/accounts.py`; routes are thin wrappers. **P2.6:** the account is the primary identity — an account with no linked Sleeper source works under the synthetic key `acct_<account_id>` (rank/tiers/anchors fully functional; league features empty until a source is linked).

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/auth/apple` | Verify a Sign in with Apple identity token (JWKS RS256 + iss + aud=`com.fantasytradefinder.app` + exp). Find-or-create the account, then: with a session → bind the session's Sleeper user + mark session `verified_via='apple'`; no session + bound account → device-loss restore (returns `session_token`); no session + new account → **account-first (P2.6)**: mints an account-keyed session — `{account_only:true, session_token, user_id:"acct_<account_id>", league_id:"no_league"}` — with per-format ranking services and a real EMPTY league (never the demo fallback). Optional body `display_name` (Apple sends the name only to the client, first auth only). Binding is sticky — a session for a different user gets `conflict:true`, never a rebind; `acct_*` keys are never bound as Sleeper sources. 404 while flag off. |
| POST | `/api/auth/google` | Same flow, Google JWKS + `GOOGLE_OAUTH_CLIENT_ID` as `aud`. 503 `not_configured` until that env var is set. 404 while flag off. |
| GET | `/api/account` | Current account: `{sleeper_user_id, verified_via, account: {account_id, sleeper_user_id, identities:[{provider, linked_at}]} \| null, account_only, sleeper_username}`. 404 while flag off. |
| POST | `/api/account/link-sleeper` | **P2.6.** Link a Sleeper username as a source on the session's account. Body `{username, strategy?}`; requires `sess.account_id` (400 `no_account`). Rules: sticky binding (409 `sleeper_conflict` if bound elsewhere); **first-verified-wins** — target id already has a verified controller → 403 `sleeper_already_claimed`, no takeover; both boards have data and no `strategy` → 409 `merge_choice_required` + `{account_board, sleeper_board}` summaries; `strategy='keep_sleeper'` wipes the account board, `'keep_account'` wipes the Sleeper board and migrates the account board in; account-board-only → migrated automatically. On success: binds, marks the Sleeper user `verified_via=<provider>`, evicts the `acct_*` sessions, returns a fresh session for the Sleeper user `{session_token, user_id, username, merge}`. 404 while flag off. |
| GET | `/api/account/export` | **Data export (teardown 06-02, flag `account.data_export`; 404 while dark).** JSON archive of every user-keyed row — the deletion matrix in `accounts.delete_user_data` is the manifest (same table set, plus the user's side of `trade_matches` and the account/identity rows; `sleeper_credentials.token_encrypted` excluded). Same gates as deletion: 400 `demo_session`; verified user + unverified session → 403 `verification_required`. → `{export_version, exported_at, user_id, tables:{...}}` with a `Content-Disposition: attachment` hint. |
| DELETE | `/api/account` | **In-app account deletion (App Store 5.1.1(v)) — NOT flag-gated.** Deletes/anonymizes per the matrix in `accounts.delete_user_data` (honors `web/privacy.html` §6): own rows deleted; shared rows (trade matches, others' impressions/flags naming this user) anonymized so counterparties keep their records; feedback anonymized; non-user-keyed aggregates kept. If `users.verified_via` is set, the calling session must itself be verified (403 `verification_required` otherwise). Evicts all of the user's live sessions. **SIWA revocation (teardown 06-02, unflagged):** when a linked Apple identity exists, best-effort revoke via Apple `/auth/token` + `/auth/revoke` — requires env `APPLE_TEAM_ID`/`APPLE_KEY_ID`/`APPLE_PRIVATE_KEY` plus a fresh `apple_authorization_code` in the optional request body; failures are logged and never block local deletion. Response gains additive `apple_revoked: bool`. |

## Ranking — Trio

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/trio` | Next 3-player matchup. Generic pick rungs carry the same year-explicit `name` / `pick_value` `/api/rankings` serves (#207 — see that row) so a rung reads identically in a matchup and on a board. **Rookie scope (flag `ranks.rookie_subset`, 2026-08-06):** optional `?scope=rookie` narrows the response to the current rookie class — a POST-Elo VIEW filter applied immediately before serialization, so every value, tier and rank magnitude is the one the full board carries (the pool, the Elo computation and every write lane stay full-pool; filtering the pool would drop rookie-vs-vet swipes and fork the Elo space — see [ADR-009](adr/adr-009-rookie-scope-view-filter.md)). Players only — generic pick rungs are NOT in scope (operator decision O10). `rank` is renumbered 1..n over the filtered list; no other field changes. A thin or unloaded class is a typed **200** `{empty:true, reason:"thin_pool"|"class_not_loaded"|"stale_player_cache", position, scope:"rookie", count}` — never the unscoped path's 400. Unknown `scope` values ⇒ `400 {"error":"bad_scope"}`. **Flag off ⇒ the parameter is never read**, so responses are byte-identical to today. Under scope the subset constrains **candidate selection only** (via the existing `skipped_player_ids` channel) — the Elo updates a user's picks produce are unchanged full-board updates. Two lanes that channel cannot constrain are disabled under scope: the `cross_pos` trio variety and the `swipe.qc_compliments` QC trio, both of which reach across the full pool by design |
| POST | `/api/trio/skip` | Skip current trio |
| POST | `/api/rank3` | Submit ordered (best→worst) result |
| POST | `/api/rankings/submit` | Publish the **session user's** ELO snapshot to `member_rankings` (optional body `league_id`; a body `user_id` is ignored — teardown W2C closed the S6B-01-class override that let any session upsert another user's published rankings) |
| POST | `/api/rankings/reorder` | Manually reorder ranks |
| POST | `/api/rankings/import-match` | **#232 follow-on (2026-08-02), flag `ranks.import` (404 while off).** Paste-first rankings import, step 1: body `{names: [line, …]}` (the pasted table's lines; a raw `{text}` blob also accepted, split on newlines; max 500 rows) + optional `scoring_format` (else X-Scoring-Format header → session active format). Each line runs the tolerant extractor (`backend/rankings_import.py`): accepts "rank. name", bare names, TSV/CSV rows (name in any column), space rows with trailing POS/TEAM codes; header + numbers-only lines are dropped. Fuzzy match vs the format's **universal pool**, normalizing case/punctuation/suffixes (Jr/Sr/II–V) + "K. Walker" initial forms. Returns `{rows: [{input, name, status: matched\|ambiguous\|unmatched, player, candidates(≤3, consensus-best first)}], counts, scoring_format}`. ### Pick assignment (flag `picks.assign`, ships dark — W3 M-A, [ADR-010](adr/adr-010-user-asserted-pick-ownership.md))

User-asserted pick **ownership** for a league whose platform has no readable draft object. ESPN has no rookie-draft concept (operator ruling), so an ESPN dynasty league's rookie draft necessarily runs off-platform and there is **no draft object to read, now or ever** — its own members are the only possible source.

All three routes 404 `feature_disabled` **before any session work** while the flag is off, carry the verified-session gates, resolve the actor as the session user (**a body `user_id` is ignored** — the teardown S6B-01 precedent), and assert league membership server-side against `league_members` (403 `not_in_league`).

**No user-entered values, ever.** Price comes only from the shipped `pick_values.pick_pool_value` / `database.compute_pick_value`. Any body carrying `value` / `pool_value` / `pick_value` / `elo` / `price` / `values` is refused with **400 `values_not_accepted`** — a loud refusal, never a silent ignore. Because of that, plus the fixed `rounds × teams × seasons` grid over existing `league_members`, **a bad or malicious assignment can redistribute value but can never create it**; `rounds` is clamped server-side to `ROOKIE_MAX_ROUNDS` (8), which is the bound's only lever.

Asserted picks do **not** reach trade math under this flag — every existing read site still takes `load_draft_picks`' platform-only default. Lighting them up is M-C's separate `picks.assign_tradeable` switch, so pick math can be killed without destroying the rows a league typed in.

#### Trade-math activation (flag `picks.assign_tradeable`, ships dark — W3 M-C)

The second, deliberately separate switch. **ON ⇒ assigned picks behave exactly like any other league's picks** (operator decision 4 — full engine parity): all **seven** read sites read the platform ∪ asserted union instead of the platform-only default —

| Stage | Read site | What the user gets |

| S1 | `GET /api/league/picks` · `POST /api/trade/evaluate` | sees and prices their picks in the calculator |
| S2 | `GET /api/league/power-rankings` (`_power_picks_by_owner`) · the own-outlook seed (`_user_pick_share`) | draft capital in standings; a truthful contend/rebuild window |

S1→S4 was the **build sequence** (each site golden-diffed on its own); all four land together behind the one flag.

**OFF ⇒ byte-identical on every one of those payloads**, and asserted rows reach no trade math, no power rankings and no suggestion.

Three contract details clients must not paraphrase (registered in [cross-client-invariants.md](cross-client-invariants.md)):

- **`source: "platform" | "user"`** rides every payload that prices a pick — `/api/league/picks` rows, `/api/trade/evaluate` `per_player` entries for pick ids, `eveners[]` pick items (and any combo containing one), and `power-rankings` `picks.items[]`. - Payloads that did not already carry them gain **`season`** (and `pick_id`, on power-rankings items) alongside `source`, because the client's one-action correction deep link is `{leagueId, season, focusPickId}` and a badge without a season is a dead end.
- **`picks_supported` is a DATA test, not a platform test:** `platform != "espn" or the league has assigned rows`. An ESPN league with nothing assigned still honestly reports `false`. The demo / no-league early return keeps the platform test.

**Contested and orphaned slots are excluded from the priced union by ROW FILTER**, never by nulling `pool_value` — the power-rankings path re-derives a price from a NULL, so nulling would silently re-price the exact row the rule withholds. They stay visible on `GET /api/league/pick-assignments`, which is the screen where they get fixed.

### Live offline pick recording (flag `draft.manual_picks`, W3 M-D)

Records what actually happened during a real off-platform (offline) rookie draft — the last piece of ESPN pick assignment, sequenced after M-A/M-B/M-C so recording can lean on an already-assigned grid. Storage is the new `recorded_picks` table ([data-dictionary](data-dictionary.md#recorded_picks)) — **never `draft_picks`, never `leagues.draft_status*`**. `(league_id, season, overall)` is the idempotency key; the client's offline write queue (`mobile/src/api/_queue.ts`, extracted from `events.ts`'s battle-tested contract) replays through it on reconnect. Any linked league member may record — there is no designated-recorder role. Both routes 404 `feature_disabled` before any session work while the flag is off, and `GET /api/draft/board`'s ESPN branch reads **zero** rows from the table regardless of what it holds — the flag gates the read, not only the writes.

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/league/recorded-picks` | Batch record (≤50/request, mirroring the client queue's `BATCH_MAX`). Body `{league_id, season, picks:[{event_id, overall, round, slot, picking_team_id, player_id, client_ts}]}`. → `200 {accepted, deduped, rejected:[{index, reason}]}` — the **same reconciliation shape** `mobile/src/api/events.ts` already parses. `reason` ∈ `slot_out_of_range \| unknown_player \| not_in_league`. Per-row classification against the existing row at that `overall`: no existing row → insert; existing **live**, same `player_id` → `deduped`; existing live, different `player_id` → UPDATE in place (a correction); existing **voided**, any `player_id` → UPDATE in place, revived (`voided_at` reset to `NULL` — re-recording a voided pick reverses an undo). Errors: 404 `feature_disabled` / `league_not_found` / `pick_not_found` (nothing live at that slot) · 400 `league_id is required` / `season is required` / `overall is required` · 403 `not_in_league` |

`GET /api/draft/board`'s ESPN branch (above) projects live `recorded_picks` rows into `picks[]` (`{round, pick_no, slot, player_id, name, position, team, picked_by_user_id, picked_at}` — `pick_no` is the recorded `overall`) and subtracts them from `undrafted[]`, through the SAME `assigned_board` renderer every other platform's board uses — no second source of truth. `state` becomes `"live"` once ≥1 pick is recorded and `"complete"` once every `order[]` slot has one.

**Off-by-one recovery: manual-cursor-only, no auto-shift.** The mobile recording screen auto-advances its cursor after each tap, but a missed or out-of-order pick is recovered by tapping the correct slot directly — there is no "insert a skipped pick" shift-everything-after mode. `overall` is derived from the assignment grid's own `pick_no` (never a client-side formula), so the cursor and the server can never disagree about numbering.

MFL boards are built from `TYPE=draftResults` (see [MFL league linking](#mfl-league-linking-flag-mfllink)); an expired MFL cookie serves the stored snapshot with `notice.mfl_reconnect` + `stale:true`, **never stale-as-live**. **MFL identity is resolved server-side, never left as an id (#289).** `order[].owner_username` comes from the stored `league_members` row for the franchise's user id (`username` → `display_name`), falling back to `Team <franchise_id>`; note that an uncrosswalked MFL id may coincide with an unrelated Sleeper id, so it is never used as a `players` lookup key. `original_user_id`/`original_username` remain `null` for MFL — the grid states current ownership only. **MFL live mode is release-gated:** a drafting MFL league reports `state:"live"` honestly, but MFL's mid-draft update latency is unverified, so recurring refresh stays behind `draft.live_poll` until the timed probe in [build-m5](plans/rookie-draft/build-m5.md#the-live-probe) passes — flipping `draft.mfl` on starts no poll. **ESPN behind `picks.assign`** (W3 M-B, [ADR-010](adr/adr-010-user-asserted-pick-ownership.md)) — ESPN has no rookie-draft concept, so there is no draft object to read, now or ever, and the room is built entirely from the league's **assignment grid** with **ZERO platform egress in every state**. Three states: flag OFF ⇒ the byte-identical `platform_unsupported` payload below; flag ON with nothing assigned ⇒ `state:"unavailable"` + `notice.picks_not_assigned` (an **unconfigured state with a user-performable fix**, never an error — the CTA routes to the League tab's pick-assignment screen); flag ON with assignments ⇒ a real board (`state` `"upcoming"`/`"live"`/`"complete"` depending on how many slots are recorded), `order_confidence:"assigned"`, order and `type` (linear/snake) from the grid, `picks: []` unless `draft.manual_picks` is ALSO on and picks have been recorded (see [Live offline pick recording](#live-offline-pick-recording-flag-draftmanual_picks-w3-m-d) — an off-platform draft otherwise leaves no record we can read), the full rookie class undrafted minus whatever is recorded, and `deep_link: null` (no ESPN draft room exists to link to). `build_board` is unreachable for ESPN — the branch precedes it — so its behavior is untouched. Fleaflicker and every other platform still return `state:"unavailable"` + `notice.platform_unsupported`. Errors: 404 `feature_disabled` (flag off, checked before any session work) / `league_not_found` · 400 `league_id is required` / `bad_basis` / `bad_mode` · 401 · 403 `verification_required` · 409 session not initialized |

**Upstream budget.** The service polls Sleeper's 1.2 KB draft-detail object (`s-maxage=30`) and fetches the ~20 KB pick list **only when `last_picked` moves** — polling `/picks` directly reads the ~24 h CDN cache of a complete draft while believing it is live. Per-draft shared TTL cache (20 s live / 5 min pre-draft / 24 h complete / 60 s unavailable) with per-key single-flight, so N viewers of one draft cost ≤1 upstream read per TTL, hard-capped at 3 upstream cycles per rolling 60 s, with a 3-failure/120 s circuit breaker (D6).

**Client polling** is a separate flag, `draft.live_poll`: the mobile Draft Room refetches **our** endpoint every 15 s, and only while focused + foregrounded + `state == "live"`. Blurred or backgrounded is **zero** requests. Manual Refresh is present either way.

**Read gate — recorded divergence.** `/api/draft/board` carries `@_gate_unverified_read` wholesale, per the plan. The nearest precedent, `/api/league/power-rankings`, applies the gate **inline for `basis=personal` only**, because its consensus output is a league-shared aggregate. The blanket decorator therefore gates the consensus board more tightly than that precedent. This is deliberate, not an oversight.

**State payload** reuses the Draft Room's `schema: 1` vocabulary verbatim so the same render components serve both: `{schema, mock_id, status, league_id, season, on_the_clock: {pick_no, round, slot, roster_id, is_user}, order[], picks[], undrafted[], undrafted_basis, my_picks[], settings_echo, notice}`. `order[]`/`undrafted[]` entry shapes are exactly the board's; `picks[]` adds one field, `by` ∈ `user`\|`cpu`. `status` ∈ `active`\|`complete`\|`abandoned`. `settings_echo` carries `{rounds, type, teams, order_source, ownership_source, personas, noise, consensus_pool_size, mode, user_owner_id}` — `order_source` is `assigned` only when a real platform order was resolved, `randomized` otherwise, and it is **never** an invented "real" order. `ownership_source` (#328) is the provenance of the traded-pick ownership overlay: `"platform"` (platform-stated — Sleeper board / MFL store — covering every slot of this mock) \| `"user"` (the ESPN manual assignment grid, user-asserted, full coverage) \| `"partial"` (ownership data applied but **not** covering every `(round, slot)` — rounds beyond grid/store depth, contested/orphaned exclusions, identity-dropped rows; uncovered slots draft at slot order) \| `"none"` (no ownership data applied; every team drafts its own slot) \| `null` (the row was persisted before the label existed — clients treat `null` as **unknown**, never as `"none"`). Closed vocabulary server-side, open + nullable client-side ([cross-client-invariants](cross-client-invariants.md)). `mode` is present on every state payload (rows persisted before #305 echo the effective value, `cpu`) and is the **only** source of mode truth — clients must never infer mode from `by` values, pick cadence, or `on_the_clock`. `user_owner_id` is the caller's team id in this draft — the join key for "my team" (`my_picks`, ticker highlight): in manual mode every pick is `by: "user"` while `picked_by_user_id` walks the order, so keying "my team" off `by` is wrong in exactly the mode that needs it.

**`picks[]` entries** (W2d): the board's pick shape plus `by` ∈ `user`\|`cpu` and three recap fields — `consensus_rank` (the player's 1-based position in the **frozen pre-draft** consensus pool, so a delta does not move as later picks come off the board), `consensus_delta` (`consensus_rank − pick_no`, signed in the ADP convention: **positive = went later than the consensus said** i.e. value, negative = a reach) and `valued` (false for a D7 unvalued rookie). `consensus_rank` and `consensus_delta` are **`null`**, never `0`, when the consensus cannot place the player — the client must render "no consensus value" rather than an even delta. `settings_echo.consensus_pool_size` is the denominator for "12th of 79". **`tier`** (#323, additive under the plan-D10 open-payload convention — `schema` stays 1, and `my_picks[]` entries carry it too since they are the same dicts): `string | null`, exactly the 8-rung cross-client Tier ladder (`firsts_4plus` … `waivers`, [cross-client-invariants](cross-client-invariants.md)), computed at payload-build time via `RankingService.tier_for_elo` over the pick's **consensus** Elo + position + the league's scoring format. **Consensus-denominated always** — it does NOT switch to the user's board under `basis=my_board` (a pick's tier is a property of the pick, stable across basis toggles and across reads of the same mock). `null` when the player has no consensus Elo (the `valued: false` rows) or sits below the `waivers` floor — `null` means "show no tier", never a fabricated one; clients treat an absent key (pre-change server) identically to `null`.

**Resolution inputs (W2d, per-platform since #328).** The create route resolves all four of the engine's inputs from the league's real data, per platform, with **zero platform egress on the ESPN/MFL paths** (both read only our DB): **Sleeper** — `order` and the traded-pick `ownership` overlay from the **same `draft_board_service` board the Draft Room renders** (cached, single-flight, budgeted — the mock costs no read the room has not already paid for) ⇒ `ownership_source: "platform"`. **ESPN** (behind `picks.assign`, the board route's own gate) — the same `_assignment_grid`/`assigned_board` the ESPN Draft Room renders: the stored round-1 assignment order (`order_source: "assigned"`), the grid's linear/snake `order_type` as the mock's default `type`, and the user-asserted traded picks ⇒ `ownership_source: "user"`. **MFL** — no slot sequence exists to read (KD-6: never invent an order), so the order stays a seeded shuffle labelled `randomized`, but the traded-pick overlay is read from the normalized `draft_picks` store and **anchored to the original owner's shuffled slot** ⇒ `ownership_source: "platform"`. Everything else (Fleaflicker, unlinked, flag off, unseeded grid, empty store) falls back to slot-order drafting — **labelled `"none"`, never silent**; incomplete coverage is labelled `"partial"` with the applied rows still applied. A resolution failure degrades to the labelled fallback and never blocks creation. `personas` are unchanged: each member's stored `league_preferences.team_outlook`, falling back to `trade_service.infer_team_outlook` and then to `not_sure` (`declared` > `inferred` > `default`).

**Capability probe (W2d).** `GET /api/mock-draft` with no active mock returns `capability: {can_start, reason, teams, min_teams, rounds_default, rounds_max, type, order_source}` so a client can render a **disabled** entry state without POSTing a create to discover the refusal. `reason` is `null` when `can_start` is true, otherwise the same string the create route's typed-empty would carry, off one shared refusal ladder (`mock_draft_service.start_refusal`): `class_not_loaded` → `cpu_model_unvalidated` → `league_too_small` → `user_not_in_draft`. The probe reads the DB and the process pool only — no platform call. `type`/`order_source` are deliberately absent (resolving them needs the board), and **`ownership_source` is deliberately absent for the identical zero-egress reason** (#328, HD-6) — the probe payload is byte-identical to its pre-#328 shape. `min_teams` is `MOCK_MIN_TEAMS = 4`; below it a "mock" is too thin to simulate a draft, and `league_too_small` is returned rather than a 2-team board. `user_not_in_draft` (last — least actionable) means the session user could not be placed in the resolved draft. The shared ladder checks membership in `owners`; `build_settings` independently raises `UserNotInDraft` for the case the ladder is structurally blind to (the user is an owner but the platform's assigned order does not name them — e.g. a co-owner id), and the create route maps the raise to the identical typed-empty, so a born-broken mock can be refused but never persisted and clients see one vocabulary. To prefill a linear/snake setup toggle from the real draft, read `type` on `GET /api/draft/board` (W2d added it; `null` when the platform states no shape we recognise — never a guess).

**One consensus definition (binding).** CPU drafters rank candidates through `draft_board_service._undrafted(basis="consensus")` against the same `_get_universal_pool()` seed the Draft Room gets. The user's own board (`basis=my_board`) re-sorts **only the user's own undrafted list** and never enters a CPU decision — otherwise every mock would read the user's rankings back to them, and the room's undrafted order and the bots would visibly disagree on one screen.

**Determinism.** `rng_seed` is stored on the row and the per-pick stream is `Random(rng_seed * 10007 + pick_no)` — a pure function of `(seed, pick_no)`, never of call order, so a resumed mock replays byte-identically. The fitted noise parameters are snapshotted into `settings.noise`, so retuning `model_config` cannot change an in-flight mock.

**No polling.** The mock only changes when the user acts, so this surface never touches the `draft.live_poll` refetch machinery.

Errors: 404 `feature_disabled` (flag off, checked **before any session work**, on all four routes) / `league_not_found` / `mock_not_found` (also returned when the row is not the caller's) · 400 `league_id is required` / `bad_basis` / `not_rookie_draft` (rounds outside 1–`ROOKIE_MAX_ROUNDS`) / `player_unavailable` · 409 `not_your_turn` · 401 · 403 `verification_required` · 409 session not initialized. Typed-empty `200 {"schema": 1, "empty": true, "reason": …}` for `class_not_loaded`, `no_active_mock`, `cpu_model_unvalidated` `league_too_small` and `user_not_in_draft` — new states ride this field rather than a new member of any closed client enum.
