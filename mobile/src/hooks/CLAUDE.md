# mobile/src/hooks/

Custom React hooks. Currently:

- `usePushNotifications.ts` — registers Expo push token, wires foreground/background handlers; with flag `notif.tap_routing_v2` also consumes `useLastNotificationResponse` for cold-start taps (deduped vs. the live listener) and routes kinds via `utils/deepLinks.resolveNotificationTarget` (adds `bundle_summary`, passes `match_id`) — flag off = legacy inline kind sets exactly (teardown S5 PRD-02)
- `useScoringFormat.ts` — SF/1QB scoring format: league-driven default applier (`useLeagueFormatDefault`, mounted in RootNav) + explicit toggle hook (`useScoringFormat`, used by Tiers/Trios)
- `useRecoverOnResume.ts` — refetches an errored query once app-resume session revalidation mints a fresh token (zustand `hasToken` set) or on foreground resume; fixes queries that 401 during the revalidation race and would otherwise stick in error (staleTime: Infinity screens, e.g. Anchors — #121/#125)
- `useReducedMotionSafe.ts` — `useFlag('a11y.reduce_motion') && Reanimated useReducedMotion()`; flag off → always false (teardown S2 PRD-02)
- `useAppActive.ts` — `true` while `AppState === 'active'` (foreground). Added for the Draft Room's live poll (rookie-draft M4): `useIsFocused` alone doesn't cover backgrounding — a focused screen stays focused when the user swipes home — and that poll's QA threshold is literally ZERO requests while backgrounded. `'inactive'` (app switcher, Control Center) counts as NOT active on purpose: the worst case is one skipped tick
- `useWhatsNew.ts` — flag `ux.whats_new`: version-keyed what's-new entry (Constants.expoConfig.version → in-file `WHATS_NEW` map), shown once per version (AsyncStorage `ftf_whats_new_seen_version`); anchor = ONE CoachMark-style inline tip in LeagueScreen, never a modal. Adding a release note = one map entry alongside the app.json version bump (teardown S7 PRD-04)

- `usePresentationSignals.ts` — the impression/outcome spine for the presentation-v2 surface (flag `trades.presentation_v2`). **Parity with the deck is enforced by REUSE**: it calls the same exported `swipeTrade(card, decision, signal)` and `postDeclineReason(...)`, imports `SwipeSignal` as a type rather than redeclaring it, and emits the same event names (`deck_card_viewed`, `trade_pass_layer1`, `trade_pass_layer2`) with the same properties. A hand-rolled HTTP call here would silently fork the dataset every downstream re-ranker depends on — `mobile/tests/check-presentation-v2.js` §4 asserts there is none.
- `usePresentationDeck.ts` — read-only deck fetch for the same surface. Resolves `fairness_threshold` through the SHARED `fairnessOnFromPref`/`fairnessThresholdFor` helpers so it lands in the deck's server job-cache slot instead of kicking a second generation, and never sends `force`.

- `useMyRosterAssets.ts` — the caller's roster as roster-first setup counts it: player ids via `findMyRoster` (owner or co-owner) on `['league-rosters', id]` plus owned pick ids on `['league-picks', id]` (both shared cache keys). A picks failure degrades to no picks, never to no roster.

- `useRosterSetupPassTrigger.ts` — roster-first setup's ONLY automatic entry (flag `trades.roster_setup`; operator amendment 2026-11-10): returns a stable function TradesScreen calls at the committed-pass points (plain pass in `advance()`, the undo-held pass's timer, and after each `commitReasonAdvance()` caller once the reason capture closes); it pushes `RosterSetup {entry:'first_pass'}` when `utils/rosterSetup.shouldPushSetupOnPass` holds (flag, non-demo, store hydrated, no device record, non-empty roster, once per league per app session). Never touches the pass itself.

- `usePassReasonCadence.ts` — the React half of `utils/passReasonCadence.ts` (flag `trade.pass_reason_cadence`). `TradesScreen` calls `record(decision)` once in `advance()` and spreads `cardProps` into its reason props; flag off ⇒ `record` is inert and `cardProps` is `{}`. N/M come from `api/flags.fetchedPassReasonCadence()`. `onShown` (the why-pass frame opened) marks the card so `record` knows the ask was spent; a like or a swipe on an armed card whose frame never opened carries the ask to the next card. Fires `pass_reason_prompt_shown` / `_dismissed`. State is per screen mount.

- `useTradePagePrewarm.ts` — mounted once in TabNav: hydrates/refreshes the organic first page before Acquire focus, using persisted fairness and the exact active user/league/format. Joins foreground session revalidation and cancels after identity, token, flag, foreground or format changes. Passive requests use the server prewarm header guard; free previews require a user tap.
