# mobile/src/state/

Cross-screen state. **zustand**, not Context — 11 of the 19 modules are zustand stores; the rest are module buses, plain hooks, or the shared `QueryClient`. Shapes + persistence keys: [README.md](README.md).

MAP, not a changelog — present behavior only. History: `git log -- <this file>` and `living-memory/CHANGELOG.md`.

- `useSession.ts` — current Sleeper user / selected league. `connectLeague` MERGES the refreshed league list instead of replacing it, because `getLeagues()`'s response can never contain a platform-imported (ESPN/MFL/Fleaflicker) row — a wholesale `setLeagues(lgs)` would silently drop every one of them the moment a user connects a Sleeper league mid-session. Rows whose `platform` isn't `'sleeper'` and whose id is absent from the fresh list are carried forward; a fresh row for the same `league_id` still wins. **Caveat:** `platform` is only trustworthy while `draft.room` is on — the server stamps it inside that flag's block.
- `useEntitlements.ts` — the client's cached view of Pro (flags `monetize.*`, dark). `{pro, expiresAt, loaded, optimistic}` plus `loadCached` / `refresh` / `noteCustomerInfo`; `initEntitlements()` is kicked from `App.tsx` boot and `refresh()` again on foreground. **Client receipts are never trusted — the server is authoritative via `backend/entitlements.check_pro()`.** Three inputs in descending authority: `GET /api/me/entitlements` (overwrites in BOTH directions, so a refund can take Pro away), the AsyncStorage cache under a **72 h offline grace** (past it the cached grant is discarded and the UI reads free — an indefinitely-honored cache is a free subscription for anyone who stays offline), and a RevenueCat `CustomerInfo` push which may only RAISE `pro` and is never persisted. The listener is attached through `api/purchases.setOnPurchasesReady`, because `configure` may happen at boot (restored session) or minutes later (fresh sign-in) and attaching earlier binds nothing.
- `useFeatureFlags.ts` — flags fetched from `/api/flags`; onboarding.* features MUST be read via `useOnboardingFeature()` / `onboardingEnabled()` (master `onboarding.v2` AND the individual flag).
- `useOnboardingState.ts` — persisted `ftf_onboarding_state` (first-run, prompt snooze, Apple-ask policy, coach marks, push-primer backoff fields under `ux.prompt_arbiter`, `ratingPromptShownVersion` under `growth.rating_prompt`).
- `useInterruptCoordinator.ts` — one-surface prompt arbiter (flag `ux.prompt_arbiter`): `useInterruptSlot(id, wants)` claims the single `activeSurface` slot (priority quickset prompt > coach mark > apple banner > outlook banner, no preemption); root modals self-defer while any slot is claimed; flag off = passthrough.
- `usePushPriming.ts` — push-primer coordination; with `ux.prompt_arbiter` on, "Maybe later" declines persist and re-prime only after 3+ sessions or a want-it moment (fired by MatchesScreen's first mutual match).
- `quicksetProgress.ts` — per-position quick-tiers completion for Rank-tab launch routing: AsyncStorage cache of `/api/tiers/status` `saved`, union'd with `useOnboardingState.quicksetCompletedPositions`; `nextQuicksetPosition()` returns the next unset position in QB→RB→WR→TE order (null = all done → TabNav defaults the Rank stack to Trios). Cache-optimistic — stale answers converge next launch, never a mid-session reroute.
- `rookieScope.ts` — the shared rookie-scope model (flag `ranks.rookie_subset`): session-only zustand store (`useRookieScope()` + non-hook `rookieScopeParam()`), the scope control's content, and the typed-empty copy. One state + one copy set consumed by every rank surface via `components/RookieScopeControl`. Never persisted — a board filter must not outlive its session; `rookieScopeParam()` returns `undefined` with the flag off.
- `premiumImport.ts` — device-local "imported N weeks ago" stamps per premium source (zustand + AsyncStorage `ftf.premium_import.v1`). Written on APPLY, never on preview. v1 is schema-free by design — there is no backend row behind a premium source — so losing this degrades to "no prior import", never to a wrong board. Exports `stalenessLabel()`.
- `rankImportBus.ts` — module mailbox for the premium in-app-browser handoff ([D-058]), same shape and same reason as `espnConnectBus.ts`: `ImportRankingsSheet` is an RN Modal and `PremiumRankingsBrowserScreen` is a native-stack push, so they live on opposite sides of a Modal boundary. A capture delivered with nothing subscribed is parked and flushed to the next subscriber — the browser pops as soon as it has the file, and dropping it would spend the user's export for nothing.
- `onboardingBus.ts` — session-scoped module mailbox: QuickSetTiers (onboarding mode) posts a pending deck-regen position; TradesScreen consumes it on focus.
- `useNotifications.ts` — in-app notification inbox state.
- `useFinderTargets.ts` — finder pin lists (zustand): `pinnedGive`/`pinnedReceive` + a `packageMode` toggle. Session-only, never persisted; self-clears on league switch via a `useSession` subscription. TradesScreen owns add/remove; the hub reads live counts. Also owns the **hand-off** (`FinderHandoff`, #330 and #384): `opponent` is **nullable** — a calculator canvas with no partner chosen is an *unscoped sweep*, not "no search" — plus `autoRun`, `origin` (`'calculator'` distinguishes a calculator hand-off from a league-rankings offer, and is what scopes the ✕→overlay presentation and the end-of-deck exits to the deck the calculator sent), and `fairAnchor` (**W6-B, [D-153]** — the calculator canvas itself, present iff it has a GIVE side. Its presence is what FORKS the arrival: with it the deck runs the synchronous `POST /api/trades/fair-packages` sweep and sets its cards directly, without it the deck arms today's model auto-run. It replaced `includePlayers`, and it is deliberately not a boolean — the canvas no longer travels through the pin store at all, so the deck needs the ids). The handoff is **consumed once**; `deckOrigin` is cleared on league switch, on pins emptying, and on a mode switch — a sticky origin would keep the overlay after the deck stopped being the calculator's.
- `useGuide.ts` — The Analyst guided-tour engine (flag `onboarding.guided_avatar`): one-bubble-at-a-time step store, `guidedAvatarActive()` gate, guide_* analytics; `enableTour()` (Settings toggle re-enable) clears `guideDismissed`/`guideSeen`/`guideTourCompleted` via `resetGuideProgress()`. **Tour-owned mute (#384):** a runner registers its beat ids with `setTourOwnedIds(set)` on start and clears them on end, so `requestStep` can refuse a non-tour beat while a tour holds the floor — and refuse it **before any side effect**, since recording a suppression episode or a retirement for a beat that was never eligible spends a beat the user never saw. Tour-owned beats are exempt from the v1 release cap. The set is **registered into** the store, never imported: `utils/calcTour.ts` imports `useGuide`, so the reverse would be a cycle (pinned by `check-calc-tour.js`).
- `guideTargets.ts` — spotlight target registry: screens register views by testID, the overlay measures at show time (missing target → bubble-only, never a blank cutout). Also the **movement seam** (`subscribeGuideTargetsMoved` / `notifyGuideTargetsMoved` — a host announces that its content moved without importing a single guide internal) and the **scroller registry** (`registerGuideScroller(screenKey, handle)` / `unregisterGuideScroller` / `getGuideScroller`, 2026-08-22). The scroller key is the SCREEN NAME the steps declare (`GuideStep.screen`), so a beat on `Trades` reaches TradesScreen's deck ScrollView and one on `TradeCalculator` reaches the calculator's page ScrollView. The handle is deliberately `{scrollTo(y), getScrollY()}` rather than a `ScrollView` ref: the overlay works in absolute WINDOW coordinates and the container in CONTENT offsets, so it needs the host's current offset to convert. A screen with nothing to scroll simply never registers, and the lookup returns `undefined` — the same quiet degrade as a missing target.

- `useFeedback.ts` — in-app feedback capture. **Local AsyncStorage (`ftf_inapp_feedback_v1`) is the source of truth from the user's POV**: every save lands on-device immediately and never blocks the UI; a background `POST /api/feedback` then mirrors it, and `synced` tracks the round-trip. Failures are silent except for the inbox badge; `retrySync()` re-attempts on foreground (wired in `App.tsx`).
- `useTradeQueue.ts` — stacked trade ideas, mirroring the web's 2K-style queue; "Send All" opens each Sleeper propose URL with a 500 ms stagger. Persisted per-USER (`ftf_trade_queue_<user_id>`) so signing in/out never mixes queues across accounts; per-league scoping lives in the in-memory `byLeague` map.
- `outlookStrip.ts` — per-user, per-league memory of the League Summary outlook strip's expanded state (#169 frame E). Plain hook + AsyncStorage, deliberately NOT a zustand store; borrows only `useTradeQueue`'s error-swallowing persist posture and user-scoped key shape. Sparse record — collapsing DELETES the league's entry rather than writing `false`, so the blob only ever names leagues the user opted into.
- `espnConnectBus.ts` — module mailbox for the ESPN Connect WebView handoff, the same shape and reason as `rankImportBus.ts`. `EspnLinkSheet` is an RN `<Modal>`; the WebView push lands BEHIND it, so the sheet hides its own Modal — and RN unmounts a hidden Modal's children. The sheet therefore subscribes from its component body rather than through navigation focus, which it cannot observe from inside a Modal.
- `queryClient.ts` — the single app-lifetime `QueryClient`, shared between `App.tsx`'s provider and non-React modules that invalidate imperatively (e.g. `useSession` swapping the active league outside any component tree). Defaults: retry 1, `staleTime` 30 s, `gcTime` 30 min (vs TanStack's 5 min — tab switches and AppState suspensions must not nuke the cache), refetch on mount/focus/reconnect. Pairs with screen-level `placeholderData: (prev) => prev` for "instant content, refetch silently".

## Conventions

- **zustand for anything two screens read**, or that a non-React module must reach via `.getState()`. Context is not the pattern here, despite what this file used to say.
- **Persist only what should survive a relaunch, and scope the key by user id.** `useFinderTargets` and `rookieScope` are session-only on purpose — a pin list or a board filter must not outlive its session.
- **A store coordinates; it does not compute or fetch.** Math goes in `../utils/` (where a `tests/check-*.js` guard can reach it), requests go in `../api/`.
- **Clearing on league switch is a subscription**, not a screen's responsibility — `useFinderTargets` subscribes to `useSession` and is the pattern to copy.
- **A module bus is for two surfaces separated by a `Modal` boundary**, where neither navigation params nor focus can reach across — `espnConnectBus`, `rankImportBus`, `onboardingBus`. Nothing else.

- `presentationDismissed.ts` — the in-session dismissed set for the presentation-v2 surface (flag `trades.presentation_v2`), keyed by league. Exists because `TodaysTrade` and `TradeBrowseAll` are two views over ONE ranked deck and must agree about which cards the user dismissed. Deliberately **not persisted**: the durable record is the server's (the swipe disposition plus the decline-reason row, and the next generation's suppression logic), so persisting locally would create a second drifting source of truth. `restore` backs the Undo affordance — it un-hides the row, it does not un-write the signal, and the copy never claims it does.
