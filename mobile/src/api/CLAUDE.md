# mobile/src/api/

HTTP clients. No React, no UI. The only allowed upward imports are the flag store (`events.ts`, `tradePregen.ts`) and type-only session/feedback types.

MAP, not a changelog. Orientation + conventions: [README.md](README.md).

| File | Wraps |
|---|---|
| `client.ts` | Base fetch wrapper: base URL from `Constants.expoConfig.extra.apiBaseUrl`, `X-Session-Token` from expo-secure-store, `X-Device`/`X-OS-Version`/`X-App-Version` headers, JSON by default, 401 → clears the session (only when the sent token still matches SecureStore — the FB-45 guard). Also the single mint source for the anonymous device id (`getDeviceId`, `dev_` + UUID) and `getBaseUrl` |
| `_queue.ts` | Shared offline-write-queue **primitives**, extracted from `events.ts` when `recordedPicks.ts` needed the identical contract: `uuidv4` idempotency keys, the jittered backoff ladder, and the accepted/deduped/rejected response-driven purge parser. Deliberately NOT extracted: the stateful queue/flush/persist loop — each queue builds its own, structurally identical, so a shared generic never becomes a risky refactor of the production analytics path |
| `auth.ts` | Sign in / session endpoints + account auth (`/api/auth/apple`, GET/DELETE `/api/account`, POST `/api/account/link-sleeper`). `initLeagueSession` resolves to a **`SessionInitSeed`** (`{rosters?, leagueUsers?}`) and `buildSessionInitBody` takes an optional `seedOut` of the same shape — the Sleeper reads the session-init payload is built from, handed back so the caller can seed the query cache instead of letting four screens re-fetch the identical two endpoints. Both are ABSENT on the ESPN / MFL / Fleaflicker branches (backend snapshot, no Sleeper proxies). The seed is deliberately NOT folded into `SessionInitBody` — that object is POSTed verbatim — and the cache write lives in `state/queryClient.seedLeagueSessionCaches`, because this layer may not import the QueryClient |
| `sleeper.ts` | Sleeper public API (via the backend proxy). **Co-owner resolution lives here and nowhere else** (2026-08-15, [ADR-012](../../../docs/adr/adr-012-co-owned-roster-identity.md)): `RosterRow.co_owners` + `ownsRoster` / `findMyRoster` / `myOwnerId`. `ownsRoster` is `owner_id === userId || userId ∈ co_owners`; `myOwnerId` returns the caller's **league identity** — their roster's PRIMARY `owner_id` — which is what every `rosterByOwner[…]` lookup and every "exclude my own team" filter must key on, since a co-owned roster is keyed league-wide on its primary owner. Identical to `userId` for a sole owner. Never re-implement the predicate at a call site; the backend + web mirrors are pinned in `docs/cross-client-invariants.md`. `getLeagues()` also maps the rookie-draft placement fields `draft_status` / `draft_status_confidence` — stamped onto `GET /api/sleeper/leagues/<user_id>` behind `draft.room` from the cached #207 columns, and consumed ONLY by `state/draftLeagues.ts` (the seasonal Draft tab's predicate). Absent with the flag off, null for a league we've never synced |
| `accountPrefs.ts` | Account preference + data-rights endpoints: profile visibility (GET/PUT `/api/profile/visibility`), data export (`/api/account/export`), and #215 stud-tax mode (`getStudTaxMode`/`setStudTaxMode` → GET/PUT `/api/settings/stud-tax`) |
| `league.ts` | League data + members. **W3 M-C (2026-08-08):** `OwnedPick.source` and each power-rankings `picks.items[]`'s optional `pick_id`/`season`/`source` — `draft_picks.source`, server-authoritative and never inferred. `'user'` means a leaguemate asserted that pick's ownership on the ESPN grid, which obliges every surface rendering its PRICE to carry `components/MemberEnteredMarker` (D17). Absent / `'platform'` is platform truth; every pre-W3 row reads as platform because no backfill ran |
| `rankings.ts` | Submit/fetch personal rankings. **Rookie scope (rookie-draft M2, flag `ranks.rookie_subset`):** `getRankings` / `getNextTrio` / `getAnchorPool` take `{scope:'rookie'}` and return `T \| ScopedEmpty` — the server's typed `{empty:true, reason, position, scope, count}` 200 for a thin/unloaded class. Narrow with `isScopedEmpty()` or the `splitRankings()` helper (→ `{rows, empty}`), never inline. `saveTiers` takes `{scope, via}` for the merged-band scoped save (`via` ∈ `rookie_tiers\|rookie_quickset\|rookie_anchors` — the forensic tag the board-restore procedure keys off). `reorderRankings` and `saveAnchor` deliberately take NO scope: `apply_reorder`/`apply_anchor` are already subset-safe, so posting the rookie subsequence is byte-identical to the unscoped equivalent. `reorderRankings`'s optional `via` is `'quickrank' | 'rookie_ranks'` — `quickrank` is read server-side (fires `quickrank_completed`, FR-20); `rookie_ranks` (the 2026-08-06 editable consolidated rookie board) is REQUEST-ONLY, since the route branches on `quickrank` alone and ignores every other value, so the response is byte-identical either way. Callers pass the param from `state/rookieScope`, which returns `undefined` whenever the flag is off ⇒ the query string is byte-identical to pre-M2 |
| `trades.ts` | Trade card fetch + decisions. Also `queueTradeForOpponent` (#384 ✓ cell, `POST /api/trades/queue`) and its `CalcQueueReason` union — a cross-client enum, kept in step with `server.CALC_QUEUE_REASONS` Also `getFairPackages` (#384 W6-B, `POST /api/trades/fair-packages`, [D-153]) — the fairness-only sweep the merged calculator runs when the canvas has a give side. Its `ideas` reuse the `AssetIdea` shape, which gains two fields ONLY this route sets: `trade_id` (the server's deterministic `fairpk_…`, the row key a swipe / queue / flag on the card reconstructs under) and `basis`. Both are validated, not coerced, so an asset-ideas payload normalizes byte-identically. |
| `tradePregen.ts` | Onboarding item 4 pregen: fire-and-forget `maybePregenTrades()` kicked from session-init success paths (LeaguePicker pick, `revalidateSession`) — flag `onboarding.trades_first`, per-launch dedupe; also the single source for the shared fairness-pref constants |
| `events.ts` | First-party analytics SDK (`POST /api/events`, P1 contract — flag `analytics.client_events`) — `track(type, props?, screen?)` + batched offline queue (`{v:1}` shape, funnel-critical drop-last), per-session `seq`, response-driven purge + backoff. Device id (`dev_`) is minted in `client.ts` (`getDeviceId`) and re-exported here to avoid a flag-store import cycle |
| `flags.ts` | Feature flags (`/api/flags`) |
| `purchases.ts` | **The ONE module allowed to import `react-native-purchases`** (pinned by `tests/check-paywall.js` §7a) — RevenueCat behind the Fleeced Pro paywall. Lazy `require` behind an `EXPO_PUBLIC_REVENUECAT_IOS_KEY` check, so with no key (or in Expo Go, where the native module is absent and the SDK drops to Preview API Mode) the SDK is never even evaluated and every export no-ops: `initPurchases` returns, `getOfferings`/`restorePurchases`/`purchasePackage` return null, `onCustomerInfoChange` returns a no-op unsubscribe. `initPurchases(userId)` `configure`s once with the session WORKING KEY as `appUserID` and `logIn`s on any later key — **never `logOut`**, including on sign-out (RevenueCat guidance: logOut re-anonymizes the identity, and leaving FTF is not leaving the App Store account that owns the subscription). `purchasePackage` deliberately THROWS a real StoreKit failure so the caller can tell a user cancel (`isUserCancelled`) from an error; it returns null only when purchases are unavailable. `setOnPurchasesReady` is the callback seam `state/useEntitlements` uses to attach its CustomerInfo listener at the moment `configure` succeeds — same not-an-import pattern as `client.ts`'s `setOnVerificationRequired`. Nothing here decides entitlement |
| `billing.ts` | Monetization reads: `getEntitlements()` → `GET /api/me/entitlements` (`{pro, ad_free, sources, expires_at, enforcing}`) and `getPaywallConfig(platform)` → `GET /api/paywall/config` (pro-subscription LLD §3: `{enabled, platform, pages[], products[], trial_eligible, dismissible}`). Both stay mounted server-side regardless of flags — the config answers `{enabled:false}` while `monetize.paywall` is off. `display_price` is FALLBACK copy: on iOS the StoreKit-localized `priceString` from the offering wins, because the server's strings are US-English list prices that know nothing about the caller's storefront |
| `draft.ts` | Draft Room (rookie-draft M3/M4, flag `draft.room`): `getDraftBoard(leagueId, basis)` → `GET /api/draft/board` — one versioned read-only payload (`state`/`kind`/`order[]`/`picks[]`/`undrafted[]`/`my_picks[]`/`order_confidence`/`as_of`/`stale`/`degraded`/`notice`/`deep_link`). **Rejects an unknown `schema` with `DraftSchemaError`** rather than best-effort parsing a payload it doesn't understand; the screen turns that into "needs a newer version of the app". No write path exists — `deep_link` hands off to the platform. **W3 M-B (2026-08-08):** `NoticeCode` gains `picks_not_assigned` — the ESPN league nobody has assigned picks for. It is the ONE new vocabulary item of the wave and rides `notice.code` precisely because that set is OPEN while `state`/`kind`/`order_confidence` are closed, so an older binary renders `notice.message` and behaves correctly. `state` stays `unavailable`; `schema` stays 1 |
| `mockDraft.ts` | **draft-extensions W2 (2026-08-06, flag `draft.mock`, ships OFF)** — the four `/api/mock-draft` routes: `getMockDraft(leagueId, basis)` · `createMockDraft({leagueId, rounds, type})` · `pickInMockDraft(mockId, playerId)` · `abandonMockDraft(mockId)`. The FTF-native rookie-draft simulation: the user picks for their own team, computer drafters pick for the rest, and NOTHING reaches a platform (the mock is one server-side row, so the room's D9 "never drafts for you" guarantee is untouched). **Two response shapes on the same route and callers MUST branch** (`isMockEmpty`): the full state payload — deliberately the SAME entry shapes as `GET /api/draft/board` (`order[]`/`picks[]`/`undrafted[]`/`my_picks[]`/`notice`, plus `on_the_clock` and `settings_echo`), which is what lets the Draft Room's row components render it verbatim — or M2's typed-empty `{schema, empty:true, reason}`. `reason` is typed OPEN on purpose (plan D10: typed-empty is the one place a new refusal may appear without touching a closed client enum), so an unknown value degrades to generic copy. Reuses `DraftSchemaError` from `draft.ts` — unknown `schema` ⇒ "update the app", never a best-effort parse. **Contract gaps the client works around, not bugs it hides:** `GET` has no capability probe (`class_not_loaded` / `cpu_model_unvalidated` are POST-only, G2), `picks[]` carries no `consensus_rank` so recap deltas are not computable (G3), and the round default is the client's job to pass (G9) |
| `pickAssignment.ts` | **draft-extensions W3 M-A (2026-08-06, flag `picks.assign`, ships OFF)** — the three `/api/league/pick-assignments` routes: `getPickAssignments(leagueId)` · `assignPick({leagueId, pickId, ownerUserId, ifAssignedAt})` · `seedPickGrid({leagueId, rounds, orderType, order, reseed})`. ESPN hosts no rookie drafts, so an ESPN dynasty league's rookie draft happens off-platform and FTF becomes the league's system of record for pick OWNERSHIP. **No value field exists on any request here and none may be added (D13)** — prices are a pure server-side function of (round, years_out, format), which is what bounds a bad assignment to REDISTRIBUTING value inside a league rather than creating it (the conservation bound); the server 400s `values_not_accepted` on any value-shaped key. `assigned_at` is BOTH a timestamp and the **optimistic-concurrency token**: a PUT carries the value it read as `if_assigned_at`, and a mismatch — including "row already assigned, token omitted" — returns 409 `stale_assignment` carrying the WHOLE current row, so the UI renders "Dana changed this pick 4 minutes ago — keep theirs, or use yours?" without a second request. Narrow it with `staleAssignment(err)` (→ `PickSlot \| null`), never by reading `err.status` inline; other typed rejections come back through `pickAssignmentErrorCode(err)`, read as an OPEN set. The GET always answers **current + 3 seasons** (operator decision 3, ~192 slots, ~40 KB, deliberately not paginated). `pickAssignmentSubline(progress, seeded)` is the ONE formatter behind both the League tab's sub-line and the screen's progress line so they cannot disagree. **Contract gaps this client works around, not bugs it hides:** the GET's documented `season=` query param is not sent (the payload is always all four seasons, so it has no effect worth risking); an UNSEEDED payload has no slots and therefore no id→name mapping for the setup step's drag list, so `PickAssignmentScreen` reads `GET /api/league/members` for that one purpose. **W3 M-C (2026-08-08):** exports `PickSource` (`'platform' | 'user'`) — ONE definition of the provenance discriminator, imported by `league.ts`, `calc.ts`, `data/calcTypes.ts` and `components/MemberEnteredMarker`, so no client can invent a third value or read the enum two ways. **ESPN auto-derived draft order (2026-08-08, no new flag — it changes a DEFAULT inside `picks.assign`):** the GET may carry `suggested_order` (member ids in derived round-1 pick order) + `suggested_order_source` (`'espn_standings'`, OPEN set) + `suggested_order_season` + `suggested_order_detail[]` (`SuggestedOrderEntry` — the caption's "why"; **no value field, D13**), all four together or not at all. It is a **DEFAULT for the setup step's drag list, not adopted state**: `settings.order` is untouched and nothing persists until `seedPickGrid`. The server emits it **only while the league has no stored order**, which makes "a saved order is never overwritten" STRUCTURAL rather than a client rule — after the first save the keys never return and no ESPN read happens, so there is deliberately no "reset to the ESPN order" affordance. Absent whenever the derivation can't be honest (non-ESPN, never-linked, first ESPN season, pre-season 0-0-0 grid, expired cookies, ESPN down, membership changed since the snapshot) — and absent is the shipped behaviour, the user orders manually. Convention + refusal matrix: `docs/plans/draft-extensions/build-espn-auto-order.md` |
| `market.ts` | Market movers (#243, flag `market.movers`): `getMarketMovers(format)` → `GET /api/market/movers` — top risers/fallers by trailing-window % change of FTF community value. Open read; consumed by `MarketPulseStrip` |
| `notifications.ts` | Notifications inbox |
| `leaderboard.ts` | `GET /api/leaderboard` — league + universal boards over two metrics (`streak`, `ranks`) and four windows (`week`/`month`/`season`/`all`); rows carry `is_self` so the caller can pin a sticky self-row. Consumed by `components/LeaderboardsSection` and `ContrarianLeaderboard` |
| `feedback.ts` | `POST /api/feedback` — uploads one on-device feedback note; also `getMyFeedback` and the `CLOSED_FEEDBACK_STATUSES` / `FeedbackStatus` vocabulary the FAB badge math reads. The LOCAL copy is owned by `state/useFeedback.ts`; this module only shapes the wire payload. Anonymous and signed-in tester flows both work — `client.ts` already attaches whatever headers exist |
| `declineReasons.ts` | Decline-reason capture (flag `feedback.decline_reasons`; spec `docs/plans/decline-reason-capture/SPEC.md` §2 taxonomy, §3 persistence). **Progressive writes are the point** — every tap commits on its own, nothing batches behind a submit: layer-1 tile → layer-2 option → "Other" (which posts `*_other` BEFORE the text box opens, then upgrades the same row with `free_text`). The server upsert is keyed on `impression_id`, so 1→2→3 land on ONE row and a tester who stops at any step still leaves a complete, honest record. **Fire-and-forget by contract**, exactly like `events.ts`: a reason write must never block the deck or surface an error mid-triage, and the disposition itself rides the unchanged `/api/trades/swipe` POST — a failed reason write costs the reason, never the pass. This module is the ONLY place mobile knows the route shape; if the backend's route differs, this file is the entire fix |
| `recordedPicks.ts` | **draft-extensions W3 M-D (flag `draft.manual_picks`, ships OFF)** — the offline write path behind `RecordPicksScreen`. ESPN hosts no rookie drafts, so once M-A's assignment grid is filled the only way FTF learns who was taken is a member typing it in during the real draft; recording is "confirm, not select" (the team comes from the grid, the cursor auto-advances). The queue **copies `events.ts`'s contract field-for-field** rather than reinventing it — live drafts happen on bad wifi — sharing the pure pieces via `_queue.ts`. `initRecordedPicksQueue()` is kicked from `App.tsx` boot and is inert on an empty queue |

All optional — a pre-M-C server omits them and nothing marks |
