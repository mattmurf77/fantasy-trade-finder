# mobile/src/api/

HTTP clients only. No React, no state, no side effects beyond fetch.

| File | Wraps |
|---|---|
| `client.ts` | Base fetch wrapper (URL, auth headers, JSON) |
| `auth.ts` | Sign in / session endpoints + account auth (`/api/auth/apple`, GET/DELETE `/api/account`, POST `/api/account/link-sleeper`) |
| `sleeper.ts` | Sleeper public API (via the backend proxy). `getLeagues()` also maps the rookie-draft placement fields `draft_status` / `draft_status_confidence` — stamped onto `GET /api/sleeper/leagues/<user_id>` behind `draft.room` from the cached #207 columns, and consumed ONLY by `state/draftLeagues.ts` (the seasonal Draft tab's predicate). Absent with the flag off, null for a league we've never synced |
| `accountPrefs.ts` | Account preference + data-rights endpoints: profile visibility (GET/PUT `/api/profile/visibility`), data export (`/api/account/export`), and #215 stud-tax mode (`getStudTaxMode`/`setStudTaxMode` → GET/PUT `/api/settings/stud-tax`) |
| `league.ts` | League data + members. **W3 M-C (2026-08-08):** `OwnedPick.source` and each power-rankings `picks.items[]`'s optional `pick_id`/`season`/`source` — `draft_picks.source`, server-authoritative and never inferred. `'user'` means a leaguemate asserted that pick's ownership on the ESPN grid, which obliges every surface rendering its PRICE to carry `components/MemberEnteredMarker` (D17). Absent / `'platform'` is platform truth; every pre-W3 row reads as platform because no backfill ran |
| `rankings.ts` | Submit/fetch personal rankings. **Rookie scope (rookie-draft M2, flag `ranks.rookie_subset`):** `getRankings` / `getNextTrio` / `getAnchorPool` take `{scope:'rookie'}` and return `T \| ScopedEmpty` — the server's typed `{empty:true, reason, position, scope, count}` 200 for a thin/unloaded class. Narrow with `isScopedEmpty()` or the `splitRankings()` helper (→ `{rows, empty}`), never inline. `saveTiers` takes `{scope, via}` for the merged-band scoped save (`via` ∈ `rookie_tiers\|rookie_quickset\|rookie_anchors` — the forensic tag the board-restore procedure keys off). `reorderRankings` and `saveAnchor` deliberately take NO scope: `apply_reorder`/`apply_anchor` are already subset-safe, so posting the rookie subsequence is byte-identical to the unscoped equivalent. `reorderRankings`'s optional `via` is `'quickrank' | 'rookie_ranks'` — `quickrank` is read server-side (fires `quickrank_completed`, FR-20); `rookie_ranks` (the 2026-08-06 editable consolidated rookie board) is REQUEST-ONLY, since the route branches on `quickrank` alone and ignores every other value, so the response is byte-identical either way. Callers pass the param from `state/rookieScope`, which returns `undefined` whenever the flag is off ⇒ the query string is byte-identical to pre-M2 |
| `trades.ts` | Trade card fetch + decisions |
| `tradePregen.ts` | Onboarding item 4 pregen: fire-and-forget `maybePregenTrades()` kicked from session-init success paths (LeaguePicker pick, `revalidateSession`) — flag `onboarding.trades_first`, per-launch dedupe; also the single source for the shared fairness-pref constants |
| `events.ts` | First-party analytics SDK (`POST /api/events`, P1 contract — flag `analytics.client_events`) — `track(type, props?, screen?)` + batched offline queue (`{v:1}` shape, funnel-critical drop-last), per-session `seq`, response-driven purge + backoff. Device id (`dev_`) is minted in `client.ts` (`getDeviceId`) and re-exported here to avoid a flag-store import cycle |
| `flags.ts` | Feature flags (`/api/flags`) |
| `draft.ts` | Draft Room (rookie-draft M3/M4, flag `draft.room`): `getDraftBoard(leagueId, basis)` → `GET /api/draft/board` — one versioned read-only payload (`state`/`kind`/`order[]`/`picks[]`/`undrafted[]`/`my_picks[]`/`order_confidence`/`as_of`/`stale`/`degraded`/`notice`/`deep_link`). **Rejects an unknown `schema` with `DraftSchemaError`** rather than best-effort parsing a payload it doesn't understand; the screen turns that into "needs a newer version of the app". No write path exists — `deep_link` hands off to the platform. **W3 M-B (2026-08-08):** `NoticeCode` gains `picks_not_assigned` — the ESPN league nobody has assigned picks for. It is the ONE new vocabulary item of the wave and rides `notice.code` precisely because that set is OPEN while `state`/`kind`/`order_confidence` are closed, so an older binary renders `notice.message` and behaves correctly. `state` stays `unavailable`; `schema` stays 1 |
| `mockDraft.ts` | **draft-extensions W2 (2026-08-06, flag `draft.mock`, ships OFF)** — the four `/api/mock-draft` routes: `getMockDraft(leagueId, basis)` · `createMockDraft({leagueId, rounds, type})` · `pickInMockDraft(mockId, playerId)` · `abandonMockDraft(mockId)`. The FTF-native rookie-draft simulation: the user picks for their own team, computer drafters pick for the rest, and NOTHING reaches a platform (the mock is one server-side row, so the room's D9 "never drafts for you" guarantee is untouched). **Two response shapes on the same route and callers MUST branch** (`isMockEmpty`): the full state payload — deliberately the SAME entry shapes as `GET /api/draft/board` (`order[]`/`picks[]`/`undrafted[]`/`my_picks[]`/`notice`, plus `on_the_clock` and `settings_echo`), which is what lets the Draft Room's row components render it verbatim — or M2's typed-empty `{schema, empty:true, reason}`. `reason` is typed OPEN on purpose (plan D10: typed-empty is the one place a new refusal may appear without touching a closed client enum), so an unknown value degrades to generic copy. Reuses `DraftSchemaError` from `draft.ts` — unknown `schema` ⇒ "update the app", never a best-effort parse. **Contract gaps the client works around, not bugs it hides:** `GET` has no capability probe (`class_not_loaded` / `cpu_model_unvalidated` are POST-only, G2), `picks[]` carries no `consensus_rank` so recap deltas are not computable (G3), and the round default is the client's job to pass (G9) |
| `pickAssignment.ts` | **draft-extensions W3 M-A (2026-08-06, flag `picks.assign`, ships OFF)** — the three `/api/league/pick-assignments` routes: `getPickAssignments(leagueId)` · `assignPick({leagueId, pickId, ownerUserId, ifAssignedAt})` · `seedPickGrid({leagueId, rounds, orderType, order, reseed})`. ESPN hosts no rookie drafts, so an ESPN dynasty league's rookie draft happens off-platform and FTF becomes the league's system of record for pick OWNERSHIP. **No value field exists on any request here and none may be added (D13)** — prices are a pure server-side function of (round, years_out, format), which is what bounds a bad assignment to REDISTRIBUTING value inside a league rather than creating it (the conservation bound); the server 400s `values_not_accepted` on any value-shaped key. `assigned_at` is BOTH a timestamp and the **optimistic-concurrency token**: a PUT carries the value it read as `if_assigned_at`, and a mismatch — including "row already assigned, token omitted" — returns 409 `stale_assignment` carrying the WHOLE current row, so the UI renders "Dana changed this pick 4 minutes ago — keep theirs, or use yours?" without a second request. Narrow it with `staleAssignment(err)` (→ `PickSlot \| null`), never by reading `err.status` inline; other typed rejections come back through `pickAssignmentErrorCode(err)`, read as an OPEN set. The GET always answers **current + 3 seasons** (operator decision 3, ~192 slots, ~40 KB, deliberately not paginated). `pickAssignmentSubline(progress, seeded)` is the ONE formatter behind both the League tab's sub-line and the screen's progress line so they cannot disagree. **Contract gaps this client works around, not bugs it hides:** the GET's documented `season=` query param is not sent (the payload is always all four seasons, so it has no effect worth risking); an UNSEEDED payload has no slots and therefore no id→name mapping for the setup step's drag list, so `PickAssignmentScreen` reads `GET /api/league/members` for that one purpose. **W3 M-C (2026-08-08):** exports `PickSource` (`'platform' | 'user'`) — ONE definition of the provenance discriminator, imported by `league.ts`, `calc.ts`, `data/tradeCalcMock.ts` and `components/MemberEnteredMarker`, so no client can invent a third value or read the enum two ways. **ESPN auto-derived draft order (2026-08-08, no new flag — it changes a DEFAULT inside `picks.assign`):** the GET may carry `suggested_order` (member ids in derived round-1 pick order) + `suggested_order_source` (`'espn_standings'`, OPEN set) + `suggested_order_season` + `suggested_order_detail[]` (`SuggestedOrderEntry` — the caption's "why"; **no value field, D13**), all four together or not at all. It is a **DEFAULT for the setup step's drag list, not adopted state**: `settings.order` is untouched and nothing persists until `seedPickGrid`. The server emits it **only while the league has no stored order**, which makes "a saved order is never overwritten" STRUCTURAL rather than a client rule — after the first save the keys never return and no ESPN read happens, so there is deliberately no "reset to the ESPN order" affordance. Absent whenever the derivation can't be honest (non-ESPN, never-linked, first ESPN season, pre-season 0-0-0 grid, expired cookies, ESPN down, membership changed since the snapshot) — and absent is the shipped behaviour, the user orders manually. Convention + refusal matrix: `docs/plans/draft-extensions/build-espn-auto-order.md` |
| `market.ts` | Market movers (#243, flag `market.movers`): `getMarketMovers(format)` → `GET /api/market/movers` — top risers/fallers by trailing-window % change of FTF community value. Open read; consumed by `MarketPulseStrip` |
| `notifications.ts` | Notifications inbox |
| `calc.ts` | Trade Calculator consensus endpoints (`/api/trade/values`, `/api/trade/evaluate`) — public; #215: `evaluateTrade` attaches the session token when present (endpoint stays public) so the server applies the caller's stored `stud_tax_mode`, echoed on `CalcEvaluation.stud_tax_mode`; exports the `StudTaxMode` union; #264: `evaluateTradeInLeague` takes an optional trailing `oneSidedEveners` — it sends the same `one_sided_eveners: true` key `evaluateForSwapSuggestions` does, so a half-built in-league trade comes back with candidate assets for the EMPTY side (two-sided reads and old servers are unaffected) · **W3 M-C (2026-08-08):** `CalcEvener` gains `source`/`pick_id`/`season` so the evener chip and the swap-suggestions sheet can mark an ASSERTED owned pick and deep-link its correction. `id` already IS the `pick_id` for a single-pick evener; `pick_id` rides along anyway so a 2-piece package row could name the asserted piece without a client parsing `<a>+<b>`. All optional — a pre-M-C server omits them and nothing marks |
| `sendInSleeper.ts` | Link Sleeper account + propose trades directly (flagged beta); #180 `validateTradeSend` (`POST /api/trades/validate`) — advisory pre-send checks, never throws (shared with the MFL send: the route platform-branches server-side) |
| `sendInMfl.ts` | "Send in MFL" (flag `trade.send_in_mfl`): `proposeTradeToMfl` → `POST /api/trades/propose-mfl` — server reverse-maps Sleeper→MFL ids and HARD-BLOCKS (422 `mfl_asset_unmapped`) rather than dropping an unmapped asset; error codes drive the MFL re-sign-in UX (`mfl_not_connected` / `mfl_auth_expired`) |
| `espn.ts` | ESPN league linking (flag `espn.link`): `/api/espn/link|leagues|import` + `buildEspnSessionInitBody` (ESPN leagues source session-init rosters from the backend snapshot, never Sleeper proxies) + `isEspnLeague` (platform check against the cached league list, used by auth.ts's builders) |
| `platformLink.ts` | Zero-auth multi-platform linking — MFL (`mfl.link`) + Fleaflicker (`fleaflicker.link`): generic `/api/{platform}/link|leagues|import` (+ Fleaflicker `/discover` by email) + `buildPlatformSessionInitBody` (backend snapshot, never Sleeper proxies) + `isMflLeague`/`isFleaflickerLeague` (used by auth.ts's builders) + `parseMflLeagueInput`/`parseFleaflickerLeagueInput`. ESPN keeps its own `espn.ts` (private-league cookie flow). #177 (flag `mfl.auth_link`): `mflAuthLink` (`POST /api/mfl/auth-link` — password transient, never logged) + `mflAuthImport` (`POST /api/mfl/auth-import`, default ALL leagues, franchise auto-bound) |
