# mobile/src/utils/

Helpers. **No React**, ever. Most are pure; a handful touch native modules or `../api/` (marked below). Full file list + the node-testable/not split: [README.md](README.md).

- `relativeTime.ts` — "2h ago"–style formatting
- `tierBands.ts` — maps Elo / value → tier key and label (8-tier pick-value ladder, #117: 4+ 1sts / 3 1sts / 2 1sts / 1st / 2nd / 3rd / 4th / FA — the bottom label renamed from "Waivers" 2026-07-17, key still `waivers`). The former `pickTerms.ts` sublabel helper was removed 2026-07-11 — tier labels ARE pick terms now.
- `anchorRows.ts` — **draft-extensions W1 (2026-08-06)**: the pick-anchor rung grid (`ANCHOR_ROWS`, two rows of four, `4_firsts`…`no_value`). Extracted from `PickAnchorScreen` the moment a SECOND surface (`components/AnchorSheet`, the Draft Room's "Set my value") started asking the same question — the keys are a cross-client enum shared with `backend/server.py:VALID_ANCHORS` (see `docs/cross-client-invariants.md` § Pick anchor keys), so a copied table would be a silent mis-valuation, not a layout bug. Data only; order is presentational, the keys are the contract.
- `playerValue.ts` — 0–10k display value from Elo (inverse of the #117 value-affine consensus seed map — keep in lockstep with `backend/data_loader.seed_elo_for_value`).
- `feedbackBadge.ts` — FeedbackFAB badge math (#184): `openFeedbackCount` counts notes still awaiting action (excludes `closed` + `RESOLVED_FEEDBACK_STATUSES` = fixed/shipped/declined; the inbox LIST still shows `fixed`). Deliberately zero runtime imports so `mobile/tests/check-feedback-badge.js` can transpile + run it under plain node.
- `firstSessionMoment.ts` — F9 adaptation-moment trigger math (flag `deck.first_session`, PRD F9): dominant-liked-attribute detection over the session's likes (≥3 sharing a phraseable sessionRerank attribute key at magnitude ≥0.5), human phrase mapping (only phraseable keys are eligible — value bands / give-side age-position keys excluded), and `cardMatchesAttribute` (the "more of those ahead" literal-truth check — ≥1 unseen matching card required before the card renders). Session state + rendering live in TradesScreen.
- `sessionRerank.ts` — F4 session re-rank math (flag `deck.session_rerank`, PRD F4): card attribute extraction, last-k (10) ×0.8-decay boost vector (like +1 / long-dwell pass +0.3 / fast pass −0.5 / not-interested −2), cosine similarity, and `rerankRemaining` (newScore = 1/(servedIdx+1) × (1 + 0.3·cos), served-order tiebreak, boundary + position-lock guards — likes-you/`retest`/future F7 `wildcard` never move via `isPositionLocked`). Zero runtime imports (structural card type, not shared/types) so `mobile/tests/check-session-rerank.js` runs it under plain node. Session state itself lives in TradesScreen refs.
- `rankPresets.ts` — premium rank-set CSV presets (Connected Rankings addendum §3.2, [D-058]). Tolerant CSV reader, **anchor-column** source detection (DN = `Rank,Player,Team,Position,Age,Exp,Value` all present, Trend/PPG optional; DLF = `Rank`+`Player`+`Avg`, since DLF's header is dynamic per selected analyst), DN filename inference (`dynasty_rankings_[contender_]<scoring>[_<pos>][_rookies].csv`), and the format map (`ppr`→`1qb_ppr` and `sflextep`→`sf_tep` EXACT; `sflex`/`std` NEAREST, which the confirmation copy must name). **Order only** — `PresetRow` is exactly `{name, team, pos}`, the extractor never indexes a `FORBIDDEN_COLUMNS` (`value`/`trend`/`ppg`) column, and `detectSource()` returns null rather than guessing. Zero runtime imports so `mobile/tests/check-rank-presets.js` runs it under plain node; the order-only guarantee is also pinned structurally by `check-premium-import.js` §3.
- `applyJobResult.ts` — #330 R-10 generation-epoch guard: `applyJobResult(result, dispatchEpoch, currentEpoch)` returns the result only when the epochs match, else null — TradesScreen routes every trade-job result application (mutation onSuccess/onError, polling attach) through it so a stale in-flight search can never overwrite a scoped run. Zero runtime imports so `mobile/tests/check-offer-prefill-330-unit.js` runs it under plain node.
- `leagueUnlocks.ts` — mutual-match unlock math (#265): `MATCH_UNLOCK_MATES` (= 1 — one other ranked leaguemate is enough for `backend/trade_service.py generate_trades` to produce mutual-gain matches; do NOT reuse the unrelated 3-ranked-members `/api/league/contrarian` threshold here) and `matchesUnlockRemaining(rankedMates)`. Also the leaderboards/contrarian fold-line copy (#308): `CONTRARIAN_UNLOCK_USERS` (= 3 — the `/api/league/contrarian` gate: users with rankings in the ACTIVE scoring format, caller INCLUDED — different population AND different threshold from the mutual-match unlock) and `contrarianFoldLine(needed, format)` (format labels mirror TopBar's tile labels, pinned in `docs/cross-client-invariants.md`). Zero runtime imports so `mobile/tests/check-league-unlocks.js` runs it under plain node. Consumed by `components/LeagueProgressModule.tsx`.
- `matchesDerive.ts` — #334/#335 (G9): render-layer pending-dismiss suppression + segment/chip counts for MatchesScreen. **Visibility lives here, not in the query cache**: a dismissed tile is removed optimistically, but six independent paths (mount refetch, pull-to-refresh, reconnect, league-switch invalidation, tab-press prefetch, TradesScreen's guide-v2 `fetchQuery`) can rewrite that cache with a pre-dismiss payload while the delayed dismiss POST is still in flight. Filtering hidden keys at RENDER time makes the tile's disappearance independent of cache contents. Key shapes are PREFIXED forms of the two FlatLists' `keyExtractor`s so a match key can never collide with an awaiting key in the shared set. Zero runtime imports — `tests/check-matches-counts.js` runs it under plain node.
- `mockPool.ts` — #326/#327: the mock-draft undrafted pool's filter + search composition. **Composition order is the contract** (operator decision): position filter FIRST, then search — so a QB-only name under an RB filter finds nothing until you switch to All. Owning the order here keeps it in tested code instead of inline screen JSX. A player whose position is outside the four appears only under All; search is case-insensitive substring on the rendered name (id only as a fallback); empty query ⇒ subset unchanged; no debounce, the list is in-memory. Zero runtime imports — `tests/check-mock-g2-ui.js` calls it under plain node.
- `tickerWindow.ts` — #322/#325: the mock-draft ticker's window. Renders the last `depth` picks ASCENDING by `pick_no` — earliest at the top, newest at the bottom; the section grows one fixed-height row per pick until it holds `depth`, then each new pick appears at the bottom while the earliest falls off the top. The ascending sort inside is **defensive, not decorative** (PRD R-1 / NB-2): `picks[]` arrives in pick order today by construction, but nothing pins that server-side, so sorting here makes the ordering a LOCAL guarantee rather than an unpinned assumption.
- `deepLinks.ts` — **the** route table for `linking` (flag `ux.deeplink_router_v2`) and the single source shared by URLs, push taps, and notification-bell rows. Also owns `handleDeepLink` (called from `App.tsx` for the cold-start case, where the navigator hasn't mounted yet) and `resolveNotificationTarget` (consumed by `hooks/usePushNotifications` under `notif.tap_routing_v2`). Impure — imports `api/events` and the navigation ref.
- `tradeText.ts` — copy-trade text **and** the P0-6 send-platform resolution. Compensating coverage for the MFL/Fleaflicker waiver (`tests/check-trade-text.js`), which is why it stays import-free.
- `inviteSocialProof.ts` — the ONE formatter deciding both whether an invite CTA renders and what it says, across three surfaces (League Home card, Matches empty state, inline-link suppression) plus the `invite_cta_shown` impression guard (P1-5 / audit A-14). Zero runtime imports for `tests/check-invite-social-proof.js`.
- `espnCookies.ts` — `pickEspnCookies()` selects the first native cookie bag carrying BOTH `espn_s2` and `SWID`; `clearEspnCookies()` scopes its clear to espn.com **and** the Disney SSO domains, never `clearAll` (the 2026-08-12 wrong-account incident). Pinned by `tests/check-espn-cookies.js` + `tests/check-espn-connect-clear.js`.
- `espnNavPolicy.ts` — `allowEspnNavigation()`, the pure decision behind `EspnConnectScreen`'s `onShouldStartLoadWithRequest` (2026-08-09 mid-login Safari-escape fix). Pinned by `tests/check-espn-nav-policy.js` — which currently has **no `npm run` script**.
- `shareLinks.ts` — the ONE place a mobile trade-share URL is built (audit P1-1/P1-2): every share artifact must carry a link back to the app. Rung ladder `package` → `ref` → `root` with typed mint outcomes (`ok`/`rate_limited`/`demo`/`failed`), so a failed mint degrades a rung instead of shipping a bare screenshot. Impure — calls `api/calc` + `api/client`.
- `ratingPrompt.ts` — App Store rating gate (flag `growth.rating_prompt`), one entry point `maybeRequestReview(trigger)`. Impure.
- `verification.ts` — shared error copy for read-gated screens (account-auth P2.5): the backend 403s board reads with `verification_required` once a verified controller exists for the user_id. `readErrorCopy(err, fallback)` is the single place that copy is chosen.
- `tradeCalcMath.ts` — client-side calculator math for **demo mode only**, ported from `mockups/trade-calc/`. Dual-perspective: every trade scores on BOTH owners' boards. Retired when `/api/trade/evaluate` fully replaces it, along with `data/tradeCalcMock.ts`.
- `clipboard.ts` — the app's ONE clipboard write (audit P0-6). RN core's `Clipboard` is deprecated behind a warn-once getter; this wrapper exists so that warning has exactly one source.
- `haptics.ts` — semantic haptics taxonomy (`selection`, …). Call sites use these, never `expo-haptics` directly, so feedback stays consistent across screens.
- `testRouteEntry.ts` — launch-argument screen entry (`FTFTestRoute` / `FTFTestRouteParams`) plus `IS_TEST_BUILD`. Capture-harness only; params are a QUERY STRING, never JSON. The harness that drove it is retired (D-056), but the entry point remains in the app.
