- `RootNav.tsx` — root stack: Sign in → main app. Also hosts the pushed league-wide surfaces `LeagueSummary` (League rankings, #142/#144 — since #181 a LEGACY entry point kept for deep link `app/league/summary` + stored whats-new routes; the primary registration is the League tab's stack root, see TabNav) and `FreeAgents` (FA finder, #143, entered from League home's Explore row); being root-stack routes, `navigation.navigate` from any tab screen bubbles up to them
- `TabNav.tsx` — bottom tabs (Rank, Trades, Matches, League). **#245 (2026-08-05): the Trades tab is LABELED "Acquire"** (tabBarLabel + tabBarAccessibilityLabel) — presentation-level only; the route name stays `Trades`, so deep links, analytics events, and the `tab.trades` testID are unchanged. **#246 (2026-08-05, guided-first landing — SEMANTICS CHANGE for `TradesHome`):** with flag `trades.finder_hub` on, the Trades-stack root `TradesHome` no longer renders the launcher hub — it renders **TradesScreen with `initialParams {mode:'guided'}`**, i.e. the tab LANDS in the guided deck (approved mock `mockups/polish-lab-2026-08/acquire-landing-guided-first.html`, V1). Consequences: (a) `TradeFinderHubScreen` is UNROUTED (kept in the tree, no imports — see the screens registry); (b) every existing `navigate('TradesHome')` call site (LeagueScreen `league.action.find`, MatchesScreen `matches.go-to-trades`, TradeCalculatorScreen `calc.find-a-trade`, the deep-link base path `app/trades`, F10's old summary-Done) keeps working unchanged and now lands on trades; (c) mode switching lives in the deck's persistent `TradeFinderModeBar` chip strip (Guided/Team/Player in place, Calc + Free agents push); (d) the `editDna:true` param on `TradesHome` now opens the deck's `TradeDnaSheet` instead of auto-expanding a hub panel; (e) `TradeDeck` STAYS registered (same component) so the `app/trades/finder` deep-link path still resolves — a link there pushes a second deck instance over the landing, back returns to it. Flag off ⇒ classic pre-hub behavior, byte-identical (TradesScreen standalone, no mode param, TradeDeck unregistered). The Rank tab is a stack (RankHome chooser / Trios / Anchors / Tiers / QuickSetTiers / QuickRank / ManualRanks / Trends) whose initial route follows `useSession.rankingMethodPref` (null → QuickSetTiers, the default method since #122, with an always-on "More ways to rank" header link to the demoted RankHome chooser — formerly gated behind `onboarding.rank_routing`, item 9's Q1 ruling; a stored pref always wins); tapping the tab opens the rank-mode action sheet. QuickSetTiers is in that sheet as "Quick set" (recommended, #119) and is also entered from the Tiers header or launch routing (`rankingMethodPref: 'quickset'`). QuickRank (#136) sits in the sheet as "Quick rank" and is offered when the Quick set walk finishes; it is deliberately not a launch-routable pref. The League tab is a stack too (#181): root `LeagueRankings` = `LeagueSummaryScreen` (the rankings view — the tab's primary page, header "League rankings") with the classic league page (`LeagueScreen`) pushed as `LeagueHome` from the rankings screen's "League home" row (testID `league-summary.league-home`); focused re-tap pops to the rankings root (flag `ux.retap_active_tab`), whose screen owns the `registerScrollToTop('League', …)` handler

- **Rank-stack back topology (FB-162/165, 2026-07-25, unflagged bug fix):** every rank surface's HeaderBack fallback is `RankHome` (the rank-method chooser) — never a sibling surface — and Trios carries the always-on back control in BOTH `ux.rank_tab_destination` states (it was headerless flag-off). Pair rule: `RankHomeScreen.choose` uses `navigation.navigate` (NOT `replace`) so the chooser stays under the chosen surface and back/edge-swipe/hardware-back return to it. Regressing either side recreates the "stuck in a ranking loop" trap (launch-routed surface at stack root → Back → dead-end Trios; chooser unreachable). Shared HeaderBack testID: `stack.back-btn`. **#217 exception (2026-08-01):** QuickSetTiers — and ONLY QuickSetTiers — hides the back control when it sits at the stack ROOT (`quickSetBackWhenPushed`: positional `route.key` check, both flag states): as the tab's launch route it has no history and its header already carries the "More ways to rank" path (flag off → RankHome; flag on → RankMenu sheet), so the root back was a duplicate. Pushed mounts keep the always-on control unchanged; every other rank surface keeps it even at root.
- **Rank stack, `RookieRanks` (rookie-draft M2, 2026-08-06, flag `ranks.rookie_subset`)** — the consolidated cross-position rookie ranking view (`screens/RookieRanksScreen`, deep link `app/rank/rookies`). Registered as a SIBLING rank surface with the standard topology: `subScreenOptions`/`rankSubScreenOptions` and the #162/#165 `RankHome` back fallback. It is NOT launch-routable and NOT a `rankingMethodPref` (it's a view, not a ranking method), so `PREF_ROUTE` and the #244 completion-aware default are untouched. Both entry points — every rank surface's `RookieScopeControl` link and RankHome's "Rookies" section — are flag-gated, so with the flag off the route exists but is unreachable in-app and the screen renders its own unavailable state.
- `rankChooserModel.ts` — #232 (2026-08-02): the rank-method chooser's shared content model (3 primary methods labeled by outcome — Quick set / Head-to-heads / Tiers board — + "More ways to rank" disclosure rows), consumed by BOTH `RankHomeScreen` and TabNav's `RankMenu` sheet so the two surfaces can't diverge.
