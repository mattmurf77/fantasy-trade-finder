# mobile/src/navigation/

React Navigation config. MAP, not a changelog — present behavior only, no dated amendments. History: `git log -- <this file>` and `living-memory/CHANGELOG.md`. File roles + the full route tree: [README.md](README.md).

- `RootNav.tsx` — root stack: `SignIn` → `LeaguePicker` → `Main`, plus `LeagueJoin` (the invite interstitial). The `Main` screen renders `<TabNav />` alongside the app-wide mounts: `VerifyAccountBanner`, `PushPrimingModal`, and the **single global `<FeedbackFAB activeScreen={activeScreen} />`** that covers every tab-stack screen (root-stack pushes render their own with `aboveTabBar={false}`). `AnalystGuide` is likewise mounted once here, above the nav tree and below system modals. Root-level pushed surfaces: `Settings`, the seven Settings second-level pages (`SettingsLeagues`, `SettingsRanking`, `SettingsTradeValues`, `SettingsNotifications`, `SettingsAccount`, `SettingsAbout`, `SettingsTesting`), `Profile`, `LeagueSummary` (legacy deep-link entry; primary registration is the League tab's stack root), `FreeAgents`, `UsageTrends` (Usage Trends; flag `usage_trends.enabled` gates the Home hub's Usage Rates tile + the Free Agents link, not the route), `Standings` (D-202 Home hub's single standings table; pushed from Home or League rankings so Back returns there; accepts a legacy `{ segment }` it never reads), `ImprovePlayoffChances` and `ImproveDraftPick` (D-265 Improve pages: no params, the session league; `league.direction_pages` gates the Standings link rows, not the routes), `Receipts`, `WinNow`, `DraftRoom`, `MockDraft`, `PickAssignment`, `RecordPicks`, `TestStages`, `EspnConnect`, `PremiumRankingsBrowser`. Modal presentations: `FeedbackInbox`, `SleeperConnect`, `Paywall`, and `TipJar` (both flag `monetize.paywall`, dark — `headerShown:false` because `PaywallScreen` draws its own header with the explicit ✕ that components.md requires of a modal; the flag gates the Settings entry row, not the route, and the screen self-guards). Flag-gated screens (`DraftRoom`, `MockDraft`, `PickAssignment`, `RecordPicks`, `PremiumRankingsBrowser`, and all seven `Settings*` pages) register UNCONDITIONALLY — the flag gates the entry point, not the route.
- **League selector as the header**: `FreeAgents`, `Standings`, `ImprovePlayoffChances`, `ImproveDraftPick`, `UsageTrends`, `Receipts` and `WinNow` render through native-stack's custom `header` = `LeagueTopBarHeader` — the global `TopBar` (league cluster + `LeagueSwitcherSheet`, format tile, bell, gear) over a 44pt sub-header with the #151 JS `HeaderBack` (literal testID at the registration, `canGoBack ? goBack : navigate('Main')`) and the condensed-caps title. No native header exists on those screens, so no native back (RNS#3294). The header has an optional `right` slot; `UsageTrends` feeds it the screen's own `headerRight` (`usage-trends.info`, set via `setOptions`). TopBar owns the top inset, so these screens pad the bottom only. `LeagueSummary`, `DraftRoom`, `MockDraft`, `PickAssignment`, `RecordPicks` and `ShopAsset` keep their own headers on purpose (they take a league from route params, so a selector there needs a decision first). Pinned by `mobile/tests/check-free-agents-header.js` + `check-league-header-pages.js`.
- **Settings** is one route with two components: `account.settings_hub` ON mounts `SettingsHubScreen` (grouped nav rows that push the seven pages), OFF mounts `SettingsScreen` (the flat list). The branch is the `SettingsRoute` wrapper in `RootNav.tsx`, not a branch inside either screen — mounting one component or the other is what keeps the hub off the network. Every settings surface is a plain push with `headerBackVisible: false` + an explicit `HeaderBack` (`settings.back-btn`, `settings.<page>.back-btn`), in BOTH flag states.
- `TabNav.tsx` — bottom tabs **Home · Rank · Acquire · [Calibration | Draft] · Matches · League** (Home renders only with flag `nav.home_tab`; the third slot is Calibration when `grading.blind` resolves true at mount, else Draft under `draft.tab`, else empty; the Acquire tab's route name stays `Trades`). **Launch tab:** `Home` when `nav.home_tab` is on — except a first-run user (`onboarding.trades_first` live, no swipe yet), who lands on `Trades` so the analyst guide runs against the screen it is scripted for. With `nav.home_tab` off the launch tab is `initialTab`: `Trades` under `nav.trades_landing` or for that same first-run user, else `Rank`. Both tab flags and the launch tab are decided once at mount from an imperative flag read, so a mid-session flip takes effect next launch.
  - **Home** (flag `nav.home_tab`) — one plain screen, `HomeScreen`, no nested stack: a question and four text rows that `navigate` to the `Rank` / `Trades` / `Matches` / `League` tabs by route name. Pinned by `mobile/tests/check-home-tab.js`.
  - **Rank** stack (RankHome / Trios / Anchors / Tiers / QuickSetTiers / QuickRank / ManualRanks / Trends / RookieRanks); launch route follows `useSession.rankingMethodPref`, or for no-pref users the next unset QuickSetTiers position, or Trios once all four are complete. Every surface's ONE exit is the header's "More ways to rank" control, which navigates to `RankHome` (with `nav.continuity`: with `pop`, so a chooser already underneath is returned to rather than stacked again) (the "Build your board" chooser) — flag-on rank surfaces carry **no back control** (operator, 2026-08-16: Back and More-ways were two controls for one destination). `RankHome` itself keeps a back control to the preferred surface; with `ux.rank_tab_destination` OFF every surface reverts to the old back-falls-back-to-`RankHome` topology.
  - **Acquire** (route `Trades`) — stack root `TradesHome` renders `TradesScreen` with `initialParams {mode:'guided'}` when flag `trades.finder_hub` is on (the guided deck is the landing), else the classic standalone home. `TradeDeck` stays registered for the `app/trades/finder` deep link. `TodaysTrade` and `TradeBrowseAll` (flag `trades.presentation_v2`, default OFF) are the additive presentation-v2 pair — registered UNCONDITIONALLY like every other flag-gated route, reached only from the mode strip's leading "Today" chip, which exists only while the flag is on. `Portfolio` and `TradeCalculator` are the stack's other two screens — Portfolio is reachable only from inside this stack, which is why it adds no tab to the bottom bar. With `nav.continuity` Portfolio wears the shared JS "‹ Back" (`subScreenOptions`), like every other Acquire sub-page; off, the plain header.
  - **League** stack — root `LeagueRankings` = `LeagueSummaryScreen`, with the classic `LeagueScreen` pushed as `LeagueHome`. Focused re-tap pops to the root (flag `ux.retap_active_tab`).
  - **Draft** (flag `draft.tab`, hand-flipped seasonal switch, never computed) registers one screen, `DraftRoomScreen` with `initialParams {inTabs:true}` — no per-league chooser. The flag is read once at first mount, so a mid-session flip takes effect next launch. `DraftRoom` is dual-registered (root + this tab), but `deepLinks.ts` points its one canonical path at the root-stack copy.
- `navContinuity.ts` — the pure navigation decisions of D-275 (no imports; executed by `tests/check-nav-continuity.js`). Flag `nav.home_return`: which Home taps arm the "‹ Home" control (`homeReturnTabFor` — never a rank page, never D-269's roster arrival) and how long it lasts (`homeReturnOnTabFocus`: until another tab gets focus). Flag `nav.continuity`: `backOrFallback` (a Back-or-fallback control tests its OWN stack's index — `canGoBack()` also counts the tabs, which can always go back to Home), `pickerOpenedInApp` / `pickerExit` / `pickerAutoSkipAllowed` (the league picker over `Main` gets Close, no one-league auto-forward, and a pick `popTo('Main')`s instead of replacing), `returnOptions` (`{ pop: true }` for links to a page that may already be underneath, G-056), `signInReset` (sign-out, deletion and session expiry reset the root stack), `tiersLeavePrompts`.
- **Home return control** (flag `nav.home_return`): `components/HomeReturnBar` is mounted ONCE in `TabNav` between `TopBar` and the tab navigator; `TabNav`'s `screenListeners` report each tab focus to `state/homeReturn`. A Home hub tile that crosses to Acquire, League or Matches arms it; the bar shows "‹ Home" on that tab until the tab changes. The position tile body keeps D-269's header "Home" control in League rankings instead (one control per arrival).
- `rankChooserModel.ts` — the rank-method chooser's shared content model, consumed by both `RankHomeScreen` and TabNav's `RankMenu` sheet so they can't diverge.
- `scrollToTop.ts` — re-tap-to-top registry (flag `ux.retap_active_tab`): each tab's root screen registers its scroll handler via `registerScrollToTop`.
- `../utils/deepLinks.ts` — **not in this folder.** Nested route table for `linking` (flag `ux.deeplink_router_v2`); single source for URLs, push taps, and bell rows. It also owns `resolveNotificationTarget` (consumed by `hooks/usePushNotifications`) and `handleDeepLink` (called from `App.tsx` for the cold-start case).

## Sharp edges

- Flag-gated screens (`DraftRoom`, `MockDraft`, `PickAssignment`, the `Settings*` pages) must stay registered unconditionally — gating the route breaks an in-flight push on flag revalidation.
- Settings is a PUSH, not a modal. It was a page sheet with a ✕ (`settings.close-btn`) until the settings-IA work; that presentation is what forced `navigateFromSettings` to dismiss Settings before every outbound link, which is why Back from SleeperConnect used to land on the tabs. Re-introducing the modal re-introduces that hack — see `docs/plans/settings-ia-hub/plan.md` §5 before citing #130 to bring the sheet back.
- `RankHomeScreen.choose` must use `navigation.navigate`, not `replace`, so back/edge-swipe returns to the chooser — regressing this recreates a "stuck in a ranking loop" trap. With `nav.continuity` it passes `{ pop: true, merge: true }`: a method page already UNDER the chooser (the one "More ways to rank" was tapped on) is returned to with its params, and the chooser above it goes; a page not in the stack is still pushed over the chooser. Tiers holds a `beforeRemove` "Discard your tier changes?" prompt for that removal.
- Links that name a page that may already be underneath (the Acquire landing, League rankings, the rank chooser) pass `pop` under `nav.continuity` (`returnOptions`, or `pop: true` in nested `{ screen }` params) — a bare `navigate` PUSHES a second copy (G-056). A root-stack page returning to the tabs uses `popTo('Main', …)`, never `navigate('Main', …)`.
- **Never-strand rule (#162/#165, re-stated 2026-08-16):** a flag-on rank surface has no back control, so `rankSubScreenOptions` must ALWAYS render `MoreWaysButton` and must keep `headerBackVisible: false` (native stack draws the OS chevron otherwise). `RankHome` must keep its own back control — it is the one rank screen with no More-ways control. Pinned by `mobile/tests/check-rank-nav-exit.js`.
- Adding a screen means three things together: register it here, create the file in `../screens/`, add its route to `deepLinks.ts`.
