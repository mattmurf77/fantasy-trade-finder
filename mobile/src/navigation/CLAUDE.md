# mobile/src/navigation/

React Navigation config. MAP, not a changelog — present behavior only, no dated amendments. History: `git log -- <this file>` and `living-memory/CHANGELOG.md`. File roles + the full route tree: [README.md](README.md).

- `RootNav.tsx` — root stack: `SignIn` → `LeaguePicker` → `Main`, plus `LeagueJoin` (the invite interstitial). The `Main` screen renders `<TabNav />` alongside the app-wide mounts: `VerifyAccountBanner`, `PushPrimingModal`, and the **single global `<FeedbackFAB activeScreen={activeScreen} />`** that covers every tab-stack screen (root-stack pushes render their own with `aboveTabBar={false}`). `AnalystGuide` is likewise mounted once here, above the nav tree and below system modals. Root-level pushed surfaces: `Settings`, the seven Settings second-level pages (`SettingsLeagues`, `SettingsRanking`, `SettingsTradeValues`, `SettingsNotifications`, `SettingsAccount`, `SettingsAbout`, `SettingsTesting`), `Profile`, `LeagueSummary` (legacy deep-link entry; primary registration is the League tab's stack root), `FreeAgents`, `DraftRoom`, `MockDraft`, `PickAssignment`, `RecordPicks`, `TestStages`, `EspnConnect`, `PremiumRankingsBrowser`. Modal presentations: `FeedbackInbox`, `SleeperConnect`, `Paywall`, and `TipJar` (both flag `monetize.paywall`, dark — `headerShown:false` because `PaywallScreen` draws its own header with the explicit ✕ that components.md requires of a modal; the flag gates the Settings entry row, not the route, and the screen self-guards). Flag-gated screens (`DraftRoom`, `MockDraft`, `PickAssignment`, `RecordPicks`, `PremiumRankingsBrowser`, and all seven `Settings*` pages) register UNCONDITIONALLY — the flag gates the entry point, not the route.
- **Settings** is one route with two components: `account.settings_hub` ON mounts `SettingsHubScreen` (grouped nav rows that push the seven pages), OFF mounts `SettingsScreen` (the flat list). The branch is the `SettingsRoute` wrapper in `RootNav.tsx`, not a branch inside either screen — mounting one component or the other is what keeps the hub off the network. Every settings surface is a plain push with `headerBackVisible: false` + an explicit `HeaderBack` (`settings.back-btn`, `settings.<page>.back-btn`), in BOTH flag states.
- `TabNav.tsx` — bottom tabs **Rank · Acquire · Draft · Matches · League** (Draft renders only with flag `draft.tab`; the Acquire tab's route name stays `Trades`).
  - **Rank** stack (RankHome / Trios / Anchors / Tiers / QuickSetTiers / QuickRank / ManualRanks / Trends / RookieRanks); launch route follows `useSession.rankingMethodPref`, or for no-pref users the next unset QuickSetTiers position, or Trios once all four are complete. Every surface's ONE exit is the header's "More ways to rank" control, which navigates to `RankHome` (the "Build your board" chooser) — flag-on rank surfaces carry **no back control** (operator, 2026-08-16: Back and More-ways were two controls for one destination). `RankHome` itself keeps a back control to the preferred surface; with `ux.rank_tab_destination` OFF every surface reverts to the old back-falls-back-to-`RankHome` topology.
  - **Acquire** (route `Trades`) — stack root `TradesHome` renders `TradesScreen` with `initialParams {mode:'guided'}` when flag `trades.finder_hub` is on (the guided deck is the landing), else the classic standalone home. `TradeDeck` stays registered for the `app/trades/finder` deep link. `TodaysTrade` and `TradeBrowseAll` (flag `trades.presentation_v2`, default OFF) are the additive presentation-v2 pair — registered UNCONDITIONALLY like every other flag-gated route, reached only from the mode strip's leading "Today" chip, which exists only while the flag is on. `Portfolio` and `TradeCalculator` are the stack's other two screens — Portfolio is reachable only from inside this stack, which is why the bottom bar still shows five tabs.
  - **League** stack — root `LeagueRankings` = `LeagueSummaryScreen`, with the classic `LeagueScreen` pushed as `LeagueHome`. Focused re-tap pops to the root (flag `ux.retap_active_tab`).
  - **Draft** (flag `draft.tab`, hand-flipped seasonal switch, never computed) registers one screen, `DraftRoomScreen` with `initialParams {inTabs:true}` — no per-league chooser. The flag is read once at first mount, so a mid-session flip takes effect next launch. `DraftRoom` is dual-registered (root + this tab), but `deepLinks.ts` points its one canonical path at the root-stack copy.
- `rankChooserModel.ts` — the rank-method chooser's shared content model, consumed by both `RankHomeScreen` and TabNav's `RankMenu` sheet so they can't diverge.
- `scrollToTop.ts` — re-tap-to-top registry (flag `ux.retap_active_tab`): each tab's root screen registers its scroll handler via `registerScrollToTop`.
- `../utils/deepLinks.ts` — **not in this folder.** Nested route table for `linking` (flag `ux.deeplink_router_v2`); single source for URLs, push taps, and bell rows. It also owns `resolveNotificationTarget` (consumed by `hooks/usePushNotifications`) and `handleDeepLink` (called from `App.tsx` for the cold-start case).

## Sharp edges

- Flag-gated screens (`DraftRoom`, `MockDraft`, `PickAssignment`, the `Settings*` pages) must stay registered unconditionally — gating the route breaks an in-flight push on flag revalidation.
- Settings is a PUSH, not a modal. It was a page sheet with a ✕ (`settings.close-btn`) until the settings-IA work; that presentation is what forced `navigateFromSettings` to dismiss Settings before every outbound link, which is why Back from SleeperConnect used to land on the tabs. Re-introducing the modal re-introduces that hack — see `docs/plans/settings-ia-hub/plan.md` §5 before citing #130 to bring the sheet back.
- `RankHomeScreen.choose` must use `navigation.navigate`, not `replace`, so back/edge-swipe returns to the chooser — regressing this recreates a "stuck in a ranking loop" trap.
- **Never-strand rule (#162/#165, re-stated 2026-08-16):** a flag-on rank surface has no back control, so `rankSubScreenOptions` must ALWAYS render `MoreWaysButton` and must keep `headerBackVisible: false` (native stack draws the OS chevron otherwise). `RankHome` must keep its own back control — it is the one rank screen with no More-ways control. Pinned by `mobile/tests/check-rank-nav-exit.js`.
- Adding a screen means three things together: register it here, create the file in `../screens/`, add its route to `deepLinks.ts`.
